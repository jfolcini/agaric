A one-shot speculative handoff with a short TTL — not a persistent cache — that `load()` consumes while running every existing guard unchanged. | `src/lib/prefetch-page-subtree.ts`, `src/hooks/usePagePrefetchIntent.ts` |

## Cross-cutting facts

A handful of facts touch every feature; rather than repeat them in each file:

- **All UI is keyboard-reachable.** See [features/keyboard.md](features/keyboard.md).
- **All text is internationalised** via i18next. Every visible string — toasts, ARIA labels, empty states, error messages — passes through `t()`. Two locales ship: English, statically bundled because it is the fallback, and Spanish, a lazily-imported chunk that today covers the `errors` namespace and falls back to English elsewhere. The language is a device-scoped preference (Settings → General) that switches without a restart and drives `<html lang>` and every date format. `src/lib/i18n/locales.ts`, `src/hooks/useLanguage.ts`.
- **Two sizes, per device.** Settings → Appearance → Note text size scales the text of notes only. On desktop, Zoom (also `Ctrl+=`, `Ctrl+-`, `Ctrl+0`, rebindable) scales the whole interface through the webview's page zoom, which reflows rather than magnifies; its largest step keeps the default window at least as wide as the narrowest phone layout, so no view scrolls sideways (#5646). Whether Android follows the system font size is not yet checked on a device. `src/hooks/useFontSize.ts`, `src/hooks/useInterfaceZoom.ts`.
- **All interactive elements meet a 44 px touch floor** on coarse-pointer devices (see `docs/UX.md` § Touch & responsive), except the tag, page-link and block-reference chips inside block text; a tag chip in a list row (the Tags browser, agenda and task lists) reaches 44 px in height (#6532).
- **On a touch phone a view's header scrolls away with its content** (a narrow mouse window keeps it pinned, #5992), except the search field of Pages and Search, which stays pinned; each screen shows one title, and Pages' header is one row: search, a sort icon, a ⋮ menu with the saved views and Tags, Graph, Query, Templates and Trash, and New page as an icon (#5955).
- **On a phone panels, dialogs and long menus open as bottom sheets** (block properties, History, Outline, Keyboard shortcuts, New page, the date picker, the block and page menus), and toasts sit at the bottom, above the capture button and the keyboard (#5957).
- **On a phone text starts on one 16 px edge**: headings, block text, a sheet's contents and a settings card's contents (#5958).
- **A failing disk says so once.** When the disk is full, the data folder cannot be written to, or the database is damaged, a banner under the header names the cause and what to do, and stays until dismissed; each failed action still reports itself (#6554).
- **All edits are offline-first.** They land in the local SQLite database first and sync afterwards (see [features/sync.md](features/sync.md)).
- **Everything is space-scoped by default.** The active space filters every list, search, agenda, backlink and history view (see [features/spaces.md](features/spaces.md)).
- **Reduced motion is respected** globally; JS-driven animations check explicitly (see `docs/UX.md` § Accessibility).

## Roadmap

Features that aren't yet shipped or that are intentionally deferred are tracked separately. The major outstanding items today:

- **OS notifications** — *desktop reminders ship; nothing more is planned*. A maintenance job (`src-tauri/src/reminders.rs`, on the 60 s daemon tick) fires one OS notification per open task on its `due_date`, at the reminder time set in Settings → Tasks & reminders, while the app is running (minimised counts; closed does not). A per-`(block, date)` ledger in `app_settings` keeps a tick or a restart from notifying twice; preferences are device-local (`get_reminder_settings` / `set_reminder_settings`, off by default). Dispatch is the fire-now `notify_task` path (`src-tauri/src/commands/notifier.rs`; Linux via notify-rust, macOS/Windows via `tauri-plugin-notification`). Not built, and dropped when #4554 was narrowed to the desktop slice, so no issue tracks them: `scheduled_date` as an anchor, the Android arm (OS alarms), lead offsets and a per-task `reminder` property, the catch-up digest, tap-to-open, snooze.
- **Working two-device sync** — the *transport* is done: the iroh QUIC port shipped (#78, plan #3464), replacing the WebSocket + TLS + cert-hash-TOFU stack, with mDNS (`iroh-mdns-address-lookup`, added to the bound endpoint) advertising `_agaricv1._udp` with each peer's `endpoint_id` as the instance name. The defect that stopped a first-ever pairing being initiated at all (#3502 — daemon policy rather than transport, so the port carried it across unchanged) is fixed. A first-ever pair has now been observed against two live devices (Linux desktop and Android phone, both 0.9.8) over QUIC on a real LAN, retiring the Android half of the old unverified claim. What that run surfaced is that the remaining failure modes are largely environmental — a VPN tunnel capturing a publicly-numbered LAN, and a default-deny host firewall. The pair also exposed three real defects: an initiator-side apply that aborted on `blocks.parent_id` (#4083, the one that broke sync outright); a responder-only device recording no progress, so it reads as never-synced and is marked due every tick (#4084); and every initiator `SyncEvent` carrying an empty `remote_device_id` (#4085). All three are fixed on main. The run is recorded in [`session-1345`](session-log/sessions-1301-1400.md). Two-way sync is verified by `e2e-tauri/sync-two-device.e2e.ts` on every PR that touches code the real-backend lane covers and in daily Android ↔ Linux use; **QUIC/UDP behaviour on restrictive WiFi is still unverified**. Known follow-ups from the cutover: #3511 (asymmetric per-peer lock during the pairing window), #3512 (wire compression retired), #3513 (inbound single-homed), #3514 (silent one-time re-TOFU for migrated installs), #3515 (10 s dead-peer dial).
