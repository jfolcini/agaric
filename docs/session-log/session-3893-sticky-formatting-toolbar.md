# Session 3893 — One sticky formatting toolbar per view (#6562, first checkbox)

**Goal.** Block mode's formatting toolbar was the first child of the focused block's `.block-editor`, in flow, so focusing a block pushed its text and everything below it down 27 px; a double-click's second press landed on a toolbar button. The maintainer decided on one sticky bar per view, hidden at rest. The second checkbox (click-to-caret) is not built: `StaticBlock.handleOuterClick` and `rovingEditor.mount` are untouched.

**What changed.**
- `src/components/FormattingToolbar/view-toolbar.tsx` (new, TipTap-free): `useViewToolbar(element)` publishes the edited block's bar into a module store from a layout effect, with an owner token so a surface that unmounts late cannot clear its successor's bar; `ViewToolbarSlot` renders it. The slot is mounted once in `App.tsx`, first in the main scroller after the phone header slot, so every view gets exactly one (the journal week and stream views included) and no editing view is outside it. It is `sticky top-0 h-0` with the bar absolute at `-top-4 md:-top-6`, overlaying the scroller's padding: it takes no layout space, so showing and hiding it moves nothing.
- `EditorSurface` hands its `FormattingToolbar` element to the slot instead of rendering it. Because the slot renders the same component in the same place, the bar stays one mounted element while the roving editor moves between blocks (spec and unit test check element identity). The bar renders outside the tree, so `EditorSurface` passes `listStyle` from `useListMarker` (Turn into read it from `ListMarkerProvider` context before).
- `focusStaysInEditor` (`src/editor/editor-portal.ts`) skips `[data-view-toolbar]` in its "a visible overlay holds the editor" scan. The bar carries `data-editor-portal` and is now outside the block's wrapper; without the skip it would keep every edit open forever. Focus moving *into* the bar is still caught by the first check.
- Page mode's and *Edit as Markdown*'s sticky bars move from `top-0` to `-top-4 md:-top-6`: sticky offsets count from inside the scroller's padding, which left a 24 px band above them.
- Touch is unchanged: `ToolbarFrame` still pins the bar `fixed` above the keyboard; it just renders from the slot now.

**Traps.** Toolbar buttons can no longer be found inside `[data-testid="block-editor"]`; six existing specs scoped *Turn into* that way and `editor-lifecycle` looked for the bar inside a day section; they now use `formatting-toolbar` on the page. A double-click's word selection needs the second press after ProseMirror's 20 ms post-focus selection write-back; the spec waits a frame plus 20 ms, as `editBlock` does. At 640 px the full-width bar fits every button, so the overflow spec uses 480 px. The `toolbar-and-blocks` #4320 popover spec still passes, but its toolbar is no longer mid-viewport: it anchors at the top bar.

**Checks run.** `e2e/sticky-toolbar.spec.ts` red on unfixed code (7 of 8 then), green after; the stay-mounted, narrow-overflow and phone-pinned tests also shown red by mutation. Vitest on the toolbar, EditableBlock, page-toolbar, PageSourceToolbar, App and lazy-editor tests, mutation-checked; `npm run typecheck`. 56 existing Playwright specs (toolbar, picker, table, journal week/stream, phone, page mode, keyboard, gutter) green with `--workers=1`.
