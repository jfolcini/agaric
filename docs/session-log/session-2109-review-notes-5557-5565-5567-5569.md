# Session 2109 — Review notes from #5557, #5565, #5567 and #5569

Non-blocking reviewer notes from four merged PRs, batched into one change.

- **#5557.** `count_unlinked_references` drops its `LEFT JOIN blocks p`. Its
  one read, `p.id != ?2`, equals `b.page_id != ?2`: `page_id` is an FK with
  foreign keys on, and a NULL `page_id` drops out of either form. The
  `interactive_slo` header lists all three #5422 probes, and the
  `useUnlinkedReferences` doc matches the query.
- **#5565.** The two `filtered_blocks_query` benches share one timing helper,
  `time_filtered_blocks_query`, and each makes its own verdict call.
- **#5567.** `list_page_links` measured within its budget after #5567, so its
  probe moves to the green tier and asserts the budget. Every copy that called
  it over budget is updated.
- **#5569.** The space guard (`SpaceGuard`, `SPACE_GUARD`, `check_space_guard`)
  and `validate_block_in_space` move into `db::command_tx`, so the db layer no
  longer imports from `mcp`; moving only the guard would have kept that
  dependency, since the check calls `validate_block_in_space`.
  `spawn_mcp_rw_task` takes eight arguments, so its
  `allow(clippy::too_many_arguments)` becomes an `expect`. `with_space_guard`'s
  doc says it fails open without a `CommandTx` in the same task, and that a new
  guarded tool joins the transaction-count test.

The note 1 premise was half right: the query is runtime SQL, not `query!`, so no
`.sqlx` entry changes.
