## Session 3600 — bound and retry the apt install in apt-install

Run 42078795569's "Real-backend specs (1)" sat in `Install runtime dependencies` with no output until it was cancelled, while its sibling shards passed the same step in seconds. The action bounded `apt-get update` twice but ran `apt-get install` with no bound, and its stdout goes to a log printed only on failure, so a slow install is silent.

- The update was not the stall: it prints a `::warning::` on every timed-out attempt and none appeared. The same silent, long install recurs in the e2e-tauri history and finishes successfully, its only output being needrestart's closing lines: jobs 127320928631 (run 42048022669), 127281611611 (run 42037023371), 127007410934, 126936159680, 126936159619 and 126949717796 among them. The build job's `Install system dependencies`, which restores the .debs from `actions/cache`, was never slow in the same window; the runtime install, which downloads them, was. So it is a mirror trickling .debs to one runner, which `Acquire::http::Timeout` does not catch: that fires on a silent connection, not a slow one.
- Fix: `apt-get install` runs under `timeout -k 30` with a new `install-timeout` input (default the update's bound) and gets one retry after the same kill, lock wait and `dpkg --configure -a` the update path used, now shared as `reap_apt` and `wait_for_apt_locks`. The retry opens new connections and keeps every .deb the first attempt finished. A timeout prints the apt log, whose `Get:` lines name the slow mirror. Two timeouts exit 75 with `AGARIC_APT_INFRA`; any other install failure still exits with apt's status, unretried.
- Ran the action's script with shimmed `sudo` and `apt-get`: an install that never returns hung the old script until an outer timeout and made the new one exit 75 after two bounded attempts; slow-then-fast exits 0; `E: Unable to locate package` exits 100. `prek run --all-files` and `prek run --hook-stage manual --all-files`.

## Session 3597 — `add_meeting_inner`

The second PR of #5364 slice 2 (S4 in the build plan on #5410): the backend that makes a meeting, in one transaction. No caller yet. The MCP `add_meeting` tool and the app's dialog call it in the next PRs. Cut from #6395's branch, since a meeting sets the `meeting_date` built-in that #6395 adds.

- `add_meeting_inner` (`commands/meeting_attachments.rs`, a name `e2e-related` maps to `@attachments`):
  - A new meeting is the page `<Title> <YYYY-MM-DD>` (*Meeting* when the title is blank), tagged `#meeting` (created in the space if missing) with `meeting_date`.
  - The chosen template page is copied under it, with its variables expanded against the meeting date and title rather than the clock. A template block reading `<% recording %>` becomes the recording block; without one, the recording block is the page's first block.
  - A summary given as text is written just above the recording block. The audio, transcript and summary files go onto that block as `<name>.transcript.md` and `<name>.summary.md`.
  - The page is linked from the given block (appended to its content) or from the end of the day's journal, which is created if missing.
  - Given a block, or a page, it adds the files to an existing meeting instead. A page's recording block is its first block holding an attachment, else a new block at its top.
- The files are written before the transaction and removed if it fails. A taken title, a page that is not a template of the space, audio that is not audio and a target in another space are refused with nothing written.
- One `revert_ops` of the captured refs takes the whole meeting back: page, template copy, tag, link edit and attachments.
- Splits along the `_in_tx` pattern, with no change for existing callers: `persist_attachment_in_tx` and `write_attachment_bytes` (`attachments.rs`), and `create_tag_in_space_in_tx` (`blocks/crud.rs`). The journal's template expander now takes the page title (`expand_template_variables`); the journal still passes the day.
- Not here: dropping `<% recording %>` from a journal-template copy (Q15) goes with `/template`'s drop in S5b. It needs a filter in `copy_page_blocks_in_tx`, which is in a file another session has open.

## Session 3587 — a carriage return in a page property no longer breaks Edit as Markdown

#6325: a page property holding a `\r` made the page's Edit as Markdown buffer, and MCP `edit_page_markdown`, refuse every save. `yaml_scalar_emit` quoted such a value but wrote the `\r` raw, and the buffer reader read it as a line end, so the front matter split into a line that is not `key: value` (a CRLF value took the block-scalar branch and carried the raw `\r` the same way).

- Fix: `yaml_scalar_emit` sends any value holding a `\r` to the double-quoted branch, and that branch now writes `\\`, `\r` and `\n` as YAML escapes. The importer's `front_matter_scalar` (`agaric-engine/src/import.rs`) decodes those three escapes in a double-quoted inline value and leaves any other backslash as written. Quotes inside the value still stay unescaped, as before.
- Compatibility: a double-quoted value that an older export wrote with a literal `\\`, `\r` or `\n` in it now reads as the escape. Real YAML reads it that way too.
- Mock twin: `readFrontMatter` in `src/lib/tauri-mock/handlers/pages.ts` decodes the same escapes. Its writer `renderFrontMatter` still writes values verbatim and unquoted, a documented approximation this fix does not touch. `source-buffer-document.ts` reads no front-matter values.
- Not changed: the `arb_front_value` filter that leaves `\r` out of the Document proptest's page values. It is an existing test and can go in a follow-up.
- Ran: the new test `a_page_property_with_a_carriage_return_saves_by_its_line_ids`. It is red on origin/main (`line 3: '"' is not a 'key: value' line`). ## Session 3583 — every attachment extension imports

## Session 3518 — clippy and the sqlx cache check share one compile

Set out to shorten the PR CI critical path outside nextest. Re-measured on green `main` runs: on a Rust-touching run `validate / lint` took about 800 s, and its cargo steps were clippy (161 s), the four `sqlx prepare --check` steps (140 + 24 + 37 + 41 s), cargo doc (61 s) and the fuzz check (56 s). Playwright shard 3 was the longest shard on some runs, not all, so rebalancing it would have been chasing noise.

Every sqlx step recompiled the workspace members clippy had just compiled. Its job log shows why: rust-cache keeps only dependencies, and each `prepare --check` lane builds `agaric-core`/`agaric-store`/… under its own feature set, so all four compile from scratch. `scripts/clippy-sqlx-check.sh` now runs clippy once with the query macros online. `scripts/sqlx-rustc-wrapper.sh`, a `RUSTC_WRAPPER`, sets a separate `SQLX_OFFLINE_DIR` for each crate's lib and test builds. The script then diffs each committed cache using sqlx-cli's rules: a missing or different entry fails, and unused entries only warn. The root cache is checked against every crate's queries, the way `just gen-sqlx` builds it. A member cache is checked against its own lib and test queries plus the lib queries of the workspace crates it depends on, which is what its own `prepare` lane wrote.

Traps:

- A member's committed cache holds its dependencies' lib queries but not their `#[cfg(test)]` ones. A per-crate union without the lib/test split reported hundreds of false "missing" entries.
- The wrapper does not dirty dependency fingerprints. Only the seven workspace crates recompile.
- Clippy now runs online. The offline-cache resolution it used to prove is implied by the exact cache match, and cargo doc and the fuzz check still compile offline.

Ran: the script on a clean tree (passes, zero unused warnings), and a falsification that deleted one `agaric-store` entry and edited one `agaric-sync` entry (it failed with exactly those two errors). Also ran the `classify-changes` vitest file (shown red without the new paths), `prek` on the changed files, and the manual stage over all files. Locally the merged step ran in 1 m 34 s, against 1 m 18 s for offline clippy alone.

## Session 3513 — Page mode's paste resolves names (#6033 S12)

Set out to build #6033 S12. In page mode, a pasted `[[Name]]`, one line or many, was saved as escaped text (`\[\[Name\]\]`), so no page was linked or created. Foreign forms were missed the same way.

**Premise check: the plan's mechanism (Q7) could not work.**
- The plan was a leave-time commit that scans each block's saved markdown and saves through a thin command over `edit_block_resolving_names`.
- But the serializer always escapes `[` and `]`, and `scanNameTokens` skips escaped tokens, so the scan finds nothing.
- On a multi-line paste, `parse` had already decoded `\(x\)` to `(x)`.
- Three options went back on #6033. The maintainer chose A (comment 6649048892): reuse block mode's path, with nothing new in Rust.

**What shipped.**
- A page-mode paste that block mode would send to the block path (`needsBlockPath`, or a multi-line paste that `onlyBlockPathReads`) is no longer inserted into the document.
- Instead, page mode saves the block and lands the paste through the existing `paste_blocks` with a page-mode splice (`spliceAround`, shared with block mode). It then re-reads the page and puts the caret at the join, scrolled into view.
- The paste counts as a write (`save.writes += 1`, the idiom page tags use), so the store's own queued reads go to the backend instead of bringing in stale rows.
- A refused paste, or a block that could not be saved, goes in as plain text, so nothing is lost.
- Pastes that don't qualify, dropped text, HTML clipboards, and pastes inside a list or table or across blocks keep today's path.

**Review fixes.**
- `clipboardTextParser` also runs for drops, so the first build swallowed dropped text that held a name. The parser now claims only during a DOM `paste`.
- The caret is now scrolled into view after a routed paste.
- Three vacuous or missing tests were replaced: the cross-block case, the list-line route, and the end-of-block guard.

**Trades.**
- Ctrl+Z in the editor doesn't undo the routed paste; page-level undo does, and an e2e test pins it.
- Typing in the block while its `paste_blocks` call is in flight loses text. Block mode loses the typing instead. That is filed as #6364, with why each fix the review tried fails.

**Tests.**
- `e2e/page-mode-paste-names-6033.spec.ts` covers one line, several lines, page-level undo and a drop. It was red before the fix.
- New vitest: `page-paste-block-path.test.ts` and `PageModeEditor.block-path-paste.test.tsx`.
- Reds shown for every new guard: the route decision, the splice end, the refusal and save-failure fallbacks, the caret, the `save.writes` bump, the range mapping, the drop gate and the undo entry.
- Gates: typecheck, lint, all hooks (including the manual stage), the editor, block-tree and lib vitest suites (12261 passed), 262 paste and page-mode Playwright tests, and the bundle budget.

## Session 3512 — Image sizes survive import (#6033 S6)

Set out to build #6033 S6: an image's display size, written in Obsidian's or Logseq's own form, was dropped on import, so a sized figure came back at full width.

**Premise check.**
- `OBSIDIAN_EMBED_RE` threw away the `|…` suffix of `![[pic.png|300]]`, and `detect_attachment_refs` stored an empty alt.
- Logseq's `![alt](url){:height 53, :width 42}` stayed literal text after the image. Removing the new call site showed the map left in the stored content.
- Agaric's own sized image is `![alt|W](url)` or `![alt|WxH](url)`, read by `parseImageAlt` (`src/lib/image-alt-size.ts`). The new readers match that grammar.

**What shipped.**
- An Obsidian `|W` or `|WxH` embed suffix becomes the alt size. Any other suffix, such as display text, keeps the alt empty as before.
- A Logseq width map right after an image becomes the alt size: the fraction Logseq's drag can leave is dropped, and the height is kept as `|WxH`. This applies to an attached or a remote image. A map with no width, a link, inline code, an escaped image and a code block stay as written.
- A non-image `![[scan.pdf|300]]` embed is a link labelled by its file name, so the size no longer becomes its label.

**Trade.** The Logseq rewrite runs at import only (`parse_import_payload`), not in `normalize_foreign_forms`. That shared entry also serves Edit as Markdown and MCP writes, and Agaric's writer does not escape `{:width N}`: text a user typed would be rewritten on every save.

**Tests.** Two engine unit tests, two import tests in `page_cmd_tests.rs`, and a sized embed added to the real-backend Obsidian vault spec, which asserts the rendered width. Reds were shown for: the empty alt, the file-name label, the import call site, the inline-code skip, the dropped height and the escape skip. Gates: the import, attachment and image nextest filter, clippy, typecheck, and the `src/lib` vitest suite.
