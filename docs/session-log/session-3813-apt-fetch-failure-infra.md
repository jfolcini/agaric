# Session 3813 — apt-install retries a mirror it cannot download from, then calls it infra

- On #6502, `cargo-tests (2)`, `mcp-tests` and the real-backend build failed twice, ten minutes apart. Each time the cause was `Temporary failure resolving 'azure.archive.ubuntu.com'`, and `apt-get install` exited 100.
- `actions/apt-install` retried only an install that timed out, so a download failure went straight to red as an ordinary failure. It never got the `AGARIC_APT_INFRA` marker and exit 75 that mean "rerun the job".
- The install's stderr is now kept and printed after each attempt. When apt reports a download it could not make (`Temporary failure resolving`, `Could not resolve`, `Failed to fetch`, `Unable to fetch some archives`), the step waits a minute and retries once, reusing the .debs already fetched. If the second try fails the same way, it exits 75 with the marker. A package apt cannot find still fails at once with apt's own status.
- Test: `scripts/apt-install-action.test.mjs` runs the action's own `run:` script, read from `action.yml`, against stubbed `sudo`, `apt-get` and `sleep`. It covers four cases: a download that fails twice (exit 75, two installs, one wait), one that fails once (passes on the retry), a missing package (exit 100, no retry), and a clean install. It is registered in `_validate.yml`'s script-test step.
- Red: on main the first two cases fail (exit 100 where 75 and 0 are expected). Each half of the fix was then broken in turn. Disabling the infra classification reddens the twice case only. Disabling the retry reddens both download cases.
