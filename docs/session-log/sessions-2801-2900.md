## Session 2900 — has-property on column keys, undo refuses a taken name, a busy peer is quiet

#6051, three backend slips, plus the siblings review found.

**`HasProperty` on a column-backed key.**
- `todo_state`, `priority`, `due_date`, `scheduled_date` and `space` live in `blocks` columns. `block_properties` never holds them, by migration 0088's CHECK.
- The Pages, Search, Query and Backlinks projections all compiled `HasProperty` against `block_properties`, so `Exists` matched nothing and `NotExists` matched everything.
- `compile_column_property` maps the key through `reserved_key_blocks_column`, with `space` going to `space_id`. Operands bind as text, so `prop:priority=1` matches the stored `"1"`.
- `Ne` keeps each surface's meaning for a property row:
  - Pages, Search and Query match a block without the key.
  - Backlinks need the key.
- The mock moves with the backend, pinned by new conformance query steps.

**An undo never revives a taken name.**
- The maintainer's decision: an undo that would restore a tag or page title a live one now holds refuses, names the conflict and changes nothing. The whole group aborts, as with creating a duplicate.
- `reject_revived_duplicate_names` checks every page and tag a reverse revives after its writes. The edit reverse calls the same check as a rename, so the fold and the space scoping match.
- Every reverse path goes through `apply_reverse_in_tx`: History revert, the Activity Feed, MCP `revert_ops`, `undo_op`, `undo_ops`, `undo_page_group`, `undo_page_op`, `redo_page_op` and `restore_page_to_op`.
- It is a `Validation`/`DuplicatePageTitle` refusal, not `NonReversible`, so a point-in-time restore aborts instead of skipping the op. A name clash is current state the user can fix; skipping would leave a half-restored page.
- Trash restore, single and batch, now refuses a taken page title, as it already did for tags.
- **The refusal keeps its undo entry**, so the same Ctrl+Z works once the name is free. If the name stays taken, Ctrl+Z keeps hitting that entry, with a toast that says why. Dropping it would lose the undo.
- **Toasts show the backend's words only for this clash** (`takenNameReason`), on every surface that can raise it: undo, redo, swipe-undo, the delete-page toast's Undo, the Pages batch undo, both History dialogs, the Activity Feed and Trash, including Restore all. Every other failure keeps its previous copy. The message says "in this space", not a space ULID.
- **The mock is all-or-nothing:** its batch reverse handlers restore their state on a throw, as the backend's transaction does.

**A simultaneous dial is not a sync failure.**
- Both devices dial at once, and the responder refuses with `Rejection::Busy`, which has no user-facing message.
- Before, the initiator raised a red "Sync failed: peer is busy" twice: once from the orchestrator's `SyncMessage::Error` arm, and again from the supervisor's first-failure report.
- Both now stay quiet. The backoff is still booked, because the doubling is what keeps repeated collisions apart. The device row ends with the terminal progress event that a repeated failure sends, so the store gets no red dot and no toast.
- A refusal during a pairing window also ends the row.

**Shown red:**
- **Column keys:** with the column branch off, each surface's test returns an empty set. A number bound as `1.0` misses the stored `"1"`. Each surface's `Ne` arm and the substring operators have their own red.
- **Name checks:** with the restore-arm or edit-arm check off, the tag, page and rename tests get an `UndoResult` instead of the refusal. With the Trash page arm off, both restore tests succeed.
- **Undo entry:** with every Validation permanent again, the refused undo and redo lose their entries.
- **Toasts:** with the helper widened to any Validation, the generic-copy tests fail. With each site back on generic copy, that site's clash test fails.
- **Mock:** with the mock's check off, or a handler unwrapped from `allOrNothing`, the conformance fixtures and the mock's own tests fail. The Playwright case fails at the toast and at the page counts.
- **Busy:** with the supervisor passing no rejection, the Busy test sees the original "Sync failed: … peer is busy" event. Making every rejection quiet fails the existing outside-a-pairing-window test. With the pairing-window progress event removed, 0 events arrive instead of 1.

**Not here:**
- #6099: a move to another space does not check names there.
- The `create_block` response's `position` can differ from the stored one; to look at.
- A user-pressed sync's terminal progress still sets the global status to `error` for a quiet failure. That predates this change.

## Session 2898 — quoted aliases round-trip, page names fold like tags, one attachment-ref vectors file

**Attachment refs.** `conformance/attachment-refs.vectors.json` is read by both the Rust importer's tests and `import-attachments.ts`'s, replacing a "MUST stay in sync" comment. The rows #6032 still owes (refs with spaces, `)`, `%20`, `<…>`) carry a note and pin today's behaviour.

The reviewer's release-mode estimate is well inside the interactive target; bulk import pays it per file. An ASCII fast path in `normalize_tag_name` is the follow-up.

## Session 2895 — a trashed block moves with its page to another space

#6080: a page moved to another space lost its trashed blocks. The SQL move stamps every row of the page into the new space (`id = ? OR page_id = ?`, trashed rows included). But the engine side pruned the whole subtree from the old doc and seeded only live rows into the new one. A peer then saw the trashed rows in neither doc, and `sweep_deferred_purges` hard-deleted them. On the moving device, a restore after the move reached no doc, so it never synced.

**Fix:** `hydrate_page_subtree_into_engine` now walks trashed rows too, and seeds each one as a tombstone at its own `deleted_at`. The engine's `apply_delete_block` stamps one node, so a trashed cohort keeps its timestamps and a restore still finds it.
- **Live move:** every trashed row becomes a tombstone.
- **Boot replay:** a row trashed at or before the move becomes a tombstone. A row trashed after it is seeded live, and its delete's replay tombstones it again (#5647).
- **The tie counts as before.** A row trashed in the move's own millisecond must become a tombstone. When its delete replays before the move, which is the case for a delete the snapshot watermark withheld, nothing would tombstone it again.

The same function serves undo of a move, the first space assignment of a page created before its space (#2249), and both repairs, so they all carry trashed rows now.

**Proptest:** `proptest_db_harness.rs` had a guard that blocked space ops while anything was trashed, because the hydrate was live-only. It is deleted.
- With the old live-only filter put back, B5 and B6 then find the bug within a few thousand cases. The minimal input is create, create, delete, set space, restore, move, which takes the SQL-only fallback.
- On the fix they ran clean at 22,000 / 20,000 / 18,000 / 12,000 cases (B5, B6, B2, B1).

**Shown red:**
- Restoring the live-only filter: both two-device tests fail, B's row missing from the trash and the new doc not holding the restored block. The conformance parity guard reports `SQL=true, Loro=false`, and both `crash_tail_space_move` variants fail.
- Seeding live instead of tombstoned: the new assertion that A's new doc holds the rows tombstoned fails.
- Comparing the tie with `<`: the same-millisecond replay test fails.

**Not here:**
- Vaults already hit keep their trashed rows in no doc until the page moves again. A repair is the maintainer's call.
- Property ops on a trashed row still never reach the doc.
- The move/sync proptest has no trash or restore op.

## Session 2894 — a / in an Evernote, Joplin or Org title stays one page

#6032 item: a `/` in an Evernote or Joplin note title silently became a namespace level, so "TCP/IP" became page "IP" under "TCP". **Maintainer decision (2026-10-23): escape the `/` on import.**

**The app has no escape syntax for a title.** `/` is the namespace separator everywhere: `page-display.ts` splits on it, the export makes folders from it, and the backend's `folder_path_to_namespace_title` splits an import path on it after reading `\` as `/`. Teaching every splitter an escape was not wanted. So the importers swap the character for a look-alike that is not a separator: `/` becomes U+2215 (`∕`), and `\` becomes U+29F5 (`⧵`).

**Changes:**
- `sanitizeNoteTitleToFilename` escapes. It serves Evernote file names and the Org `#+TITLE` retitle, both titles that come from file content.
- Joplin escapes each notebook name and the note title separately, then joins them with a real `/`. The notebook chain still builds the namespace; a `/` inside one name no longer does.
- Joplin note links come from the same title, so `[label](:/id)` resolves to the escaped page.
- Left as they are:
  - Notion titles and plain folders, whose `/` comes from real folder paths;
  - the bibliography, whose title the backend builds from the citation.

**Round trip:** the export splits a title only on `/`, and neither look-alike is a reserved file-name character. So `TCP∕IP` exports as `TCP∕IP.md` and re-imports as one page.

**Shown red:** each unit test fails with its escape removed:
- the sanitizer, `TCP/IP` and `C:\Temp`;
- the Evernote file name;
- the Org retitle;
- the Joplin notebook name and note title;
- the Joplin link target.

Two real-backend cases in `import-formats.e2e.ts` (an `.enex` and a `.jex`) run first in CI.

## Session 2892 — one page-mode save timed on the real backend at the cap

#5691's MVP budget at the cap includes "one save's IPC cost", which had been measured on the mock only. A mock IPC is a deferred task, not SQLite and Loro. `e2e-tauri/page-mode-save-cost.e2e.ts` is an opt-in real-backend harness: it skips unless `AGARIC_PERF` is set.

**What it does:**
- It seeds a 1000-block page through one `create_blocks_batch` and opens it in page mode with the cap intact.
- It times each kind of save from the app's own `page-mode-save` measure, which ships in production builds: typing, a blur with nothing to save, Enter then a key, and Tab.
- It times the same edits' single IPC round trip in block mode on other blocks of the page.
- Writes are counted as the growth of `total_ops`.
- Each edit starts only once the materializer is idle: its queues are empty and its dispatch counters have stopped moving, since a drained batch still runs while the queue reads empty. The 1000-block batch's overflow comes back through the retry queue.

**Measured** (debug build, WebKitGTK under Xvfb, 5 repeats, median [min–max] in ms):

| edit | page mode save | block mode IPC | writes, each mode |
|---|---|---|---|
| typing | 14 [13–26] | 9 [8–10] | 1 |
| blur, nothing to save | 3 [2–9] | no IPC | 0 |
| Enter, then a key | 41 [32–47] | 23 [20–31] | 1 |
| Tab | 44 [39–156] | 35 [31–44] | 1 |

Page mode's save costs 5 to 18 ms more than block mode's round trip for the same edit, and writes the same one op. Load average during the run: 0.24 / 0.91 / 1.72. Enter runs two saves: an empty flush of the block being left, then the create.

**Run with:**

```
AGARIC_PERF=1 just e2e-real e2e-tauri/page-mode-save-cost.e2e.ts
```

`AGARIC_PERF_REPEATS` sets the repeat count. Without `AGARIC_PERF` the spec reports three skipped tests.

**Checks:**
- `npm run typecheck:e2e-tauri`;
- `npx vitest run e2e-tauri` (46 passed);
- `node --test scripts/e2e-related.test.mjs`;
- the measured run and the skip run.

## Session 2889 — a restore is a page-level undo step of its own

#5691 lists one gap in page mode's page-level undo: a block brought back by an editor undo, a restore, recorded no op ref. So the earlier delete stayed on top of `UndoStore`, and a `Ctrl+Z` outside the document took back the delete instead of the restore.

**Change:**
- `restore_block`'s Tauri wrapper returns `WithOps<RestoreResponse>` through `capture_op_refs`, as create, edit and delete do. One `restore_block` op covers the whole cohort, so the response carries one ref, and undoing it re-deletes the cohort.
- Page mode's save returns that ref along with a `restored` flag.
- `PageModeEditor` pushes a save that restored with `merge: false`. Both saves flush at once when the caret leaves the block, so without that the restore merged into the delete's entry, and undoing the pair changed nothing.
- The mock's `restore_block` returns the ref too.
- A new conformance fixture, `restore_block_undo.json`, has the backend author the undo of a restore.

**"After leaving the page" is not where this shows.** Leaving a page clears its stack: `PageEditor`'s cleanup calls `clearPage`, and the tab bar keeps no page mounted in the background. Coming back therefore falls through to the positional `undo_page_group`. The case that reads these refs is leaving page *mode*: switch to Blocks, blur, then `Ctrl+Z`. The new e2e does exactly that. A restore from the Trash view needs nothing: the page's stack is cleared while the Trash is open.

**Shown red:**
- **Rust** `restore_block_op_refs_undo_the_restore_5691`: with the store's capture disabled, it fails at "one op ref, got []".
- **vitest:** with `merge: true`, the stack has 1 entry, not 2. Dropping the refs fails the same way.
- **e2e** `page-mode.spec.ts`: with `merge: true`, block 31 stays live beside "block 30block 31", and that fails 3 of 3 runs.

## Session 2884 — a page-mode keystroke no longer lays out every block on WebKit

#5691's item "No per-keystroke work that grows with the page". On WebKitGTK, the desktop runtime on Linux, a keystroke in page mode cost more the longer the page was, while block mode's cost stayed flat.

**Cause: one CSS rule, not script.**
- **The JS is small.** A Chromium profile put page mode's JS at about 5–7 ms per key, mostly ProseMirror's `readDOMChange`, `dispatch` and plugin updates. It grew by only about 2 ms from 250 to 2000 blocks.
- **WebKit spends the time natively.** Most of a key went to WebKit's own text insertion, from keydown to `input`; `view.dispatch` took only a few ms of it.
- **A clone with no JS costs the same.** Page mode's DOM cloned into a plain contenteditable, with no ProseMirror and no JS, cost the same per key. Removing page mode's CSS from the clone took most of it away.
- **Bisecting the CSS named `display: flow-root`** on every `[data-page-block]`. #5825 had added it to keep a list marker's float inside its block, and measured it only on Chromium. WebKit re-lays out every block that is its own formatting context on each key. `contain: layout` has the same cost.

- Blocks are no longer formatting contexts. A `::after { clear: both }` clearfix keeps the marker's float inside its block.

## Session 2883 — the block-focus helpers wait for the editor's own focus to settle

`e2e/background-tabs.spec.ts` › "Alt+Enter with the caret right after a link in a block follows it" failed in CI on #6068, #6075 and #6078. `md-reveal-chip-marker` received no `[[` `]]` within 15 s. Each time, CI's stop-after jobs then cancelled the run's real-backend shards, so `e2e-tauri-gate` went red too.

**Cause, a race in the helpers, not the app.**
- `focusBlock` and `focusBlockById` (`e2e/helpers.ts`) returned the editor before its own focus sequence had run.
- The mount focuses the editor one frame later: `mount()` in `src/editor/use-roving-editor.ts` → TipTap's delayed `focus` → `requestAnimationFrame` → `view.focus()`.
- ProseMirror's focus handler (`handlers.focus`, `prosemirror-view`) then arms a 20 ms timer. The timer writes ProseMirror's selection back over the DOM's.
- Chrome holds `selectionchange` back while keys stream in, so ProseMirror never reads the arrow keys' moves as they happen.
- On a loaded runner the timer fires mid-stream and undoes the arrows sent so far. The caret lands a few characters right of the link, where no syntax is drawn.

A user would have to press an arrow within about a frame plus 20 ms of the click, so the app is unchanged.

**Fix.** The two helpers share `editBlock`. After the click and `editor.focus()`, it waits for `requestAnimationFrame(() => setTimeout(resolve, 20))`. The frame callback runs after the mount's, and a 20 ms timer queued inside it runs after ProseMirror's. This is the `caret` helper's technique (`e2e/page-mode.spec.ts`) plus the frame hop. It is in the shared helper because about 35 call sites press caret keys straight after it.

## Session 2869 — the frozen-peer cancel spec waits out a session the daemon started

## Session 2867 — moves and edits record their prior state, so undo works on a block a peer made or changed

This session fixes #6046, from the 2026-10-22 architecture review (#6055).

**What was broken:**
1. **A move of a block created on another device couldn't be undone.** `find_prior_position` and its batch twin read only `is_replicated = 0` rows, and that block's only create row is replicated.
2. **Text undo could restore a stale version.** `prev_edit` was stamped by `LatestCausal`, which orders by `seq` across devices. `seq` is a per-device counter.
3. **Undoing a redo could overwrite a value a peer wrote in between.** A reverse `SetProperty` carried `prior: None`.

**The change.** An op records the state it replaces, and the reverse kernels read that record first.
- **`MoveBlockPayload.prior`** (`BlockPlacement { parent, index }`): `move_block_in_tx` stamps it from the live SQL siblings (`live_placement`) in the same `BEGIN IMMEDIATE` transaction as the append.
- **`EditBlockPayload.prior_text`:** `find_prev_edit_in_tx` reads `blocks.content` in the transaction. It points `prev_edit` at the newest row holding that text, replicated rows included (`LatestHolding`). Only when no row holds the text does it fall back to the causal row and record `prior_text`.
- **Reverse ops.** Every append site in `history.rs` stamps through `with_recorded_prior_in_tx`: positional undo, redo, and batch revert. Undo and redo of a move or a property are then exact inverses, and a redo never writes an older local value over a peer's.
- **Revert order.** `plan_reverse_apply_order` reverts newest-first when the moves carry priors. Moves written before this change keep the legacy ascending path.
- **Byte and hash stability.** The new fields are `serde(default, skip_serializing_if = "Option::is_none")`, so old ops keep their bytes and hashes. A test pins both. Remote ingest hashes the raw payload, and no op payload lives in Loro, so `ENGINE_FORMAT_VERSION` is unchanged.

**Caught in review: a performance regression.**
- **The cost.** `LatestHolding` ordered by `seq DESC, device_id DESC`, which made SQLite sort every row of the block and `json_extract` each payload on every edit commit. On a dev build that roughly doubled the old stamp. The 10,000-edit, 4 KB block went from about 40 ms to about 100 ms per commit.
- **The fix.** It now orders by `created_at DESC LIMIT 1`, which follows `idx_op_log_block_created`, so the walk stops at the newest holder and the cost no longer grows with the edit count. Which holder row is named doesn't matter: all hold the same text, and the kernels read only the text.
- **Measured.** The measuring harness was temporary and is not committed, so the figures are directional only. With the fix, the stamp is about 0.2–0.3 ms at every size measured.
- **Two store tests pin it:** the newest holder wins, and an older row with a non-JSON payload is never decoded.

**AGENTS.md.** With the maintainer's approval, one clause in `src-tauri/src/commands/AGENTS.md` now says that a create with no slot makes the block's first move non-reversible only when that move records no `prior`. That means a move written before this change, or a boot repair's. The stale copies of the old claim in `block_ops.rs` and the mock's `appendSlot` doc were fixed too.

**Accepted trades, from the review:**
- A reverse edit and a reverse delete-property are not stamped. Their redo differs only after a peer write in between, which the undo had already lost.
- Boot-repair moves and draft recovery record nothing.
- `compute_edit_diff_inner` keeps its timestamp scan, because it is display-only.

**Shown red:** with these mutated, the predicted assertions failed:
- the holder query's old order;
- `prior: None` on forward moves;
- reverse moves left unstamped;
- the redo site's stamp;
- the batch kernel ignoring `prior`;
- the order planner's prior check;
- `LatestCausal` in `find_prev_edit_in_tx`.

The failing tests included the conformance fixture `redo_of_a_move_undone_out_of_order` and `undo_and_redo_keep_a_value_a_peer_set_in_between_6046`.

This session closes #5691's checklist item "No plugin scans the whole document on every transaction".

**Lowlight was a real whole-document walk.** Stock `@tiptap/extension-code-block-lowlight` (`dist/index.js`):
- calls `findChildren` on the old and new document on every transaction, selection moves included;
- re-highlights every code block whenever an edit touches one, or the number of code blocks changes.

In page mode's whole-page document, that cost lands on every keystroke.

- **Paragraph-like blocks are collected too.** Two edits turn code into a paragraph: `toggleCodeBlock` (and Turn into a paragraph) and a Backspace join onto the paragraph above. In both, the mapped colours would otherwise stay on text that is no longer code. The review caught this.

## Session 2839 — undoing a property change restores the value another device set

#6014: undo of a SetProperty restored the value the log said was there, not the one that was. A peer's value arrives as a replicated op, which the reverse kernels never read. So after a peer set `due_date` and you changed it, undo cleared the date instead of restoring the peer's. This is the SetProperty twin of #5918, which fixed the same for DeleteProperty.

- **`SetPropertyPayload` gains `prior`**, the five value slots the key held when the op was written. It carries `serde(default, skip_serializing_if = "Option::is_none")`, so an op without it keeps its exact pre-#6014 bytes and hash. Remote ingest hashes the raw payload, nothing denies unknown fields, and op payloads never enter Loro, so `ENGINE_FORMAT_VERSION` stays.
- **The central writer records it.** `block_ops::set_property_in_tx_with_declaration` reads the held value, as recurrence, MCP batch, import, page-source apply, bibliography, space moves and repairs all go through it. `repair_misfiled_tag_spaces` records it directly. The three space migrations record nothing: they only fill a key that is empty.
- **An absent key records all five slots empty.** No held value can be all-null: `exactly_one_value` holds since migrations 0062 and 0088, and promoted columns count only when non-NULL. So "all empty" means absent, and undo deletes the key. Without that, a set over a key a peer had deleted fell back to the log and resurrected the old value. The cost is about 108 bytes on a first-time set.
- **Both reverse kernels read it.** `reverse/property_ops.rs` and `reverse/batch.rs` read `prior` first, through `PropertyValueFields::into_held()`. They fall back to the op log only for an op that records none.
- **The mock follows.** `hasPriorPropertyValue` stamps the reverse op type from the recorded `prior`.

The reviewer traced every reader of a stored or remote SetProperty payload, and every `json_extract`, to top-level fields only. No conformance fixture can express "a value with no op", so the backend's two-device tests pin it.

## Session 2824 — an arrow into the next block keeps the keyboard focus

In block mode, an arrow key that left a block (ArrowRight or ArrowDown at its end, ArrowLeft or ArrowUp at its start) made the next block's editor live but left the focus on `<body>`, so the next key typed went nowhere. ## Session 2821 — one refused block no longer holds back the page's other writes, and a reread never patches in rows its load did not apply

Three findings of the #5691 review of 2026-10-21, verified by a second pass, in page mode's save.

- **A refused create held back everything.** When the backend refused a new block (content linking a page in another space, or a block over 256 KiB), the save returned at the failed create, and a gate then held back every delete. No other edit or delete on the page was written while that block held that content, and leaving dropped them. Now a failed create or restore only holds what depends on it. Its children's creates and restores wait, and the creates are replanned so a block placed after it takes its slot from the tree as it really is. `planMoves` neither moves a block the backend does not hold nor anything under one. An edit waits only if it removes text from the block just before a block still to be created, the block that may have been split from (#5272), at whatever depth the new half now is. A delete waits only while a block under it (itself included) is one the document shows, or has its text in a block the backend does not hold as shown, for the delete takes the blocks under it along. A paste in the middle of a block hands its tail to the last block pasted, so if that one is refused after the blocks pasted before it were created, the tail is held by nothing and is lost if the page is left. The order (creates, moves, edits, deletes) and the rule that a block's saved state advances only on success are unchanged.
- **A reread could patch in stale rows.** `read()` returned the store's rows even when its own load was overtaken by a newer one or failed. `read()` now returns the store's rows only if they are a new array after its load, which only a load that landed sets (a failed one, or one a newer load overtook and that is still going, leaves them), and throws otherwise. It reads the store, not a subscription, because the save made as the page closes reads after the subscription is gone. A failed read patches nothing in.
- **A failed reread skipped the toast.** When a refused write's reread failed, `runSave` threw past both the save-failed toast and the undo entry for the ops that did land; a `finally` now records both.

The mock still overwrites a colliding create id the backend refuses, so the mock lane cannot show a colliding-id hold. The cross-space refusal can only be shown on the real backend.

## Session 2820 — page mode opens on the current text, keeps typing bounded, and does not let a failed save switch away

Four findings of the #5691 review of 2026-10-21, verified by a second pass, were fixed together because they share the switching and opening code.

- **The shortcut opened page mode on a stale page.** `Ctrl+Shift+M` within the idle delay of the last key opened page mode without that text: the draft flush had saved it, but nothing refreshed the page store, and the first page-mode edit of the block wrote the old text back. Clicking the switch was fine because the click blurs the editor first. `takeCursor` (`use-page-mode.ts`) now blurs the active editor before taking the cursor, so block mode's own blur commits through the store on every path, including page mode coming back by itself once a page fits the cap again.

- **A new or empty page did not take typing.** When page mode opens on a page whose only block is empty, it now focuses the document, as block mode focuses its first block; a page with text keeps the focus where it was.

`usePageMode` also selects the block count instead of the whole block array.

## Session 2819 — page mode gets block mode's grip, chevron, collapse, drag and gutter menu (#5691)

Page mode had none of block mode's gutter: no grip, no chevron, no collapse, no drag, and the block menu only from the caret. This session added all four, reusing block mode's look and layout state rather than a second design.

- **Grip and chevron** are plain DOM buttons in the page block's node view (`page-gutter.ts`), not React per block. They take block mode's classes, `chevronToggleVariants`, glyphs, aria labels and i18n keys, and sit where block mode's do; a parity test renders block mode's and compares classes and SVG markup, so the copied glyph geometry cannot drift. A press keeps the editor's focus and caret, `stopEvent` keeps their keys away from ProseMirror, a fold redraws the same chevron so a keyboard user keeps the focus on it, and the block's hover reaches across the gap to the gutter so the controls stay while the pointer walks to them.
- **Collapse** (`page-collapse.ts`) reads and writes block mode's per-page, per-device `blockCollapse` layout (`loadCollapsedIds` / `saveCollapsedIds`, now shared), so a block collapsed in one mode is collapsed in the other. Hidden blocks are node decorations rebuilt only when blocks move, a toggle fires or the reveal changes; typing only maps them. The caret's block is never hidden (block mode's #4002 rule), `Ctrl+.` works on the caret's block, and a split of a collapsed block (Enter, a paste of blocks) puts the new blocks after the hidden ones (`keepHidden`, an `appendTransaction` that runs after the id rules). Backspace at the start of the block after a collapsed block's blocks joins the collapsed block, as block mode's merge does, and Delete at the end of a collapsed block joins the block after them: neither joins a block that is not shown.
- **Drag** (`page-drag.ts`) moves a block with its subtree by pointer, with block mode's 8 px threshold, drop bar, depth clamp and edge autoscroll; Escape, or the window losing focus, cancels it. The drop only edits the document (`dropBlock` through `applyRows`, as Move Up does); the continuous save writes it, and a subtree move is a single `move_block` of its root.

## Session 2817 — `DeleteProperty` records the value it removes, so undoing a delete of a peer-set property works

#5918: on device A, deleting a property device B had set and pressing Ctrl+Z failed with `NotFound`, and since a fatal step aborts the page's undo group, Ctrl+Z on that page stayed stuck. `reverse_delete_property` found the value to restore with `find_prior_property`, which reads only local ops (`is_replicated = 0`), so a value that arrived from a peer, or one whose local set compaction pruned, had nothing to find. Every claim in the issue held, including the batch twin (`fetch_prior_property_batch` / `build_reverse_delete_property`).

The fix is the optional `prior` the #5841 design gives `DeleteProperty`: a `PropertyValueFields` with the five value slots, serde default and omitted when absent, so an op without it serializes and hashes exactly as before (pinned against the old bytes and hash). Every writer records the value it removes, read in its own transaction by `held_property_value` (column-backed keys from their `blocks` column, the rest from `block_properties`), which replaces `property_is_held`: `delete_property_core` (Tauri and MCP), `delete_property_in_tx` (todo stamps, repeat bounds, page-source apply), the `completed_at` repair, and the reverse of a set that created its key. Both reverse kernels read `prior` first and fall back to the op-log lookup only for ops written before this change.

No format bump: no op payload denies unknown fields, remote ingest hashes the raw payload and decodes only `SetProperty`, replicated rows are never applied or reversed, and Loro never carries op payloads.

The two-device tests apply B's real commands to A through `prepare_outgoing_for_pool` and `apply_remote`, then undo on A positionally and as a page group; with `prior` dropped they fail with the issue's own `NotFound`. Two more tests pin the slot each held value is recorded in: every column-backed key and every typed `block_properties` slot, and a page's `space`. A broken `scheduled_date`, `space`, `value_ref` or `value_bool` slot had passed the whole suite, while each left a wrong value or an aborted undo group. The review confirmed the sibling by experiment: `reverse_set_property` uses the same local-only lookup, so overwriting a value a peer set and undoing clears the key instead of restoring the peer's value; it needs a `prior` on `SetProperty` (#6014).

Suites run: nextest over the property, reverse, undo, conformance, op-log and repair tests (1351 passed); clippy and `cargo check --all-targets` clean; vitest over the Tauri mock (1151 passed); `npm run typecheck`; each new test falsified by its own mutation.
