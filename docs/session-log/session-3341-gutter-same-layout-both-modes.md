# Session 3341 — the gutter lays out the same in page mode and block mode, inside the box

The maintainer asked, after #6296, that both editing modes lay out a block's gutter the same way: inside their box, just wide enough for the grip and chevron, the checkbox only on a task line, and the same text x for the same block shape in either mode. Claimed by paths, no issue.

**What was there.** Block mode hung its control lane and a checkbox slot in the pane's left margin (`md:pointer-fine:-ml-13.5`, so a depth-0 checkbox lined up with the heading), and drew an empty checkbox on every desktop row as a hover "make this a task" affordance, so plain text and task text started at the same x and a root block with a chevron and a checkbox put its grip outside the column. Page mode reserved the checkbox slot on every row inside its frame (`pl-20`), 47 px right of block mode's text. Only the phone layout in block mode drew the checkbox on tasks alone.

**What changed.** Shared custom properties in `src/index.css` (`--block-lane`, the grip and chevron with their gap; `--block-gap`; `--block-checkbox`; `--block-inset`, the text box's `px-3`) size both modes. Block mode drops the hang; its lane is `min-w-(--block-lane)` and its row gap `gap-(--block-gap)`; `BlockInlineControls` draws nothing for a plain line on a fine pointer, and the empty checkbox's code and its two i18n strings are gone. Page mode's text padding, a task block's padding (checkbox and gap), the checkbox, the chevron gutter, the grip and the hover lane all come from the same properties. At 1280 px and the Medium size, both modes now draw plain text at 442 and task text at 466 (page frame / column at 384), against 418 (block) and 465 (page) before. A task is still set through `/todo`, Ctrl+Enter, and the block context menu (block mode) or block menu (page mode). Phones: block mode unchanged; page mode's phone layout unchanged, its grip 12 px nearer the text.

**Tests.** `e2e/gutter-layout.spec.ts` pins text-x parity between the modes for a task, plain parent, plain leaf and task parent at Small, Medium and Large; the no-gap rule; every control inside the box with the row hovered; no text shift on hover; and the three task-setting paths. Its geometry tests were red on `origin/main` ("Expected 12, Received 34/36/38"), green after; dropping page mode's task padding or restoring the hang reds it. Specs and unit tests that clicked the empty checkbox to make a task now use Ctrl+Enter, the menu or `set_todo_state`, or assert that a plain line has no checkbox; the e2e-tauri ones (`advanced-query-saved-views`, `block-clipboard`, `due-date-agenda`, `history-redo-revert-restore`, `reserved-property-roundtrip`, `slash-repeat-remove`, `undo-todo-state`) were type-checked only — no tauri-driver here — and `e2e-tauri-gate` runs them. The builder ran every Playwright spec file: two `diagram-legibility` cases fail identically on the base sources, unrelated. A right-click on another block while one is being edited opened no menu in the builder's runs; it is unrelated to this change and not chased here.
