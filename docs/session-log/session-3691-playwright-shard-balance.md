# Session 3691 — deal the Playwright shards by measured file time

Part of the slow-test sweep. On recent PR runs the Playwright shard was `validate-all`'s long pole, and shard 3 was the slowest of the four: about 10.9 min against 9.0–9.2. Playwright's `--shard` cuts the test list into contiguous runs of equal count, so the files with the slowest tests (`page-mode`, `page-source-edit`, `pages-view`, all about 5 s a test against a 3.3 s median), which sort together, landed in one shard. Timing every test locally (1741 tests, about 101 worker-minutes) reproduced the ratio CI shows: 23.4, 25.7, 29.1 and 22.7 worker-minutes.

Playwright has no supported duration-based sharding: shard selection is contiguous by file order, `--shuffle` reorders only within a shard, and `PWTEST_SHARD_WEIGHTS` is internal. So the PR lane now runs, per shard, the file list `scripts/playwright-shard.mjs k/4` prints. It deals the files longest first into the shard with the least time so far, by each file's seconds in `e2e/spec-durations.json`. The same script's `--update <report.json>` rewrites that file from a JSON-reporter run, counting passed runs only, and a file it does not know counts as the median. On the committed data each shard holds about 1515 s of tests. `--list` over the four lists gives the same 1741 tests as an unsharded run, each once. The weekly `full-suite-playwright` has its own job definition and still uses `--shard`.

Also folded in, from the reviews of #6453 and #6456: the RUSTSEC-2026-0459 entry moves to the end of `deny.toml`'s ignore list, away from the comment about the removed `rsa` advisory; and `wdio.conf.ts` reads `spec-durations.json` with a plain cast, since only our own script writes it.
