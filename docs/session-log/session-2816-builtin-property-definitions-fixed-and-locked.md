# Session 2816 — built-in property definitions are fixed and locked (#5841 S0.1)

The maintainer asked for #5841's first slice. A dead session had left a WIP diff for it; this session resumed it on current `main`, resolved its three conflicts, and finished it.

The built-in keys now have their definitions in code, not in `property_definitions` rows: `BUILTIN_PROPERTY_DEFS` sits next to `is_builtin_property_key` in `agaric-store/src/op.rs`, with a TS mirror in `src/lib/property-save-utils.ts` (a parity test parses the Rust array, and `NON_DELETABLE_PROPERTIES` derives from it). `todo_state` is fixed to TODO/DOING/DONE/CANCELLED and `priority` to 1/2/3. `property_declaration()` returns the built-in before any row, and `set_property_in_tx`, the import property lines, `read_typed_ref` and the projection's value-type lookup all go through it. `list_property_defs` and `get_property_def` merge the built-ins in with a `builtin: true` field, keeping keyset pagination intact; creating, editing the options of, or deleting a built-in returns `ValidationCode::BuiltinPropertyLocked` in Rust, the TS code mirror and the mock. Migration 0128 deletes the built-in rows plus the retired `due` definition; block values stay, including an out-of-range priority, which keeps its value, draws a neutral badge and sorts last on the frontend. New out-of-range writes are refused.

Deleted: the Rust fallback defaults and reserved-value checks, the dynamic priority-levels module and `usePriorityLevels` (callers read `PRIORITY_LEVELS` / `PRIORITY_CYCLE`), the boot load, and the options editor's priority branch. `NON_DELETABLE_PROPERTIES` grew by `space`, `is_space` and `listStyle`, so add-property menus and custom query columns no longer offer them.

Traps: a Radix `Tooltip` around the built-in badge overwrote the badge's `data-slot` through `Slot` and broke `mobile-overflow.spec.ts`, so the badge has no tooltip. `set_priority` is not wired in the conformance command leg, so the new refusal fixtures use `set_property`; `CONFORMANCE_UPDATE` also reformatted three unrelated fixtures, which were restored. Left for later: the checkbox / keyword / `[#X]` cookie branch of `PropertyLines::keep_refused_as_text` can no longer fire now that the options are fixed.

Suites run: the full nextest workspace in two partitions, clippy with `-D warnings`, `SQLX_OFFLINE=true cargo check --workspace --all-targets`, the full vitest suite in four shards, typecheck and lint, and the Playwright specs for properties, settings, search, agenda, the Due panel, graph, batch, references and mobile overflow. Each new check was shown red by breaking the code it covers. The e2e-tauri lane was not run.
