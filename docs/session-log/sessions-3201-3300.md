## Session 3296 — Evernote tasks and reminders import as tasks

#6032 batch C, built by the orchestrator session and handed over for review and
merge. An Evernote 10 `<task>` was lost on import and its group's
"Content not supported" placeholder came in as prose; an old-style note
reminder was dropped. Both now import as task blocks, as the maintainer decided
on 2026-11-04: `- [ ]` or `- [x]`, `dueDate` as `due_date::`, the first

instead of the task's zone, and added the cases mutation showed open: two task

## Session 3291 — The spoken-text builder for Read aloud

Slice S4 of #5745: `src/lib/speech/spoken-text.ts` turns blocks into the
utterances *Read aloud* will speak, with no UI yet (S6 waits on the
maintainer's `speechSynthesis` check on macOS and Windows).

It walks `parse(content)` and reads what the static renderer shows: text with
marks dropped, links by label, page links and tags by title, block refs by
resolved text, image alt text, tables row by row, ordered-list numbers. A
missing link, tag or block speaks "missing page / tag / block", never the id
prefix the chip shows (Q4); the miss is detected the same way the renderers
detect it. Code blocks, Mermaid, math, embeds and query blocks are named and
skipped. Property lines are stripped; the task state is spoken as its word.

A block longer than `MAX_UTTERANCE_CHARS` (4000, Android's
`getMaxSpeechInputLength`) splits at a sentence, else a word, else a hard cut
that never splits a surrogate pair. The limit counts UTF-16 code units, as
Android's `CharSequence.length()` does, so the Rust `speech_speak` check (S5)
counts `encode_utf16()` too.

Review removed a callout-label extra (it imported `CALLOUT_TYPES` from a
component, which `lib-layering` forbids), a `RangeError` guard nobody calls,
and optional resolvers no caller leaves out. The module is enrolled in
`stryker.modules.mjs`. Not spoken: a numbered block's `list_style` ordinal,
which lives outside the content; S6 must pass it in if wanted.

Ran: vitest over `src/lib/speech` and the i18n suites, `npm run typecheck`,
`npm run lint`, `prek run --hook-stage manual --all-files`, mutation
(`spoken-text`: 93.10%, 5 survivors, all equivalent), and falsifications of
the missing-tag and surrogate paths.

## Session 3265 — search follows a cross-space mention's target

dropped the tag edge.

Two existing tests changed as the plan says. The store test that planted a
`block_tag_refs` row no longer does, and the oracle `fts_fixture` lost its

`bench_reindex_fts_references` (`interactive_slo`) times the tag reindex,
the page reindex, and the `block_tag_refs` rebuild a tag-carrying import
already pays. The rule, fixed in advance: if the scan (tag − page) costs more

## Session 3246 — keep a ref into another space whichever space syncs first

#6236: a ref property on a block in one space that points at a block in another lost its row on a newly paired device when the holder's space was imported before the target's. The FK guard in `reproject_property_row_from_engine` (#377) dropped the row because the target had no `blocks` row yet. The target's later import never revisited the holder. The sender walks its spaces in `HashMap` order, so it was a coin flip. Engine-first recovery had the same bug: it walks the snapshots by space id.

- `project_dropped_refs` (agaric-engine projection): for each key a space declares `ref`, it reads that space's holders from the engine and re-projects those with no row whose target now has a `blocks` row.
- `LoroEngineRegistry::property_holders` reads a registered engine without creating one or marking it dirty.
- An import runs the pass before commit, but only when it gives some block its first row (`brings_new_block_rows`, asked before Pass A). Healed holders join the changed set, so their pages refresh.
- Engine-first recovery runs it after its last space. When a space's holders don't read, recovery logs, leaves that space's refs dropped and arms the retry marker, as it does for a block whose properties don't read (#2920). A plain `?` there would fail every boot, since recovery runs at pool init. No engine write produces a map that doesn't read, so that arm has no test.
- A default vault declares no `ref` key, so there the pass costs one batched existence probe and one empty SELECT.
- One existing test pinned the old outcome. `a_session_without_the_new_doc_sweeps_the_moved_page_5712` expected B to lose the ref on `notes` after a sweep. The old doc still holds that ref, so it now comes back. The link and the tag stay lost.
- No e2e-tauri spec: the sender's space order is random, so a spec couldn't be shown red on demand. The Rust test runs both orders through the same real commands and `apply_remote`.

**Review.** A separate reviewer re-ran eight mutations, each red at the predicted assertion. It added an assertion that the last import reports the healed holder as changed; nothing had pinned that merge. It fixed stale prose, including the oracle's header table. It also replaced recovery's log-and-skip with a plain `?`, calling that arm unreachable. I restored the log-and-skip: recovery runs inside pool init, so one bad map would stop the app from booting on every start, and its sibling `project_engine_property_defs` skips the same way.

**Found in review:** tags have the same two gaps. A scratch test showed that, with the holder's space imported first, B misses the `block_tags` row and `reconcile_all` reports `engine.block_tags.row`. Engine-first recovery drops the edge to a tag in a later-sorting space. The tag fix is its own PR. Links have no order bug: the cross-space filter in `block_links` keeps them out either way.

## Session 3244 — hand a contested alias to the next claimant when its holder drops it

#6229: when two pages claimed the same alias, the one with the lower id held the `page_aliases` row and the other kept only its engine-map claim. If the holder then dropped the alias, or was purged, nothing gave the alias to the remaining claimant. The alias stopped resolving on every device, even though a page still claimed it.

- `project_unheld_page_alias_claims` (`agaric-engine` projection) gives each alias that the engines claim and no row holds to its lowest claimant with a `blocks` row, spelled the way that page's map spells it. It skips an alias whose folded key a row already holds, so it cannot hit the `page_aliases` UNIQUE index.
- It runs once per transaction, before commit, on each of the three paths that can leave an alias unheld:
  - `CommandTx::commit_and_dispatch`, when the batch removes an alias or purges a block. Not per op: a respell removes and then re-adds the same key, and a per-op hand-off would give the alias away in between.
  - The import's alias pass (Pass B).
  - The deferred-purge sweep.
- A soft-deleted page still has its `blocks` row, so it keeps its claim. The hand-off happens at purge.
- One existing test, `clearing_a_page_drops_an_alias_it_lost_…` in `page_alias_ops_tests.rs`, pinned the old outcome: after the winner dropped the alias, the loser never showed it. That assertion was the defect. The loser now clears its claim while it is still the loser, which still exercises the `engine_held` branch. The winner's drop then hands it nothing.
- Tests:
  - local remove, purge, sync-import removal and remote purge each have their own `_6229` test;
  - registry and projection units;
  - `e2e-tauri/page-alias-contested-sync.e2e.ts`. The app's page holds an alias, a sync peer's page claims it, the app removes it, and the peer's page takes it. Not run locally (no `tauri-driver`); CI's `e2e-tauri-gate` is its first run.
- The `aliasBadge` selector moved from `page-alias-undo.e2e.ts` into `e2e-tauri/helpers.ts`, unchanged, for the new spec to share.

**Accepted (user-visible):**
- Undoing the removal of an alias that has already been handed on is refused with `DuplicatePageAlias`. The frontend shows its generic toast and drops the undo entry; this is the write path's existing rule.
- The hand-off can give an alias to a claimant in the Trash. That alias then resolves to nothing until the page is purged or restored. It matches the oracle, engine-first recovery and the write path.

**Review.** A separate reviewer re-ran eight mutations, each red at the predicted assertion: each of the three hooks removed, the held-key check removed, the claim sort removed, the `WHERE EXISTS` guard removed, the pass run per op, and the `engine_held` clearing removed. Temporary probes confirmed undo, revert and both bulk purges hand the alias on. The reviewer also corrected two doc comments.

**Suites:** full `cargo nextest run --workspace` (both partitions), clippy, the `SQLX_OFFLINE` check, the four `sqlx prepare --check` lanes, `cargo test --doc`, `npm run typecheck`, `npm run typecheck:e2e-tauri`, `prek` (both stages); after the rebase, the alias, oracle and sync tests.

**`engine.block_properties.row`.** For each block that both the engine and SQL hold, `admissible_rows` folds each engine value into the rows it may legitimately have, using the oracle's own type check:
- Rules: `Num` → `value_num`, `Bool` → `value_bool`, `Null` → none, a `Str` that fits → its typed column, anything else → `value_text`.
- The check has its own ULID regex, date round-trip and number parse, transcribed from the projection rather than called. The maintainer required that.
- Promoted keys and `space` are left out. The membership check keeps blocks on one side only.

**The encoded legitimate differences:**
- **A dangling ref:** a ULID under a ref key whose block has no `blocks` row admits no row (the FK guard and the purge cascade).
- **A ULID under a text-like or undeclared key:** it may sit in `value_text` or `value_ref`. The local apply writes the payload's slot, the re-projection writes `value_text`, and a text→url retype leaves the row where it is.
- **A date under a text-like or undeclared key:** it may sit in `value_text` or `value_date`, for the same reasons.

The doc states the trade-off: a projection that wrongly sends such a string to `value_ref` or `value_date` reads as a local write and is not reported.

- Built-ins are in neither. Spaces with no engine are left out.
- A SQL-only row is reported, with an owner naming `repair_property_definitions`. That repair runs on every boot after recovery, so a booted vault cannot keep one.

**Traps.**
- The check found a real defect: a ref to a block projected later in the same import is dropped. Filed as #6232; the owner string cites it.

- **Left for the maintainer:** a pre-§2.1 vault (numbers and booleans stored as strings in the engine) that was never re-projected would report a number or boolean under an undeclared key whose SQL row is in `value_num` or `value_bool`.

**Review.** A separate reviewer re-ran four reds: the projection's misfit drop, the ref-under-text encoding, the definitions upsert, and the dangling-ref encoding. ## Session 3205 — Page mode on touch

#5691's "Touch and IME" item, as far as emulation reaches. The maintainer chose to enable page mode on touch behind Playwright touch emulation and to test on Android after the release; the device-only checks are listed below and the box stays open.

**What changed**
- **Page mode opens on touch.** `usePageMode` no longer requires a desktop pointer. Every gate assertion that encoded the old rule was flipped, not weakened.
- **Block actions in the toolbar.** A finger cannot hover into the grip, so the pinned toolbar gets a *Block actions* button (`BlockMenuButton`, shared with *Edit as Markdown*'s bar) that opens the block menu on the caret's block, in its bulk form when blocks are selected. It opens when the finger lifts, not when it lands: opening on touch put a menu row under the finger, and the lift ran it (Delete, in one trace).
- **The toolbar shows only while the page is edited,** as block mode's does, so the quick-capture button stays reachable on pages and the journal. Block mode's rule for when editing ends moved into `focusStaysInEditor` (`editor-portal.ts`), which both editors now call; block mode's blur is unchanged branch for branch.
- **The caret never types behind the toolbar:** ProseMirror's `scrollThreshold`/`scrollMargin` take the space the pinned bar covers, measured from its top so the keyboard inset counts.
- **The phone switch.** On a phone (`useIsTouch() && useIsMobile()`) the Blocks | Page switch pushed the star and *Page actions* to a second header row, against #5332's one-row header. By the maintainer's choice it is an *Edit as page* / *Edit as blocks* row in the *Page actions* menu (`EditModeItem`), disabled with its reason on a page over the cap. The shortcut and palette listener moved into `useEditModeShortcut`, one per mounted page. Tablets and desktop keep the header switch.
- Smaller: the link bubble fits a phone and shows alone; the journal day's row of actions wraps at 390 px; `PageSourceEditor`'s `onSwitchToPage` is required.

**Decisions and traps**
- A focus guard that greyed *Block actions* until the document had focus was added in review and removed again once the toolbar stopped showing before a tap: under the toolbar's *More* on a 320 px phone, opening *More* takes the focus, so the guard left the row permanently disabled.
- Playwright's tap lifts in the same instant it lands, which hid the ghost tap; `fingerTap` (`e2e/helpers.ts`) lifts one frame later, like a finger.

**Only an Android pass can check:** the soft keyboard against the pinned toolbar and the caret in WebView; IME composition across a long document; hold-to-select with native handles; whether Android's back key hides the keyboard without blurring (the toolbar would then stay, as block mode's does); focus after the block menu sheet closes; speed at the cap.

**Red first:** the touch gate restored (every page-mode-touch test); the toolbar always mounted on touch (the new page and journal tests); every blur ending editing (the block-menu step); *Block actions* opening on press (the reorder test, 3 of 3); the guard restored (the narrow-phone test); `pinnedToolbarCover` returning 0 (the foot test); `useEditModeShortcut` removed from `PageHeader` (three vitest cases); the link bubble's cap or reposition removed; the day row without `flex-wrap` (three `mobile-overflow` tests).

**Suites:** vitest over `src/components`, `src/editor`, `src/hooks`, `src/stores`, `src/lib` and `src/__tests__`; typecheck; lint; the manual-stage hooks; Playwright over every `page-mode*` spec, `app-chrome`, `mobile-overflow`, the journal specs and every `@mobile`-tagged spec.
