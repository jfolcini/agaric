# Session 3888 — What is typed is what is saved: `@` prose, table cells, link titles (#6530)

Three checkboxes of #6530, each its own change. The `/template` checkbox is not touched (it needs a backend command).

**`@` in prose.** The `@` picker keeps `allowSpaces`, but its `allow` gate now closes the popup once the query holds whitespace that no listed tag name continues (`atPicker` in `at-tag-picker.ts`), and its items drop the Create row for a spaced query. The gate reads the last listing, since every tag that starts a longer query also starts the shorter one and the lookup is async. So `meet @ 5pm tomorrow` + Enter splits the block and creates no tag; an existing multi-word tag still completes (unit test, as the mock refuses whitespace tag names). The issue's "`@wor` + Enter still picks `work`" is false on main: the Create row is the default selection for an inexact query (F-26), so it creates `wor`; left as it is, and the spec types `@work`. Page mode gets the change too, through the shared `contentExtensions`.

**Table cells.** `ParagraphTableHeader` / `ParagraphTableCell` (`content: 'paragraph+'`) replace the stock cells in `contentExtensions`, as decided. A typed `> `, `- `, `1. `, `# ` or fence, and the toolbar's quote, list, code and heading toggles, now leave the cell's text alone. A paste in a cell already took HtmlPaste's literal-line path (`inTableOrList`); ProseMirror's default slice fitting (`view.pasteHTML`, or a drop) would split the table around a pasted list, which the app's paste never reaches. Stored content cannot hold anything but paragraph cells (`buildTableCell`), so an existing table loads as before; one saved from several paragraphs reads back as one. `unwrapRule` also bails unless the list is the block's top level, so `- x` typed in a quote no longer sets the block's `listStyle`. Each paragraph of a multi-paragraph cell is escaped as a line start before the join (`two \> quoted`), a pre-existing quirk that loses nothing.

**Link and image titles.** `linkTitle` reads the title the destination carries; the link mark (TipTap's Link already has a `title` attr) and the image node (new `title` attr) keep it, and the serializer writes it back in `"…"` form (`linkTitleText`: `"` escaped, backslashes and unbalanced parens as `escapeUrl` does, since an unbalanced `)` would end the destination and leak the rest as text), grouping link runs by href and title and never writing a titled link as a bare URL. Ordered-list start numbers are not kept: `list-ergonomics.md` item 3, `list-ordinals.ts` and the #4076.2 test pin "numbers are computed, never stored" as the block model's design, so keeping them is a maintainer decision, not a serializer fix. No rows were added to `conformance/block-content.vectors.json`: Rust authors their `rustReads`/`fts`, and the `derivations.rs` golden hashes every vector text. The Rust side has no twin of the serializer's title handling.

Existing tests changed because the issue changes what they assert: the `@` config test (`allow` undefined → a function), N9 E20's title rows and "an image drops its title too" (no title → title kept), and external-link's "a typed title is dropped" (`[docs](https://example.com)` → `[docs](https://example.com "Docs")`).

Checks run: vitest over `src/editor`, the block-content conformance, RichContentRenderer and FormattingToolbar (three page-mode and reveal tests timed out under load 12 and passed alone); `npm run typecheck`; oxlint and oxfmt on the changed files; the three new e2e specs plus `suggestion-keyboard`, `picker-happy-paths`, `table-ops-toolbar`, `slash-table-grid`, `markdown-links-5160` and `list-style-keyboard` (28 passed). Each new test was shown red: the specs on main or under a mutation, the unit tests against the files from `origin/main`.
