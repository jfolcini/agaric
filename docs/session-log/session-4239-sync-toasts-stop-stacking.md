# Session 4239 — background sync stops raising toasts (#6870)

#6870: editing on the Linux AppImage while the Android app synced filled the phone with toasts that covered the page until each was closed by hand. The video and the log zips were not readable from the session, so the cause comes from the code: the sender starts a sync round about 2 s after the typing stops (`LOCAL_EDIT_DEBOUNCE`), and every round that changed blocks raised its own "Synced N changes from device" toast, the one sync toast without a sonner `id`. A `sync:local_text_kept` report raised one never-expiring toast per page title.

A first pass deduped the toast and summed its count. On review with the maintainer the rule became: a toast answers what the user just did, or says what they must know now; ongoing state is the status indicators'. Stated in `notify.ts`.

- **Background sync is silent.** `sync:complete` reloads and moves "last synced", and raises no toast or announcement. "Back online" is gone. A failure is toasted only for a sync the user pressed: `useSyncTrigger` holds the peer in `pressedSyncPeers` (exported by `useSyncEvents`, which the trigger already imports) for the length of its pressed session, and `useSyncEvents` toasts a `sync:error` only for a held peer. The trigger's own failure toasts (a session that ends without a report, a timeout, `listPeerRefs` failing) need `userInitiated` too, which retired the #4305 once-per-streak memory: a press is always answered, a tick never. Settings' *Sync now* and *Sync all* now answer in the Sync & devices status card only: they never enter `pressedSyncPeers`, so their `sync:error` raises no toast.
- **The failure toast names the device** (`peerDisplayName`), not the first 12 characters of its id.
- **A phone's drawer button carries the Sync button's dot** once a device is paired: green, amber, red or grey through the shared `syncDotClass`, inside `SidebarTrigger` (which now renders children), and any state but idle as its description. The maintainer chose this after a red-only failure dot there was built and then dropped.
- **Kept-in-Trash**: one lasting toast that names a single page (cut to 40 characters with the new `clampText`) or counts several, and *Open Trash* (the Trash lists newest first). A report that lands while it is up adds to the count.
- **Mirror warnings**: one toast for the type, naming a file and its first warning (both cut) or counting files.
- **Rename notice**: *Open History*.

sonner's action button closes a toast without calling `onDismiss` or `onAutoClose`, so the kept-in-Trash action resets its count itself.

The e2e flake hunt, on the since-dropped phone spec, found one in a shared helper: on a phone, `openSettingsTab` picks the section from a Radix Select, which scrolls the open list to align the selected item, and under load the option tap lands before it settles (2 of 32 at the iPhone 13's 3× ratio under full CPU load; the list was left open on General). The helper fix goes in the next PR.

The bug reached a user, which normally means an `e2e-tauri/` spec. Both halves need a session the app did not press for: the changes case waits on the app's own 60 s resync or the peer dialling in, and the failure case on a real session failing, so a real-backend spec would assert on timing it does not control. The mock lane drives the same frontend paths with the clock paused, so every toast assertion is deterministic; whether a real-backend spec is still wanted is the maintainer's call.

An independent review found no blocking issue. Folded in: Settings presses answer in the status card (the docs said the device list); the docs no longer promise the device's name and *Retry* on every failed press, which only the trigger's own failure toast has; stale copies in `sync_events.rs` (and its generated `bindings.ts`, edited identically), `sync_event_sinks.rs`, `data-and-events.md` and `sync.md`; a `notify.ts` sentence its own toasts contradicted; a mirror path cut from the end (`clampTextEnd`) so the file name stays; rename titles cut to 40 characters; the six copies of the pressed-only rule cut to one; an `e2e-tauri` assertion Settings' *Sync now* can no longer fail.
