# Session 1552 — A space created on one device reaches its peers

Closes #4775. A two-device user who created a space on one device never saw it on the other: the picker there stayed at Personal / Work, and every page created in the new space landed under Personal after the next boot.

`create_space_inner` creates the space as a parentless page with no `space_id`, so both its `CreateBlock` and its `is_space` property resolve `SpaceUnresolved` in `apply/loro_apply.rs` and stay SQL-only: the space block lives in no Loro doc. The catch-up ships the pages, but the receiver's `spaces` registry only fills from the `is_space` row, which never arrives, so `project_block_full_to_sql` stamps `space_id` NULL and the boot backfill names Personal.

The space block now joins its own space's doc, while its `blocks.space_id` stays NULL because a space is not a page of itself (every space-scoped listing excludes space blocks through that column). `hydrate_space_block_into_own_engine` seeds the block with its `is_space` / `accent_color` rows; `create_space_inner` calls it after the `is_space` op, and `bootstrap_spaces` calls it once for every registered user space so a space created before this fix gets its doc. The seeded Personal / Work blocks are excluded: every device mints them under the same ULID, and two independent tree nodes for one id would duplicate on the first merge. On the receiver, `import_and_project` projects the space's own block first so its `is_space` row registers the space before a sibling page's `space_id` subquery runs, and the projection gained `AND id <> ?` so a re-projection never stamps the space block as a page of itself. `resolve_doc_space` falls back to "is this block a registered space" so a rename, recolour or delete of the space routes through the same doc; without it a deleted space stayed in the engine and the #1257 freshness gate refused every later export of that doc.

Three tests in `spaces/tests.rs`; the first was red before the fix on the peer's `spaces` row count. Each guard was falsified against a copy: removing the rotate, the `id <> ?` exclusion, the resolver fallback, the boot backfill or the create-time hydration each reddens a named test. `just gen-sqlx` moved all four caches.

Left as it is: pages a peer already stamped Personal before this fix stay Personal there; the space now appears on the peer and `move_blocks_to_space` puts them back.
