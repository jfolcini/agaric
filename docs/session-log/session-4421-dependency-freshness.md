# Session 4421 — no external version ages silently: Dependabot plus the stale-pins lane

**Ask.** The maintainer's decision: updates that wait only on the 7-day release-age gate land through Dependabot and the weekly `stale-pins` lane, and that pair should be as exhaustive as possible. Inventory every external version source, close Dependabot's gaps, make a bump that fixes a waived advisory mergeable without hand edits, and give every pin an upstream check.

**Inventory gaps found, and what closed them.**
- The NDK and build-tools versions were hard-coded in `ci.yml`, `release.yml` and `android-launch-smoke.yml`, which AGENTS.md § Supply-chain pinning forbids and nothing checked. They are now the `android-ndk` and `android-build-tools` pins, read through `steps.pins` and by `setup-android.sh`, checked by a new `android-sdk:<pkg>;<major>` upstream. Google ships release candidates on the stable channel (`build-tools;36.1.0-rc1` is `channel-0`), so only all-numeric versions count. `pins.test.mjs` now fails a hard-coded `ndk;` or `build-tools;` version in a workflow.
- `apprun` and `linuxdeploy` were `unchecked`. The new `tauri-bundler:<tool>` upstream reads the name `prepare_tools` fetches in tauri-bundler's `linuxdeploy.rs` at the tag of the Tauri CLI that `package-lock.json` resolves (`@tauri-apps/cli-v<version>`). Any difference is stale; there is no version order between commit hashes.
- `linuxdeploy-plugin-appimage` was `unchecked`. Its `continuous` release is a prerelease, so `releases/latest` returns the newest tagged one; it is a plain `github:` pin now. The `-` upstream is gone, and `pins.test.mjs` fails a pin whose upstream scheme the lane cannot read.
- `.mcp.json` pins `code-review-graph@2.3.8`, and `package.json`'s `packageManager` pins npm. Dependabot does not document updating `packageManager`. Both are file pins now (`FILE_PINS`), checked against PyPI and the npm registry, and `pin-bump` writes both.
- `setup-dev-db.sh` installed sqlx-cli with no version; it takes the pins.txt one.
- Cargo version updates covered only crates a manifest names. `allow: dependency-type: all` (both cargo entries) adds the transitive lock entries. npm supports no `indirect` for version updates (Dependabot's options reference), so a transitive npm package moves only with a direct bump that re-resolves it or a security update.
- Security mirrors (`applies-to: security-updates`) existed for five exact-pin groups. Every coupled stack has one now: `tauri-apps`, `react`, `radix-ui`, `playwright`, `tauri`, `sqlx`, `opentelemetry` and `fuzz` join them, and `specta` after #7042.

**Waivers made unused.** On a failed Dependabot PR the lint job runs `prune-advisory-waivers.mjs list` (cargo deny's `advisory-not-detected` diagnostics, better-npm-audit's `unusedExceptionIds`) and uploads the ids. `advisory-waiver-prune.yml` follows `gradle-verification-commit.yml`: it runs on `workflow_run`, holds the write token, and runs no PR code. It runs the default branch's `prune-advisory-waivers.mjs apply` and `sync-audit-from-deny.mjs` on the branch's two waiver files, then commits with a sign-off. `apply` only deletes. An id that is malformed or not waived fails the run. It accepts `cancelled` as well as `failure`, because `stop-after-lint` can cancel the run. A push with `GITHUB_TOKEN` starts no CI, so the PR comment asks for a reopen, as the Gradle one does.

**Already true.** `report-scheduled-failures` needs `stale-pins` and reads lanes from `needs`, so a red lane files or updates the tracking issue. The lane passes `github.token` to the release lookups.

**Falsified.** The new `pins.test.mjs` and `prune-advisory-waivers.test.mjs` cases were red before the code. With the code in place, each failed again for its predicted assertion under these mutations: the exact comparison off, the `advisory-not-detected` filter forced true, the `.nsprc` key check removed, and a two-line splice. End to end, a probe waiver `RUSTSEC-2020-0001` in `deny.toml` was listed by `list dependabot/cargo/…`, and `apply` returned the file byte-identical to the original.

**Ran:** every `node --test` file `_validate.yml` lists; `node scripts/pins.mjs stale` against the live upstreams (the GitHub-release rows return 403 in this sandbox, which blocks other repositories' API); `setup-android.sh --check`; prek pre-commit and manual stages on the changed files.
