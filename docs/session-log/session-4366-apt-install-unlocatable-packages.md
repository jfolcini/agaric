# Session 4366 — apt-install: "Unable to locate" on a runner whose lists hold no archive

`validate / lint` on #6968 (job 135071285274, run 44380501998) failed in `.github/actions/apt-install` before lint ran. The plan step, which reads only the image's own lists, then the install after an `apt-get update` that returned 0, both said `Unable to locate package` for every universe package (`libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`, `librsvg2-dev`, `mold`) and `libgtk-3-dev has no installation candidate`. The step exited 100, which reads as a diff failure.

**Root cause, as far as the logs settle it.** The runner (image `ubuntu-24.04` 20261116.133.1, AWS us-west-2) had apt resolving names from no Ubuntu archive `main` or `universe` Packages index at all. Only installed packages resolved (`libssl-dev` and `pkg-config` raised no error). Ruled out:
- *A mirror mid-sync.* Every one of those packages has been in the `noble` release pocket since release, and that pocket's indexes are verified against InRelease. A mirror can serve an older consistent snapshot, or a mismatch that fails loudly, but never a `noble/main` without `libgtk-3-dev`.
- *Our own steps.* Before the plan step the job ran only `toolchain` → `prepare-apt`, which writes an apt.conf snippet and chmods the archive dir, then the plan step's `chmod 0777 /var/lib/apt/lists`. None of these removes a list or touches a source.
- *Damaged list files on the image.* Shown locally on apt 2.8.3: a deleted index file is fetched again by `apt-get update`, and an empty one makes apt fail loudly with `LZ4F … Unexpected end of file`. Neither produces a silent "Unable to locate".

That leaves sources on that runner that named no archive component, or index fetches that apt skipped without error. The update's output, which would have told the two apart, was truncated before the install. The same image passed elsewhere at the same minute (`cargo-coverage`, job 135057750713, us-east-1), and no runner-images issue reports it. So this was one bad VM, and a new runner recovers.

**What shipped.** `apt-install` keeps the `apt-get update` output in its own file and prints it with the install's output on failure. When a package will not resolve, it prints the `noble` release pocket's `main` and `universe` Packages indexes, as `apt-get indextargets` reports them. When either component has none, it exits 75 with `AGARIC_APT_INFRA`. A misspelt name, with the indexes present, still exits 100. One trap: `indextargets` lists only indexes that are on disk, so "none" covers both "not in the sources" and "not fetched". Filtering on `Suite: <codename>` matters, because `noble-security` alone would otherwise satisfy a per-component check. No mirror demotion and no second refresh: neither can recover a runner whose sources name no archive, and the frozen release pocket rules out a mirror that lacks the packages.

**Verified.** `node --test scripts/apt-install-action.test.mjs`: 12 pass. Dropping the new infra branch reddens the three new tests. Sending the update output back into the truncated install log reddens the kept-output test. `archive_indexed` was run against real apt 2.8.3 here: rc 0 with the indexes present, and `universe: none`, rc 1, with the `noble` universe index moved away. The extracted step passes shellcheck.
