# Session 3351 — A Logseq graph folder imports with its names and journals (#6033 S8)

Set out to build #6033 S8. A Logseq graph picked as a folder titled every page `graph/pages/X`, left `a___b` and `%3F` in titles, imported journals as pages named `2026_10_21` and left `[[Oct 21st, 2026]]` links pointing at empty pages; `logseq/bak/` copies imported as duplicates.

**What shipped.** `src/lib/logseq-import.ts` detects a graph (`logseq/config.edn`, or `pages/` and `journals/` at the root; `isLogseqGraph` is what #6277 E1 will send as `LogseqOrg`) and names its notes the way Logseq's `extract.cljc` does: `title::` first, then the file stem, decoded by `:file/name-format` (`:triple-lowbar` reads `___` as `/`; a config without it is Logseq's legacy format, where `.` is the separator; no config reads as triple-lowbar), percent-escapes decoded. Journals whose stem parses under `:journal/file-name-format` become the `YYYY-MM-DD` day page, and links written in `:journal/page-title-format` (falling back to `:date-formatter`, as older graphs set it) are rewritten to that day outside code fences. `vault-import.ts` skips the graph's `logseq/` folder and, in a graph, does not ship namespaced notes as `vault_notes`: the backend indexes a shipped note by its last segment, so a `[[b]]` beside `[[a/b]]` would have been rewritten to `a/b`.

**Decisions.** A journal with a `title::` line takes that title, as in Logseq. Graph files outside `pages/` and `journals/` import as folder notes. The unsupported-format warning goes to the app log only.
