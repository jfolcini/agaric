# Session 4228 — A purge re-strips, and leaves unresolved, the blocks that `((ref))` the purged subtree

Fixes #6843. Since #6277 B3 a referrer's `fts_blocks` row carries its `((target))`'s first line, and a purged target has none (`load_block_ref_titles`). No purge re-stripped the referrers, so search kept finding them by the purged block's text until a full rebuild or an edit.

- **Why the existing reindex could not reach them.** `ReindexFtsReferences` finds referrers through `block_links` / `block_links_unresolved`, and every purge cascade deletes the `block_links` rows naming the subtree in the same transaction. So each cascade now calls `cache::unresolve_links_into_purged` first, over its own member set, so a target anywhere in the subtree counts, not only the root. The sources go back to the caller and through the existing `reindex_restored_cohort_fts` pass once the purge commits, as the delete and restore cohorts' do (#4733, #6243). No new queue, table or op type.
- **The same delete lost the dangling token.** The e2e spec's after-all reconciliation found the second half: the cascades deleted those edges without the `block_links_unresolved` row that migration 0112 says a purged target's dangling reference keeps. The same helper records each live outside source's edge there before the delete, and returns the sources from that table.
- **Three cascades, one gap each.** The purge commands (`purge_subtree_tables`: `purge_block`, `purge_blocks_by_ids`, `purge_all_deleted`), the applied `PurgeBlock` (`purge_block_sql_cascade`, through the new `ApplyEffects::purge_fts_referrers`), and the sync sweep that ends a pull (`project_purge_blocks_to_sql`). Edit already re-strips referrers (`ReindexFtsReferences`), and delete and restore owe them nothing, since a soft-deleted target keeps its first line.
- **The mock needed nothing.** `ftsBlockRefTitle` resolves per lookup, so a purged target already strips to `''` there, and `block_links_unresolved` is backend-only; no conformance fixture changes.
- **Cost.** Two indexed reads and one insert per purge, plus a re-strip of each live referrer. Referrers by `[[link]]` are re-stripped too: harmless, since a deleted page's title already strips to `""`.
