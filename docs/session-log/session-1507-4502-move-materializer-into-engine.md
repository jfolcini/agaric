# Session 1507 — #4502: the materializer moves into `agaric-engine`

The second half of the maintainer's (C) for #4502, on top of session 1504's prep. `src-tauri/src/materializer/` is now `src-tauri/agaric-engine/src/materializer/`, re-exported by the app (`pub use agaric_engine::materializer;`) so every `crate::materializer::…` path resolves unchanged. The item census on the diff is in the PR body; the bodies did not change.

What the move had to invert, beyond the five couplings 1504 already removed:

- **The spawner.** `Materializer::spawn_task` fell back to `tauri::async_runtime::handle()` when no runtime was current, and `spawn_sweeper` picked `tauri::async_runtime::spawn` under `cfg(not(test))`. The materializer now holds a `tokio::runtime::Handle`: `with_read_pool_and_lifecycle` takes it as an argument (the app passes Tauri's stored handle, because `setup` runs outside any runtime) and the two test constructors take `Handle::current()`. `spawn_task` still prefers the current runtime and falls back to the stored one, so production binds exactly as before. The one test that pinned `Materializer::new` not panicking outside a runtime is gone: that constructor has nothing to fall back on any more, and the production shape it was standing in for is pinned by the `with_read_pool_and_lifecycle` test beside it, now with an explicit handle.
- **`impl ApplyHost for Materializer`** moved from the app's `sync_host.rs` into `agaric_sync::apply_host`, next to the trait. The `From<Materializer> for Arc<dyn ApplyHost>` impl could not follow: neither `Arc` nor `Materializer` is local to the sync crate, so the four sync constructors that took `impl Into<Arc<dyn ApplyHost>>` now take `Arc<dyn ApplyHost>` and the test call sites wrap with `Arc::new`.
- **Two pins that looked upward** moved to `agaric-sync`, which sees both halves: the snapshot RESET wipe list against `POST_SNAPSHOT_CACHE_REBUILDS`, and `RECV_TIMEOUT * 20` against the attachment temp-file reap window.
- **Tests.** Four files need the app crate (the command layer in `attachments_gc` and `page_link_cache`, `CommandTx` and the boot reprojection in `crash_injection_convergence_tests`, the reconciliation oracle in `apply_reproject_proptest`) and stay app-side as `src/materializer_app_tests/`, reaching the queue handlers and the per-op apply glue through the engine's `test-util` feature. Everything else descended with the module; `agaric_store::test_support::init_pool` gives those tests a migrated pool at a chosen path in place of the app's recovery-running `init_pool`.

The guards followed the files: `metric-provable` and its self-test hook point at the engine's `metrics.rs`, `check-raw-tx` allowlists the handlers at their new path, and the dynamic-SQL baseline re-anchors the same three files with the same counts. `cargo machete` then found `async-trait` and `rustc-hash` unused in the app crate, so they left.

Review caught two things the local gates did not: three `snapshot_bench.rs` sites built a `Materializer` in the bench body, outside `rt.block_on`, where `Materializer::new` now panics (the weekly `engine_bench` smoke would have found it); and nextest's `spy-counter-serial` group anchored on `materializer::handlers::`, so `apply_reproject_proptest` silently left the group when it moved to `materializer_app_tests`. Both fixed in-PR, with the notes: `CACHE_TABLES` private again, the vestigial `allow(dead_code)` gone, three stale comments repointed. The coverage "drop" turned out to be real in a different way: the merged lcov from this PR and from main both list only `src-tauri/src/**`, none of the member crates. `cargo llvm-cov report` selects packages per invocation, and CI's report step ran with no flags, so since #2817 put `--workspace` on the run (not the report) every member crate's lines were missing from the lcov, and each extraction (c13e6d2, #2621, #4631, now this) read as a phantom drop. Verified locally: an instrumented `-p agaric-core` run reports 0 files with a bare `report --lcov` and 13 with `--workspace`. The report step gains `--workspace`; the rust baseline becomes the first workspace-wide figure, read off this PR's run: 93.3% (92845 of 99517 lines), against 88.8% (31352 of 35291) for the app crate alone. CI also needed the twelve `dtolnay/rust-toolchain` pin comments changed from `# master` to `# v1` after upstream tagged the pinned commit, which reds zizmor on every branch.

Behaviour-preserving: no schema, op type, store, queue or message type. The engine gains `rt`/`sync`/`fs`/`macros` on tokio plus `agaric-observability`, `rustc-hash` and `ulid`, all already in the graph. Verification is in the PR body.
