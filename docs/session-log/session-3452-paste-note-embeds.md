# Session 3452 — Obsidian note embeds on paste, Edit as Markdown and MCP writes (#6033 S5b, #6277 D4)

Set out to build #6033 S5b (= #6277 D4). Import read Obsidian's `![[Note]]` as an embed, but a paste, an Edit as Markdown save or an MCP write stored the literal text.

**What shipped.** `rewrite_obsidian_note_embeds` in `agaric-engine/src/import.rs` splits into the whole-block case and a public `link_obsidian_note_embeds`; `normalize_foreign_forms` in `markdown.rs` now runs the embed rewrite before S4's highlight/math pass on every non-code block, and import's separate loop folds into it with its vault-aware `names_note`. Paste, `append_markdown`, `update_block_content` and `append_block` pass `import::embed_names_note`, and so does `resolve_buffer_names` (Edit as Markdown, written rows only). A whole `![[Note]]` becomes `{{embed [[ULID]]}}`, a `#Heading` / `#^id` anchor `{{embed ((ULID))}}`, one beside text `[[ULID]]`; file embeds and code stay text, and an unknown name creates the page. `html-paste.ts` routes a line holding `![[` to the block path.

**Splice trap.** The backend joins a paste's first and last blocks into the text around the cursor after names resolve, so a whole-block form became `Hello {{embed …}}world`, which no parser reads. `PasteSplice::inline_joined_blocks` reads a joined block as inline: an embed as a link, and a one-line display-math block (S4's `\[x\]` or ```` ```math ````) as `$x$`, which the review found broken (`Hello $$\n…\n$$world`). Multi-line display math joined to text is left as it was: joining its lines would swallow everything after a LaTeX `%`.

**Tests.** `page_cmd_tests.rs` (paste reads embeds as import does; an embed pasted into text links the page; display math pasted into text is inline math), `markdown_source_apply_tests.rs`, `mcp/tools_rw/tests.rs`, a routing row in `html-paste.test.ts`, and a new `it` in `e2e-tauri/paste-foreign-syntax.e2e.ts`, which this container cannot run (no `tauri-driver`); CI runs it. Each arm shown red, including the after-text arm. Gates: filtered nextest (1024), clippy, editor and lib vitest, both typechecks, lint and all hooks.
