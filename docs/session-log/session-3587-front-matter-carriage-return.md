# Session 3587 — a carriage return in a page property no longer breaks Edit as Markdown

#6325: a page property holding a `\r` made the page's Edit as Markdown buffer, and MCP `edit_page_markdown`, refuse every save. `yaml_scalar_emit` quoted such a value but wrote the `\r` raw, and the buffer reader read it as a line end, so the front matter split into a line that is not `key: value` (a CRLF value took the block-scalar branch and carried the raw `\r` the same way).

- Fix: `yaml_scalar_emit` sends any value holding a `\r` to the double-quoted branch, and that branch now writes `\\`, `\r` and `\n` as YAML escapes. The importer's `front_matter_scalar` (`agaric-engine/src/import.rs`) decodes those three escapes in a double-quoted inline value and leaves any other backslash as written. Quotes inside the value still stay unescaped, as before.
- Compatibility: a double-quoted value that an older export wrote with a literal `\\`, `\r` or `\n` in it now reads as the escape. Real YAML reads it that way too.
- Mock twin: `readFrontMatter` in `src/lib/tauri-mock/handlers/pages.ts` decodes the same escapes. Its writer `renderFrontMatter` still writes values verbatim and unquoted, a documented approximation this fix does not touch. `source-buffer-document.ts` reads no front-matter values.
- Not changed: the `arb_front_value` filter that leaves `\r` out of the Document proptest's page values. It is an existing test and can go in a follow-up.
- Ran: the new test `a_page_property_with_a_carriage_return_saves_by_its_line_ids`. It is red on origin/main (`line 3: '"' is not a 'key: value' line`). With the old reader alone it is red on the stored value. With the fix it is green. Also ran the new mock vitest, red with the old reader, and the workspace tests matching front/yaml/markdown/import under `cargo test` (nextest could not be installed here), plus clippy, typecheck, and four Playwright specs (page-source-edit, page-source-ulid-tokens, import-export, page-mode-markdown-switch). The real-backend lane needs a native build this container lacks.
