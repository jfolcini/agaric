# Session 3487 — test databases start from a migrated copy

Part of the slow-tests sweep. Per-test durations from a local full-workspace nextest run (4 cores, debug) put 7403 of 7575 tests under 1 s, and those made 71% of the summed test time. A trivial DB test took 0.33 s, about 0.30 s of it running all 130 migrations on a fresh temp file (a probe measured a migrate at 345 ms and a copy of a migrated file at 6 ms). `agaric-store`'s `test_pool_from_template` and the app's `init_pool_from_template` already copied a migrated database, but from a process-local `OnceCell`, and nextest runs every test in its own process, so it helped only a proptest's later cases.

`agaric_store::test_support::seed_from_migrated_template` gives a database file that does not exist yet a copy of a migrated template that lives in the temp dir, named for a hash of the embedded migrations' versions and checksums. Racing processes each build one via `VACUUM INTO` and rename it into place. The store's test `init_pool` and the app's test/bench `init_pool` (behind `test-util`, which now enables the store's) seed before connecting, then run the migrator and the app's recovery steps on the copy as before, so a pending migration still applies and a broken one still fails every test. A path that exists, or whose directory does not, is left alone. Both per-process helpers are deleted and their callers (`reverse_proptest_b1`, `apply_reproject_proptest`, `property_key_proptest`, the `command_integration` fixture) call `test_pool` or `init_pool`; `src-tauri/tests/AGENTS.md` says so.

Measured with the same `cargo nextest run --workspace` on one base, two runs each: before 547.6 s / 552.8 s, after 276.0 s / 269.7 s (an earlier after-run: 276.1 s), all 7583 tests passing. The two new tests were each shown red: making the seed a no-op reddened `seeding_a_new_path_applies_every_migration`, and dropping the exists check reddened `seeding_leaves_an_existing_file_alone`. `cargo clippy --workspace --all-targets -- -D warnings` is clean.

The maintainer chose to keep proptest and scale-test case counts on every PR, so the slowest single tests (`move_sync_proptest`, `conformance_fixtures_match_backend`, the `soft_delete` proptests) are unchanged.
