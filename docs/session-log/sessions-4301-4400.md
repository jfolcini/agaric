## Session 4392 — the week-view undo spec waits for the undo it pressed before pressing again

The per-PR bridge lane (#6996) failed `e2e/journal-undo.spec.ts` › "Ctrl+Z and Ctrl+Y act on the later day's edit, and a press past it stays on that day" on #6999. On a bridge built from `origin/main` it failed about 1 run in 4 to 1 in 10 with or without that PR's change: the `undo_page_group` poll never saw `[TODAY_PAGE]`.

**Cause.** Instrumented, the failing run recorded no `undo_page_group` call. It recorded one `log_frontend`: `[UndoStore] undo already in progress, skipping {"pageId":"…PAGE03"}`. The spec's previous Ctrl+Z was gated only on the backend's `get_block` returning the undone text. That is true once the backend commits, before the frontend's `useUndoStore.undo` has received its answer and released its per-page guard (`undoInProgress`). The next press landed in that gap and was dropped by design. The row's text changes only after the guard is released (`performPageUndo` reloads the page store after `undo` resolves), so a user who waits for the undo to show cannot press into the gap.

**Fix.** That step now waits for the row to show the undone text, as the spec's other steps already do, before installing the recorder and pressing again. No product change: dropping a press while that page's undo is in flight is the store's guard working, and nothing a user sees has happened yet when it drops one.

### What ran

- The test on the bridge, instrumented with a console capture: failed 1 of 4, with the warning above and no `undo_page_group` call.
- With the fix, the test on the bridge with `--repeat-each=30`: 30 pass. The whole spec with `--repeat-each=3`: 9 pass.

## Session 4389 — page mode's Ctrl+Enter task is one undo step on a slow backend

Fixes #6997. In page mode, Ctrl+Enter on a bulleted block cycles it into a task through block mode's `handleToggleTodo`, whose `clearLists` was page mode's `setListStyle(id, 'none')`. That queued the clear behind the running chain step and handed back no refs, so the clear recorded its own undo entry after the task write's and joined it only through the 500 ms `UNDO_GROUP_WINDOW_MS` window. A backend slower than that split the change into two Ctrl+Z.

## Session 4385 — a page reopened while its leave was still writing reads again

`e2e/block-line-break.spec.ts:286` ("a task line, a #name and a key:: value line split off with Enter commit on one leave") failed now and then on the bridge: the split-off row had no tag chip after the page was reopened. Its error context showed the row as `call the plumber #splitcall status:: done`, the text from before the leave committed anything.

**Cause, in the product:** leaving a block commits its task marker, `key:: value` lines and typed tags, and those writes land only after their IPCs answer (`commitTyped`, `src/stores/unmount-flush.ts`). Leaving the page and coming back mounts a new store whose load can read before they land. #6958 patched one case: once the tag rewrite was saved, the live store took it if it still showed the text the rewrite replaced (`adoptLateWrite`). A load that read before the property strip, or before the typed text itself, showed an older text, so nothing matched and the row kept the stale snapshot until something reloaded the page. A first attempt here that also reloaded a store still loading closed one more window and left this one; :286 still failed 2 of 60.

**Fix:** each such leave registers its outcome by page (`trackPageFlush`, `src/stores/page-blocks.ts`). A load whose snapshot may predate one (a flush pending when it started, or one started while it read) reads again once they have all settled. It does not wait for them before reading: a flush may itself load. `adoptLateWrite` is gone.

**Shown red:**
- `e2e/hash-tag-typing.spec.ts`, a new test: every `edit_block` waits until the reopened page has read its blocks, so that read predates the typed text and the rewrite. Its pair, a flush landed before the load began, reads once; a mutant that always re-reads loops until the worker runs out of memory.

## Session 4361 — adopting a folder of notes in place, the backend (#6540 slice B)

#6540 asks whether Agaric can mirror a folder the user already keeps notes in, where it is, instead of refusing any non-empty folder. The maintainer's decisions are on the issue: the folder becomes one space's folder, its files stay where they are, the first pass writes nothing, a preview lists what writes would change and which files are left alone, a page renamed in Agaric renames its file in its own folder (moving it only when the title's namespace changes), a trashed page's file goes to the OS trash, a mass change asks first, and Logseq is import-only. The mirror aims at a folder Obsidian can open.

Pointed at a vault, the mirror as it was would not rewrite the user's files: it lays pages out as `<space>/<title>.md`, so it would write a second copy of every note in a subfolder. Adoption needed a layout with no space folder, each file's path kept, and no write until a page changes.

Built (`src-tauri/src/mirror/adopt.rs`, two commands; no migration, op type or store):

- `preview_mirror_adoption` and `adopt_mirror_folder` take the folder, the space and each imported note's path and page. Each page's state starts from its file's own bytes, its blocks given the page's ids in order, with the page's render at adoption as the splice's base (#6948), so a write keeps a block's own lines until that block changes in Agaric. The preview's diff shows each file as it reads once every block Agaric reads as other text is changed in Agaric.
- The mirror's adopt mode: only that space, paths with no space prefix; each page's pin (its adopted path and title) keeps the file there, renames it in its folder on a rename within the same namespace, and moves it to the path the mirror names otherwise; nothing is written for a page whose buffer is unchanged since adoption, so a page a link to a missing note created gets no file; a note no page took is read only once it changes; a deleted file trashes its page as in a space folder, and many files changed or deleted at once hold reading back, counted across the whole folder; copies of attachments stay off.
- A trashed page's adopted file goes to the OS trash (the `trash` crate, desktop only, as the mirror is), its folders kept. Android has no mirror, so it needs no fallback.
- A Logseq graph (`logseq/config.edn`, or `pages/` and `journals/` at the top, the importer's own test) is refused with "import it instead".
- Turning the mirror off, or choosing another folder, gives an adopted folder back: its marker and states go, so it is never later laid out as a folder of space folders, which would move its files. Choosing it again keeps it adopted.

The two non-blocking notes on #6948: a kept block must now parse at its render's depth, shown red first; and the read-back of a file edited outside Agaric reads every block as Agaric reads it, so the docs sentence about kept lines now says so.

The Settings entry with the preview and its real-backend e2e spec are slice C. The first-run prompt, slice D, waits on the device checklists #6514 and #6515.

## Session 4334 — leaving page mode no longer logs a read overtaken by block mode
