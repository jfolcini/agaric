# Session 4221 — `cargo bench` built two `agaric_lib`s into one file

`Refs #3394`: dispatch run 43744488102 of `scheduled-deep-checks.yml` (on #6840's branch) failed one step in `bench-slo`, "Measure the Loro engine and a pulled vault" (#6828). `cargo bench --bench engine_bench` stopped with 81 E0308/E0277 errors naming two copies of `sqlx-core`, after warning of an `output filename collision` on `libagaric_lib.rlib`.

The cause: `cargo bench` also builds the package's bins, and a bin takes the profile's `panic` while a bench harness always unwinds. `[profile.bench]` inherited `panic = "abort"` from `[profile.release]`, so the unit graph held two `agaric_lib` units, abort for the bins and unwind for the bench, each with its own `sqlx_core` beneath it. The lib is also a `cdylib`, so neither unit's outputs carry a hash: both write `target/release/deps/libagaric_lib.rlib` and share one fingerprint dir. Each invocation then sees whichever unit did not write last as dirty ("the profile configuration changed") and rebuilds it, and a bench that compiles after the abort unit writes links against it. Build order decides the outcome, which is why `interactive_slo` passed and the next step's `engine_bench` did not.

`[profile.bench] panic = "unwind"` leaves one `agaric_lib` unit, so there is nothing to collide. Nothing ships from the bench profile, and the benches already ran unwind, so the measured code is the same. `[[bin]] bench = false, test = false` on both bins was tried first and changes nothing: cargo still builds every bin for a bench.

Ran: the unit graph (`cargo bench --no-run --unit-graph -Z unstable-options`) before and after the change: two `agaric_lib` units (abort and unwind) before, one after, for `--bench engine_bench` and for `--benches`. With LTO off and 16 codegen units: a cold `cargo bench --no-run --bench engine_bench` passed with the three collision warnings; a second run with nothing touched rebuilt the abort lib and the bins; a third rebuilt the unwind one. Touching `benches/engine_bench.rs` and building at `-j1` (the abort lib has more dependents, so it is scheduled before the bench) then failed with the 81 errors CI showed. With the change, the same sequence passed with no collision warning, a repeat run rebuilt nothing, and `interactive_slo` built after it.
