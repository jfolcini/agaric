# Session 3919 — First run names import and pairing; pairing in one step; phone-true copy (#6520)

**What it set out to do.** The first three checkboxes of #6520: the welcome modal offers *Import notes* and *Pair a device*, and the Folder import row names Logseq and Notion; the sidebar Sync button with no paired device reaches pairing in one step and, on a phone, does not leave the drawer over it; phone users are not told to press keys they lack, and the Markdown mirror and Agent access say why they cannot work on a phone instead of offering something that fails. The fourth checkbox (a folded Logseq / Org task keyword kept as a tag) was left: its decision is still open in the issue and it is an importer (Rust) change.

**Decisions and traps.**

- *Pair a device* in the welcome lands on Settings → Sync & devices (the pairing section) through the existing `pendingSettingsTab` handoff; the no-peers CTA instead opens `PairingDialog` itself, without navigating, because a second `PairingDialog` over a mounted Settings → Sync would leave that tab's device list stale (only its own dialog's close reloads it). `PairingDialog` keeps `useSyncStore.peers` in step itself, so the sidebar's no-peers state clears without Settings.
- The drawer is only reachable through `useSidebar()`, and `App` renders `SidebarProvider`, so the no-peers flow became `NoPeersPairing` (`src/components/dialogs/`), rendered inside the provider. `NoPeersDialog`'s prop is now `onPair` and its CTA test id `no-peers-dialog-pair`.
- On a phone the no-peers `ConfirmDialog` is a bottom sheet with role `dialog`, not `alertdialog`: the phone spec addresses it by name.
- The mirror card keys on the backend's own `MirrorStatus.supported` (`cfg!(desktop)`), not on `isMobilePlatform()` as the issue suggested: before this, a real phone hid the card entirely, and the issue's "offered a picker" came from the browser mock, whose `supported` is always `true`. The mock was left alone, so a phone user agent on the mock still shows the picker.
- Agent access on a phone keeps every section; only the description changes, keyed on `isMobilePlatform()`: the socket lives in the app's own storage, which no other app on a phone can reach.
- Welcome touch wording keys on `useShouldShowMobileChrome()`; the quick-capture sheet (opened from the floating button on a phone) does the same. Settings → Editor help stays desktop wording (out of scope in the issue).

**What changed.** `WelcomeModal` (two actions, touch copy, phone order), `NoPeersPairing` (new), `NoPeersDialog`, `App.tsx`, `QuickCaptureDialog`, `MirrorSection`, `AgentAccessTab`, i18n (`welcome.*`, `data.importFolderLabel`, `data.mirrorUnsupported`, `sync.noPeers*`, `quickCapture.descriptionTouch`, `agentAccess.descriptionMobile`, the `//` typo in `welcome.sampleQuickTipsBody3`), docs (`UI-MAP.md`, `FEATURE-MAP.md`, `architecture/frontend.md`, `features/sync.md`, `features/import-export.md`, `features/agent-access.md`) and stale comments naming the old CTA.
