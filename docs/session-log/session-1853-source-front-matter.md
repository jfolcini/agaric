# Session 1853 — page properties as front matter in Edit as Markdown (#5160 S8)

Phase 5, PR 3. S8: front matter or leading `key::` lines typed into the buffer became junk blocks, or vanished.

**What changed.**
- **The buffer opens with the page's properties, aliases and tags** as the export's YAML front matter, written by the export's own `render_frontmatter` and only when the page has any. The keys the export leaves out (`created_at`, `template`, `space`, …) are not written, so leaving them out deletes nothing. A ref value is written as its id, as a block's `key::` line is.
- **The buffer reads it with the import's reader.** `parse_source_outline` reads YAML front matter at the very top (`front_matter_fence` and `scan_frontmatter`, split out of `strip_frontmatter` and `parse_frontmatter`), then Logseq `key:: value` lines above the first bullet (`strip_leading_properties`, now handed a reader), a quoted value decoded as a block's `key::` line is (PR 2's `read_source_property_value`). Each key is known by its line. A line no property reads from (not a `key: value` pair, a mapping, a stray list item, a key the app keeps, a key written twice) and a `---` nothing closes refuse the save as `line N: …`, the `---` being line 1, through PR 2's `at_line`: the parser hands back `(line, why)` and the save prefixes it, as it does for a block. A paste reads neither.
- **A block below the front matter names its line in the buffer.** The front matter's lines are left blank rather than cut before the outline parse, so `ParsedBlock::line` (PR 2) counts them, and a refusal at a block, and the line the editor selects, is the right one. The mock did cut them, so a refusal below front matter named a line too early by the front matter's length; it now blanks them too, and its `refusedAt` takes a line, one helper for block and front matter refusals.
- **The save writes what the front matter changed** from the source the edit started from, in the save's one transaction (`markdown_source_front_matter.rs`): properties through `write_properties`, each value first checked by `PropertyLines::read` so a refused one names its line; aliases, when they differ, through the import's `apply_frontmatter_aliases`; tags added through `resolve_new_names` and `associate_page_tag` (a name no tag of the space has is created) and removed through `remove_tag_in_tx`, split out of `remove_tag_inner`. A merge keeps what the page changed since.
- **The line-ids path (PR 4, #5219) carries the front matter too.** `get_page_buffer` keeps it in `text` as written, each of its lines carrying no id: `anchor_free` reads the source with its front matter read, so no anchor is looked for there. `parse_source_text` reads it as `parse_source_outline` does, blanking its lines, so a block's line still counts them. `read_anchored`, `read_by_line` and `read_own_source` hand back the whole parse, and `FrontMatterEdit::read` takes it on either path, so a by-line save reads, writes and refuses the front matter as an anchored one does, and a page's own text writes nothing. `resolve_value_refs` came out of `apply_page_source_inner` to keep it under 70 lines.
- **Frontend.** The page header remounts when source mode closes, so the property table, aliases and tags show what the save wrote; the kebab still takes focus. The conflict dialog lists the front matter as its own change. The delete-all confirmation says it takes the page's properties, aliases and tags too.
- **Mock.** `get_page_source` writes front matter and `apply_page_source` reads and writes it (text values and plain list items; no Logseq lines or block scalars), on the line-ids path too: `anchorFree` and the by-line read go through `readFrontMatter`'s body. A new fixture, `apply_page_source_front_matter.json`, pins set, add, delete, aliases, tags and three refusals against the backend, then a by-line save of a front matter value and a block, a by-line refusal, and the `get_page_buffer` read-back.
- The corpus snapshots of the Logseq page, the Logseq docs page and the Obsidian note flip: their front matter is page properties in the buffer's reading. `CORPUS_FINDINGS` drops S8 for them.

**Worth knowing:**
- An Agaric export pasted whole into the buffer still reads its front matter as blocks: it sits under the `# Title` line, and a buffer reads front matter only at its top. `corpus_agaric_export` keeps S8 for that.
- Aliases have no op, so page-level undo does not revert an alias change, as with the alias editor.
- An alias or tag holding `"` or `\` does not round-trip: `yaml_flow_item` escapes them and the reader does not unescape. Unedited, it writes nothing; an edit to the alias list rewrites it escaped. The same gap is in Export → Import.
- A multi-line page property is written as the export writes it, a YAML block scalar (`key: |`, lines indented two spaces), which the import's reader reads back as written, blank lines included; PR 2's JSON-quoted form is for a `key::` line, which has no room for one. A YAML double-quoted value is still unquoted without unescaping, the Export → Import gap above, so `"a\nb"` typed into the YAML keeps its backslash.
- An id on a front matter line starts no block, so it is ignored, as PR 4 ignores an id on any line no block starts on.
