# Session 1478 — adopt the ladder

The maintainer asked whether Ponytail (an agent skill that makes the model "think like the laziest senior dev in the room") was worth adopting everywhere. The answer was no to the plugin and yes to its two ideas that this repository did not already state: an ordered decision ladder climbed before writing code, and the posture that laziness applies to the solution and never to reading. This session folded those into `AGENTS.md` § How we work and the two skills that cite it, in the repository's own voice.

The evidence for wanting them came from the same day. The reviewer's first note on #4603 was that one rationale had been written out in full in five places, and the builder sent to apply that note turned a one-line operand fix into a hundred-line state change with a new helper and a surface-gated branch, for an edge the reviewer had called harmless. Both are the failure the ladder names: a rung climbed past, and a paragraph written instead of a pointer.

What changed. `AGENTS.md` gained three bullets under How we work: climb the ladder before writing (not needed, already here, stdlib or platform, installed dependency, one plain line, then the minimum that works); lazy about the solution, never about reading; and lazy, not negligent, which names the floor under the ladder (trust-boundary validation, data-loss handling, security, accessibility, a test shown red). The gold-plating bullet now also refuses a helper for a one-off and an option nobody asked for, and the review bullet says over-building is a finding whose disposition is delete. The batch-issues skill carries the ladder in its bar line, in the builder prompt skeleton as a line every builder reads, in the review section as a dimension the reviewer judges from the diff rather than from the builder's report, in the fix-in-PR disposition, and as the first principle. The review-changes skill reports what the ladder would have skipped after blocking defects.

What was not adopted. The plugin itself, its five commands, its intensity dial and scoreboard, and the per-host rule files for twenty agent platforms: this repository runs one agent with one `AGENTS.md`, and the marginal value of an installed layer over three bullets is not there. Ponytail's marker comment for a deliberate simplification was not taken either; the existing disposition of a deliberate trade as a code comment already covers it. The two rungs were reworded where the repository is more nuanced: "one line" became "one plain line", since a clever one-liner is not lazier than three boring ones, and "installed dependency" sits under the coupled-dependency rules that already exist.

Verification is the pre-commit hooks on the three Markdown files and this log: markdownlint, the citation guards, and the session-log numbering guard. No code changed.
