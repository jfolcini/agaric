# Session 4373 — a stable, current agaric-mcp for the AppImage

#6980: from an AppImage the bridge lived only inside the versioned AppImage file, so a copied agent config named that file and broke on update or move, and scripts found no `agaric-mcp` on the PATH; a hand-copied one went stale silently.

**What shipped.** In the startup step that already rewrites `agaric.desktop`, `appimage_integration::install_bridge` copies `$APPDIR/usr/bin/agaric-mcp` to `<app data dir>/bin/agaric-mcp` (`stable_bridge_path`) when the bytes differ, writing a temp file beside it, setting it 0755 and renaming it over the old one, so a running bridge keeps its open file. It then links `~/.local/bin/agaric-mcp` to the copy when that path is free; its own link is kept and any other file or link is left alone (`foreign_path_bridge`). Every failure is logged and startup continues. `get_mcp_status` names the copy as `bridge_command` with no arguments under an AppImage once it exists (`<AppImage> agaric-mcp` until a copy exists; a failed refresh leaves the previous copy named), and reports the foreign file as `foreign_path_bridge`, which Settings → Agent access shows as a notice whether or not the switch is on. Outside an AppImage nothing runs and the status is unchanged.

**Verified.** New Rust unit tests over temp dirs: copy when absent or different and skip when identical; replace by rename, with an open handle still reading the old bytes; link when free and keep its own link; leave a foreign file and a foreign link alone while reporting them; status naming the stable copy and the foreign file, and nothing outside an AppImage; `bridge_invocation` choosing the copy. Frontend: `AgentAccessTab.test.tsx` shows the notice (axe-clean) and hides it when the field is null; reddened by removing the notice. No CI lane runs a real AppImage, and none was run here, so the startup wiring (`integrate_appimage_if_running` reading `$APPDIR`/`$HOME`) and the env reads in `get_mcp_status` are untested.
