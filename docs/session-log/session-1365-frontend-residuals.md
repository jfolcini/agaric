## Findings

**#4012 — table-merge junk row, resolved as split-not-merge.** Verified independently via `git show`/`git merge-base --is-ancestor`: PR #4067 (merged, ancestor of `HEAD`) genuinely fixed items 2 (`DOMParser` fallback — documented, not restored, matching the issue's own framing) and 3 (render-time ref write — moved to `useLayoutEffect`, with the residual mount-window caveat explicitly commented). jfolcini's issue comment does state a "weak preference" for split-not-merge on item 1, reasoning that a user who pasted two tables probably meant two tables and that merging would repeat the exact data-loss #3274 exists to prevent. The diff's `splitTableRuns`/`ABSORBED_TABLE_SEPARATOR_CELL` (`/^-{3,}$/`, narrower than `isSeparatorRow`'s full GFM `DELIMITER_CELL`) implements that. Probed 7 cases directly against the parser (temporary scratch spec, deleted): `:-` and `-:` embedded rows correctly do NOT split (GFM-legal shapes a real data cell can hold); whitespace-padded `---` correctly DOES split; an escaped `\---` real data row correctly does NOT false-split; an absorbed separator as the run's last line correctly splits into two header-only tables; three tables chained with no blank line correctly split into three; a genuine unescaped `--` data row (the diff's own counterweight test) correctly stays merged. All matched the documented intent — no false positives, no false negatives found within the detector's stated (narrower-than-GFM) scope.

**#4011 — reveal-completion signal replaces frame-count heuristic.** Confirmed the entire old `requestAnimationFrame`/`STALL_LIMIT`/`mountedSignature` mechanism is gone from `PageEditor.tsx` (grep for `requestAnimationFrame`, `STALL_LIMIT`, `mountedSignature` matches only historical comment references) — not left as dead weight beside the new `onRevealSettled` callback. The new `isInZoomPane` structural check and its two BlockTree tests were falsified RED by individually reverting the `mountedVisible`-membership branch and the `isInZoomPane` branch — both tests correctly fail with the specific assertion the removed code was supposed to satisfy, not a spurious error. `PageEditor`'s `pendingRevealBlockIdRef` staleness guard was read and confirmed correct (a report for any id other than the currently-pending one is a no-op; a matching stale test exists and passes). One residual risk, not a defect in this diff: if a target is structurally inside the zoom pane (so `isInZoomPane` never returns false) but never actually mounts due to an unrelated bug in `expandAncestors`/`revealIndex`/`useBlockMountLimit`, the reveal now hangs silently forever instead of eventually surfacing `error.blockNotFound` the way the old timeout-based mechanism would have. This is exactly the tradeoff the issue's "Option 2" explicitly proposes and accepts (decidable absence over a frame-count guess), so it is not treated as a bug to fix here, but it is not called out in any code comment either — worth a one-line note if this file is touched again.

**#4040 — file-scoped `mockReset()` fix, judged correct.** Measured the systemic exposure directly rather than trusting the number in the task brief: 777 test files under `src/` (411 `.test.ts` + 366 `.test.tsx`); **123** combine an `...Once` mock with `vi.clearAllMocks()` in the same file (one additional match was comment-only text, excluded).
