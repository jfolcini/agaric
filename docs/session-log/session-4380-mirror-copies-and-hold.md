# Session 4380 — attachment copies kept per folder, a mass-change hold says so, and the #6887 leftovers

Fixes #6963 and #6964, found while hardening the Markdown mirror (#6887), with the leftovers of #6887's "smaller, if cheap" list that were real bugs.

**#6963. An attachment copy edited in one folder was overwritten after switching folders and back.** The copies record was one file, `mirror/copies.json`, keyed by path below whichever folder was mirrored, while page states were per folder. It now lives beside each folder's states (`mirror/folders/<key>/copies`, no `.json` suffix because `StateDir::load` reads every `.json` there as a page); `Copies::bind` reloads it when the folder changes, and an existing `copies.json` is adopted once by the folder bound first (one rename, so a crash leaves it adopted or still to adopt). A folder that gets no record that way (several folders before the upgrade, a record that will not parse, a snapshot restore) would still have lost an edited copy, so review added the guard too: `Copies::ensure` never writes over a file the record lacks; one holding the attachment's bytes is recorded as the mirror's, any other is recorded as changed and kept, listed like any copy the user edited. `StateDir::forget` spares the record, so a fresh start prunes it instead of dropping it.

**#6964. A mass-change hold said nothing until Settings was reopened.** The mirror task emits `mirror:held` with the held space folders whenever that set changes, compared before and after each pass, so a hold the user ends and the next tick starts again is told again (review found that case). One toast with a fixed id names the spaces, stays until closed, opens Settings › Data, and closes when the hold ends; the card refetches on the event.

**Leftovers of #6887.** The confirm carries path and kind (`MirrorPending`), for turning reading back on and for the hold: a file shown as edited and deleted before the user pressed *Read them in* was trashed on a delete they were never shown. A new file the op cap refuses left an empty page in the Trash, because the create and the save were two transactions; `create_page_from_source_inner` runs both in one `BEGIN IMMEDIATE` over `create_user_page_in_space_in_tx` (main's `create_page_in_space_in_tx`, split out meanwhile by #6755, behind the reserved-`Tag/` check that the command and the mirror now share) and `apply_page_source_in_tx`. The cap now counts the page's create op too, so the largest new file accepted is one op smaller, on purpose: one undo reverts the whole event. The #6966 review notes (`unowned` without its short-circuit, `check_folder` listing the folder once) are in. Skipped: diverged pages re-render every tick (no failure, and the retry is how a settling edit gets its second read).

Open: an adopted folder's hold is keyed `"."`, so the toast and the card would name it so; nothing reaches it until the adoption UI exists. A hold computed before the webview listens is not toasted (the card still shows it).

Trap: the branch was built on #6974's branch, which was force-pushed and then deleted on merge; the rebase onto main had to name the old base by SHA.
