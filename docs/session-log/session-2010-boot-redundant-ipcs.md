# Session 2010 — Boot: drop redundant startup IPCs

Set out to work #5439: the IPCs boot sends before the first journal block, measured against the browser mock by wrapping `__TAURI_INTERNALS__.invoke` from page load (the `installIpcRecorder` helper only sees calls made after boot, so the new spec wraps the assignment the way `perf.spec.ts` does).

What shipped (PR #5511): `SpaceSwitcher` no longer re-fetches `list_spaces` on mount, since every mount sits behind `BootGate` and sync and space edits refresh the store themselves. The backlink panels fetch property keys only when the linked-references filter builder is first touched, or while the unlinked-references panel is expanded; `usePropertyKeysCache` gained an `enabled` flag. The journal panels, Agenda and search breadcrumbs read titles through `resolveTitles` (`src/stores/resolve-titles.ts`), which answers from the preloaded resolve store and sends `batch_resolve` only for misses, one in-flight request per id. The resolve preload lists every page with one `list_all_pages_in_space` call, run alongside the tag call, instead of walking `list_blocks` 100 pages at a time. `e2e/boot-ipc-counts.spec.ts` pins the boot set.

Traps: `resolveTitles` first landed in `src/lib`, which the tier-layering ratchet rejects because it imports a store, so it lives in `src/stores`. `list_blocks` with `blockType: 'page'` also hides `query-view` blocks, but saved views are content blocks, so the single listing returns the same pages. One visible change: a page with a blank title now reads "Untitled" in those breadcrumbs, as chips already did. Left undone: deferring the side panels' queries until the tree loads, which the issue says to measure on the real backend first.

Ran: vitest over every touched area and the full suite in three shards on the preload change, `npm run typecheck`, oxlint, oxfmt, and the new Playwright spec (shown red by disabling resolve-store hits and by restoring the `SpaceSwitcher` refetch).
