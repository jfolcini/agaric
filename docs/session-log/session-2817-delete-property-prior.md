# Session 2817 — `DeleteProperty` records the value it removes, so undoing a delete of a peer-set property works

#5918: on device A, deleting a property device B had set and pressing Ctrl+Z failed with `NotFound`, and since a fatal step aborts the page's undo group, Ctrl+Z on that page stayed stuck. `reverse_delete_property` found the value to restore with `find_prior_property`, which reads only local ops (`is_replicated = 0`), so a value that arrived from a peer, or one whose local set compaction pruned, had nothing to find. Every claim in the issue held, including the batch twin (`fetch_prior_property_batch` / `build_reverse_delete_property`).

The fix is the optional `prior` the #5841 design gives `DeleteProperty`: a `PropertyValueFields` with the five value slots, serde default and omitted when absent, so an op without it serializes and hashes exactly as before (pinned against the old bytes and hash). Every writer records the value it removes, read in its own transaction by `held_property_value` (column-backed keys from their `blocks` column, the rest from `block_properties`), which replaces `property_is_held`: `delete_property_core` (Tauri and MCP), `delete_property_in_tx` (todo stamps, repeat bounds, page-source apply), the `completed_at` repair, and the reverse of a set that created its key. Both reverse kernels read `prior` first and fall back to the op-log lookup only for ops written before this change.

No format bump: no op payload denies unknown fields, remote ingest hashes the raw payload and decodes only `SetProperty`, replicated rows are never applied or reversed, and Loro never carries op payloads.

The two-device tests apply B's real commands to A through `prepare_outgoing_for_pool` and `apply_remote`, then undo on A positionally and as a page group; with `prior` dropped they fail with the issue's own `NotFound`. Two more tests pin the slot each held value is recorded in: every column-backed key and every typed `block_properties` slot, and a page's `space`. A broken `scheduled_date`, `space`, `value_ref` or `value_bool` slot had passed the whole suite, while each left a wrong value or an aborted undo group. The review confirmed the sibling by experiment: `reverse_set_property` uses the same local-only lookup, so overwriting a value a peer set and undoing clears the key instead of restoring the peer's value; it needs a `prior` on `SetProperty` (#6014).

Suites run: nextest over the property, reverse, undo, conformance, op-log and repair tests (1351 passed); clippy and `cargo check --all-targets` clean; vitest over the Tauri mock (1151 passed); `npm run typecheck`; each new test falsified by its own mutation.
