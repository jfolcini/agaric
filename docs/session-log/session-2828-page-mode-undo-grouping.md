# Session 2828 — page mode's page-level undo groups by the block edited

The #5691 review of 2026-10-21 found two page-level undo problems in page mode. This session fixes the first and leaves the second for a backend change.

- **Grouping.** `runSave` in `PageModeEditor.tsx` keyed a save's undo entry by the caret's block, read after the save. A save made as the caret left block A for block B got B's key, so B's next save merged into it and one page-level Ctrl+Z took back both. `SaveResult` now carries the blocks whose edit landed (`edited`). The key is `edit:<id>` only when the save is not structural and wrote one block, which is block mode's key; a save that wrote several blocks, or only task and property commits, gets none. The retry after a refused write now adds to the same `SaveResult` instead of replacing its structural flag and edited blocks, so a split whose write was retried stays a step of its own.
- **Restore, not done.** When page mode's own undo brings back a block a save had deleted, the page's undo stack keeps the delete on top. A first attempt recorded a ref-less entry for the restore and let Ctrl+Z take it back through the positional fallback. The review showed that breaks whenever the in-document undo comes within half a second of the delete's save, which is the common case: the restore saves at once, its entry merges into the delete's within `UNDO_GROUP_WINDOW_MS`, and `undo_page_group` chains back through the delete, so Ctrl+Z reverts both. The commit's own e2e case failed 3 of 3 alone on an idle box. The honest fix is for `restore_block` to return its op refs and the save to record them with `merge: false`, a backend change for its own PR; `docs/features/editor.md` says the restore is not yet a step.

Suites run: vitest over page mode and the stores, the full suite in shards, typecheck, lint, and Playwright `page-mode`, `undo-redo-blocks` and `page-mode-block-menu`. Each grouping test was shown red by putting the old key back, dropping the structural check, dropping the one-block check, or starting the retry from a fresh result.
