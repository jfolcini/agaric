# Session 1950 — review notes from #5384, #5392, #5406 and #5407

The non-blocking reviewer notes from this sweep's merges, in one PR. Each was
checked against the code before anything changed.

- #5384 (Android keyboard inset): deleted the e2e case "sits above the soft
  keyboard with its input visible". The fix is Kotlin-only
  (`MainActivity.kt`) and the case only fakes `visualViewport`, so it cannot
  see the fix. `sheet.test.tsx` (#760) already covers how bottom sheets lift
  above the keyboard and track it.
- #5392 (QR scanner): the stop after an unmount during a pending `start()`
  now has its own `.catch` that logs a warning. Before, a rejection there fell
  into the init `catch`: it logged "Camera initialization failed" and called
  `onError`/`onCameraDenied` on a parent that was already gone. New test,
  checked on a copy three times: putting `await stopIfStarted()` back
  reddens it, and so does making the new catch call `onError` or
  `onCameraDenied`.
- #5392, "a scan then unmount does not stop twice": the premise that it goes
  red without the double-stop guard was wrong. It stayed green with the
  ref-null after a scan removed, with the `getState()` check removed, and with
  both removed. The mock's `stop()` throws before it counts unless the
  scanner is SCANNING, and it leaves that state synchronously. The test also
  unmounts only after the stop settled, so a second stop can never be
  counted. In the real library, a second `stop()` during one in flight throws
  "already under transition" inside `stopIfStarted`'s `.then`, and the
  existing catch logs it. The guard saves at most a warning, so the test was
  deleted rather than reshaping the shared mock to protect a log line.
- #5406: deleted the regex-over-`index.css` test in `useFontSize.test.ts`.
  `font-size-scaling.spec.ts` measures the task checkbox at each setting. The
  checkbox is `size-[1em]` and sits in `.block-tree`, outside `.block-static`
  and `.ProseMirror`, so its scaling comes from the `.block-tree` rule the
  regex read. This was checked by tracing the DOM, not by an e2e run on a
  mutated `index.css`: that would leave the mutation in the tree for a whole
  build, behind the shared lock.
- #5407, empty Pages view: the premise held. The Work space in
  `spaces-management.spec.ts` reaches it after its first Journal visit:
  today's page is its only page, the default chip hides it, and the view said
  "No pages yet." `list_pages_with_metadata` returns only the post-filter
  `total_count`, so the view cannot tell whether the chip hid anything. With
  the default chip on, the heading now reads "No pages outside the journal
  yet.", which is true either way. The removable chip sits above it, and the
  create-first button stays. Checked on a copy both ways: forcing the flag
  off reddens the chip test, and forcing it on reddens the chip-removed
  empty-state tests. The e2e asserts the new copy before removing the chip.
- #5407, Graph local mode: reachable. `navigateToPage` sends a valid date
  title to the Journal, but `openInNewTab` does not. Ctrl/Cmd/middle-click on
  a journal page in the QuickAccessBar recents (which record journal visits)
  or the command palette's new-tab action puts the page on a tab's stack in
  the page editor. Renaming an open page to a date does the same. That page
  is the local-graph seed, and the default journal filter dropped it, so
  local mode fell back to the whole graph. GraphView now adds back, in local
  mode only, a seed that only the journal filter removed. Other journal pages
  stay hidden. Checked on a copy three ways: without adding the seed back,
  without the local-mode gate, and with the journal filter lifted for every
  node.
