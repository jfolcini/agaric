# Session 3613 — HTML paste sends Document text (#6277 E5)

A list pasted from a browser or Google Docs landed as one block per item holding `- a` / `1. a`, a one-item list inside each block, so Enter, Tab, ordinals and `listStyle` filters did not apply to it.

- `htmlBodyToOutline` now gives each list item its text alone, with its marker (`listMarker`) and checkbox state (`todoState`) beside it; `outlineToDocument` writes the blocks with `DocumentLayout` and `pushDocumentLines`, as a copy does, and `html-paste.ts` sends that as `{ kind: 'text' }`. The backend reads it as any pasted text: a `<ul>` item is a bulleted block, an `<ol>` item a numbered one, a checkbox item a task, and a heading owns nothing (`nestUnderHeadings` is gone).
- `PasteInput::Blocks`, `PastedBlock` and `import::pasted_block` are gone, with the mock's `pastedBlock`. `into_blocks` lost its `after_text` flag. Bindings regenerated.
- `createMarkdownTurndown` (`src/lib/markdown-turndown.ts`) is the one option and rule set `createInlineTurndown` and `createHtmlTurndown` build on: ATX headings, `-` bullets, fenced code, the `---` rule and the `~~strike~~` rule of #6276. Paste gains `---` for a rule Turndown renders.
- After text, an HTML task item now joins as `[ ] task`, as a plain-text task line does, not `- [ ] task`.
- Red first: `e2e/html-paste-1439.spec.ts` pastes a `<ul>` and an `<ol>`, reopens the page and reads each block's content and `listStyle` (red on main: `"- html bullet one"`, `listStyle: null`); `src/editor/__tests__/html-to-document.test.ts` writes lists, nesting, tasks, a heading then a paragraph, an `<hr>`, strikethrough, an escaped list-like paragraph and a table and code block, and reads each back with `parsePastedText` (red on main: no `outlineToDocument`, and `* * *` for a rule). Falsified: the list marker put back in the text reddens four vitest cases and the e2e test; the shared strikethrough rule removed reddens the paste case and `enex-import.test.ts`.
- Existing tests that pinned the removed `blocks` input, `nestUnderHeadings` or `- a` content are left failing in this commit, for the maintainer to approve their update: `html-to-blocks.test.ts`, `html-paste.test.ts`, `clipboard-source.test.ts`, `use-block-tree-event-listeners.test.ts` (type error), `conformance.test.ts` and `conformance_fixtures_match_backend` (the `paste_blocks.json` steps still send `kind: blocks`), `page_cmd_tests.rs` and the `tests_pasted_text_5140` module in `import.rs` (no longer compile).
