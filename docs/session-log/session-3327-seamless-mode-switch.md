# Session 3327 — a switch to page mode draws no blank frame

The maintainer saw the page redraw when switching between block mode and page mode. Measured on the mock (Chromium, a 36-block page of headings, tasks, nested rows and long paragraphs, scrolled partway, a block focused): Blocks → Page unmounted block mode's tree at once, and page mode showed a skeleton while it read the page and built its editor, about 80 ms warm and 400 ms on the session's first switch (lazy chunk). The scroll fell to 0 under the short skeleton, then jumped back. Page → Blocks drew no empty frame. Layout-shift entries summed to 0 both ways: CLS ignores content that unmounts and remounts, so it cannot see this redraw.

`ModeSwap` (`src/editor/page-mode/ModeSwap.tsx`) now holds block mode's tree on screen, inert and absolutely placed over page mode, with its frame as tall as the tree. Page mode opens transparent beneath it and calls `onShown` (through a context `PageModeSlot` reads) once its setup has placed the caret and scroll, or once opening fails. Only then is the tree removed. The incoming view is `opacity-0`, not `visibility: hidden`: a hidden editor cannot take the caret. `restoreScrollPlace` takes the mode whose rows to measure, because both modes' rows are in the DOM during the hold.

Dropped, and why:
- **A cross-fade.** It kept block mode's roving editor alive after page mode took the caret. That editor's unmount runs `cleanupOrphanedPopups`, which sweeps every `.suggestion-popup` in the document, so it deleted page mode's open `[[`, `/` and Turn into pickers (five picker specs went red under load).
- **Anchoring on the edited block, or on the text line.** Either keeps the line under the eye still, but `page-mode.spec.ts` and `journal-page-mode.spec.ts` pin the row box of the block at the top. Block mode's rows are 32 px for a 24 px page-mode line, and the text sits 47 px further right in page mode. Until the two modes' row geometry matches (the page-mode gutter work, #6296), the edited line still moves 10 px to page mode and up to 19 px back. The way back also settles a few frames late, after the tree's reload measures its rows, as it did before.

`PageEditor` wraps block mode's tree and its Add block button in their own `flex flex-col gap-3`. Inside `ModeSwap`'s `<div>` they had stopped being items of the page's flex column and lost its 12 px gap, a regression on every block-mode page that the reviewer measured (0 px). The spec pins the gap.

`e2e/page-mode-switch-seamless.spec.ts` samples every animation frame of both switches. It asserts no frame without the page drawn, a layout-shift sum of 0, nothing below the editor moving while the tree is held, and the top block's row still on the way to page mode. On `main` it fails with 78 frames that have nothing drawn. Each piece was mutated separately and went red: no hold, no frame min-height, page mode measuring the held tree's rows (162 px). Two `PageModeEditor.test.tsx` cases pin `onShown`: called once the editor holds the page, and called when opening fails.
