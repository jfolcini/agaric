# Session 1543 — Page titles are unique within a space

Third PR of the batch run alongside a second agent in another container (1541 and 1542 carry the two before it). It closes #4723 in the scope the issue itself recommends: a `[[name]]` create resolves to the page that already carries that title, a rename onto an existing title is refused, and the comparison is the exact-content one `resolve_or_create_journal_page` already uses.

Nothing enforced the rule the issue reports the `[[` picker and the journal both assume. `create_page_in_space_inner` now looks the title up among the live pages of the target space inside the same transaction and, on a hit, commits without dispatching and returns the existing id: no row, no op. `edit_block_inner` calls the same lookup for page blocks with the page itself excluded and rejects with a new `ValidationCode::DuplicatePageTitle`; a page with no space (the pre-#3081 backfill leftovers #4715 counts) has no namespace to clash in and is skipped. `PageHeader` reads that code and names the clash instead of the generic rename failure. The mock mirrors both sides through one `findLivePageByTitle`, scoping by its `space` ref property.

Review cut the builder's widening of the conformance harness: two fixtures that needed an `expect_error` path and a command-routed create bolted onto a runner whose doc excludes command-level validation, with two branches no fixture reached. The rule is pinned without it (three create and four rename tests on the backend, four mock cases in `page-title-unique.test.ts`, the pin table on the wire string), so the `create_page_in_space` waiver stays and cites the mock test. Review also caught one real glitch, `usePageCreation` prepending a resolved id onto a list that already held it (duplicate row, duplicate key), fixed with a membership check and a hook test, and one clippy error the builder had reported as clean. Left for the maintainer: the three "New page" entry points create `Untitled`, so with a lingering `Untitled` page in the space they now open it rather than create a second; auto-suffixing instead is a design call.

Verified: the rename rejection, the mock resolve and the hook guard each shown red against a copy, restored `cmp`-identical.
