# Session 3592 — re-import merges into the page of that name (#6277 G5)

Built #6277 G5 (decision 7): a re-imported file merges into the live page its title keys to (#6278 I1's `name_key`), through the Edit as Markdown save, instead of making a twin.

- `create_import_page` (`markdown_import.rs`) asks `import_target` (`markdown_import_merge.rs`): an empty page is adopted as before; a page with blocks is merged by rendering its buffer, keeping only the file's anchors that name that page's blocks, pairing the rest with G4's `pair_unanchored_lines` and saving through `apply_page_source_inner`, so the op cap still refuses an oversize merge. The merge's ops come back in `ImportResult.merged` and the runner pushes them with `notifyUndoNewAction`, one undo step per page as a save is.
- Scope trap: the save reads only the Document dialect and none of the import's per-file rewrites (Logseq/Org outline reading, folder-relative `.md` links and folder note names, `attachment:<id>`, `^name` anchors). Merging those files would rewrite blocks the file did not change, so only a plain Markdown file sent without a vault merges (a single-file pick, an ENEX or JEX note with no attachments). The rest, and a title an earlier file of the same run created or merged (`import_markdown`'s new `run_pages`), import as `Title (n)` (`first_free_title`) with a warning. The maintainer took this as a first step (recorded on #6277): the PR says `Refs #6277` and G5 stays open for folder, attachment and Logseq/Org files.
- The dialog: `list_import_merges(space_id, filenames)` reads the same match; mock handler, `WIRE` entry and `conformance/fixtures/query_import_merges.json`. `useImportRunner` asks it before the loop and waits on `ImportMergeDialog`; declining or a failed read imports nothing.
- Existing tests whose expectation decision 7 changes: the same-title test now expects the merge; three export/import round-trip tests trash the source page before re-importing so they still test a fresh import.
- Review: the result panel's "all failed" now also needs no page updated; new tests pin an anchored line updating the block its anchor names and a note with attachments not merging; `pagesTitled` moved into `e2e-tauri/helpers.ts`; only a file that can merge carries the run's pages, so a large vault no longer sends a growing id list with every file. Two plain-file inputs are not byte-idempotent on re-import (an Obsidian `^name` marker, a Logseq `{:width}` image size); `docs/features/import-export.md` says so.
