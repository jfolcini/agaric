# Session 4414 — a reopened page waits for a plain edit or split its leave flushed

**Ask.** Root-cause two one-off failures: `agenda-projected-repeat.e2e.ts` on #6979's run 44392416112, where the page reopened after typing showed its first block blank, and `spaces-happy-paths.spec.ts`'s "a journal block added after a space switch" on the bridge in deep-checks run 44309605975, where the Work journal's typed line was gone on coming back.

**Cause.** Leaving a block flushes it. #6953 registered the flush by page so a reopened page's load reads again once it lands, but only for the marker, property and tag branches. The plain edit and the split went unregistered, the plain edit also when the blur's early persist of a blank block had already written it (a new page's first block), and the reopened page is a fresh store that cannot see the old store's holds, so its `load_page_subtree`, on a reader connection, could read before the flush's write committed and kept the old text. Both specs typed plain text, then left at once: through the sidebar, or by a space switch.

**Change.** `runUnmountFlush` registers the split and plain-edit outcomes with `trackPageFlush` too, the deduped early persist included.

**Shown.** On the bridge, delaying `edit_block` in the page by 1.5 s (or only the work line's by 2.5 s) failed the spaces test 3 of 3 on main, on the line CI failed on, and passed it 3 of 3 with the change. On #6979's shape (a new page, its first block typed, left through the sidebar, reopened), the same 1.5 s delay, with or without `create_block` delayed 1 s too, failed 6 of 6 on main and passed 6 of 6 with the change; without the delay it passed on main. `editor-lifecycle.spec.ts` gains two tests that answer the leave's `edit_block` only once the reopened page has read its block: an edit of a seeded block, and a new page's first block. On the bridge both are red without the change, only the second with the early persist left unregistered, and both green ×5 with it. Three cases in `page-blocks.page-flush.test.tsx`, a plain edit, a split and a deduped early persist flushed on leaving, each red with its branch's registration removed (the store kept the old text) and green with it.

**Ran:** `npx vitest run src/stores src/editor src/hooks src/components/editor`, `npm run typecheck`, and the `@editor|@journal|@pages` specs on the mock and the bridge. The failures there were the container-only diagram and scrollbar specs (no `chrome-headless-shell`), plus one run each of `page-mode-touch` and `page-mode-slash` under the load of a concurrent run. Each then passed ×20 and ×10 on its own, on main and with the change.
