# Session 3737 — Read aloud on Android (#5745 S7)

Built the last code slice of #5745: *Read aloud* on Android, through the OS `TextToSpeech`.

- **Shape.** `SpeechPlugin.kt` is a Tauri mobile plugin in the app module (`status`, `speak`, `stop`), loaded by `commands::speech::plugin()` with `register_android_plugin`. Rust puts the engine behind a `SpeechEngine` trait; `get_speech_status` stays a `cfg` constant (`Native` on Android), and the new `get_speech_engine_available`, `speak_text` and `stop_speaking` drive the engine. `read-aloud.ts` picks the webview or the backend route from the status.
- **Safe without a device.** The maintainer decided no manual device checks will run, so a plugin that fails to load, a `TextToSpeech` that fails `onInit` or has no installed voice, and one that never answers within `AVAILABILITY_TIMEOUT` all leave *Read aloud* hidden. The plugin's constructor does no work, the engine starts on the first availability check (the first time a menu offers *Read aloud*), and every Kotlin command catches and rejects instead of throwing. R8 keeps `@TauriPlugin` classes, their `@Command` methods and the runtime annotations; the manifest gains the `TTS_SERVICE` `<queries>` entry API 30+ needs to see an engine.
- **Traps.** Tauri runs plugin commands on a Rust thread while `onInit` lands on the main thread, so the plugin posts everything to the main looper and never blocks. A stop sent for one reading could reach the engine after the next reading's first `speak` and cut it, so a native utterance waits for the last `stop_speaking`; a replaced reading sends no stop, because `QUEUE_FLUSH` cuts it.
- **Not built here.** Kotlin cannot compile in this container: CI's `android-build` is the first compile, and `android-launch-smoke.yml` on the branch stands in for the launch check. The PR merges only once both are green.
- **#5364 recording audit**, added at the maintainer's decision in place of its device passes: `NSMicrophoneUsageDescription` is in `src-tauri/Info.plist` and `RECORD_AUDIO` with `MODIFY_AUDIO_SETTINGS` in the Android manifest. Permission denied, a missing microphone, no `getUserMedia`, a recorder or encoder that stops or fails mid-recording, and a failed save each have a message and a `VoiceNoteDialog` / `voice-recorder` test that keeps what was recorded. Nothing in the app ends a recording on `visibilitychange`, so backgrounding keeps it; only the OS killing the process loses it. No gap needed a fix.
- **Ran.** The speech Rust tests (`cargo nextest run --workspace` filtered to them), `npx vitest run` over the read-aloud and conformance tests, `npm run typecheck`, `cargo clippy --workspace --all-targets -- -D warnings`, the `read-aloud` Playwright spec, and the `android_re` guard. Each new test was shown red against a break in the code it covers.
