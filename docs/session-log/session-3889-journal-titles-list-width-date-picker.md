# Session 3889 — Journal titles, list width and the date picker's own date (#6544)

Three of #6544's checkboxes: journal pages shown in the journal date format outside the journal, list views capped and centred, and the date picker showing and clearing the date it edits. Labelled routes, query columns, task-state drawing and the synced-preference items were left to other branches.

**Journal titles.** `displayPageTitle(title)` sits beside `formatJournalTitle` in `src/lib/date-utils.ts` and reads the preference with `readPreference(PREFERENCES.journalDateFormat)`; `isDateFormattedPage` decides what a journal page is, as `TabBar` already did. It is applied where a title is drawn, never where one is matched, stored or navigated to: `PageLink`'s default text (which covers the Agenda, Due/Done panel and query-table source links and the reference/search group links), `BlockListItem`'s plain breadcrumb, `groupByPage`'s label, `CollapsibleGroupList`'s header (Search groups, linked and unlinked references), the `[[` picker's `makePagePickerItem`, `QueryResultList` and `GroupedResults` (Advanced Query), the palette's search groups, and History's preview of a `create_block` that made a page (`getPayloadDisplayContent`, the only change to History's row). Trap: a formatted date can hold `/` (`dd/MM/yyyy`), so the namespace split must run on the stored title first; the picker and the group header split, then format only an unsplit title. Navigation must keep the ISO title too: `navigateToPage` routes an ISO title to the journal day, and a formatted one would open a page-editor tab. The inline link chip in block text keeps the stored title: it is the note's own text, its editing NodeView renders the same, and a chip that changed with a display setting would make the editor and the static block disagree. The Pages view's rows were not in the issue's list and still show the stored title.

**List width.** A `--container-list: 60rem` token beside `--container-reading` gives `max-w-list`; each list view's root (Pages, Search, Tags, Templates, Advanced Query, Trash, History) takes `mx-auto w-full max-w-list`, and the three views with an outlet header wrap it the same way, as `AgendaView` does with the reading width. A phone is narrower than the cap, so nothing changes there.

**Date picker.** `useBlockDatePicker` now returns `datePickerValue` (the chip's or focused block's due or scheduled date while open, read through a `useStore` selector that is O(1) while closed) and `clearPickerDate`, which writes `null` through the same `setDueDate` / `setScheduledDate` path a pick uses (the two handlers became `writeDueDate` / `writeScheduledDate` taking a nullable date). `BlockDatePicker` takes `mode`, `value` and `onClear`: the title names the date edited, the value is `selected` and `defaultMonth`, `required` keeps a re-click on the selected day from deselecting it, and a "Clear date" button shows only with a value. Page mode queues the clear behind its saves through `actions.current.pick`, as it does a pick.
