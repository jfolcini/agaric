# Session 3931 — In-page replace: one or all matches in the open page (#6608)

The find bar gains a replace row (its toggle, or `Ctrl+H`): **Replace** takes the current match and moves past the text it put in, **Replace all** takes every match in the page, rows not mounted included.

**Block mode.** A replace rewrites the block's stored Markdown, not the rendered text. `replace.ts` parses the block, replaces in its text nodes, and serialises it again, so no rendered-text offset is mapped back into the Markdown (the issue's experiment). The find text walker in `block-text.ts` now also records which piece of the document each stretch came from (`findTextPieces`). A match is replaced only when every piece it covers is a text node. A chip label, a line break, the gap between two paragraphs, or an empty piece such as inline math makes the match skipped, and the row counts skipped matches. Overlapping matches keep the first. Capture groups expand natively: a sticky copy of the pattern runs at the match's offset and goes through `String.replace`.

The save goes through the page store's `edit`, after `flushActiveDraft()`. Once the save succeeds, `takeReloadedText` hands the new text to a roving editor still on the block; handing it over first left a refused replacement in the editor, committed by the next keystroke (review). For Replace all to be one undo entry per page, `edit` takes an `undoGroup` key. The first edit of a run on a page is `merge: false` with the key, and later edits join it by key, whatever the time between them. No new op, IPC, or store was needed. A failed `edit` stops the run.

**Page mode.** Find walks page mode's editor as DOM, so a replace there is one ProseMirror transaction (`replace-in-editor.ts`): page mode saves it as typing, and one undo in the editor takes it back. A DOM match maps to the document with `posAtDOM`. Text in a chip, a widget, or outside the editor gets no span of positions, so that length check alone rejects it. Three other checks (`nodesBetween`, `textBetween`, `view.dom.contains`) were tried and deleted, because removing any one of them left every test green. After a page-mode replace the DOM walk has to be re-run by hand (`replaceRun`), because no store change starts it.

**Traps.** `Cmd+H` hides the app on macOS. The binding is `Ctrl + H`, and the matcher accepts the physical Control key. This is unverified on a Mac. A Replace all of more than `MAX_COALESCED_UNDO_REFS` ops splits into one undo entry per chunk. Disabling Replace all once no match is left dropped focus to the page, where Escape does nothing, so focus goes back to the replace field.

**Measured** (scratch vitest, not committed): `replaceAllInContent` over 500 realistic blocks took about 70 to 160 ms in jsdom on the shared 4-core box. A run's time is the sequential `edit_block` IPCs, not the rewrite.
