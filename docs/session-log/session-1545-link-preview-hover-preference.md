# Session 1545 — A preference to stop the hover fetch of link previews

Fifth PR of the batch run alongside a second agent in another container (1541 to 1544 carry the others). It closes #3684 in the scope the maintainer narrowed on 2026-09-02: one boolean preference, default on, checked before the hover fetch, with the threat model updated in the same PR; the three-state vocabulary, the per-host allowlist and any gating of the paste and popover prefetches were dropped there.

Hovering or focusing an external link made the Rust process fetch the link's host to fill the preview tooltip, the only outbound request whose far end is chosen by note content, and nothing gated it while the favicon it names was already behind the image policy. The new `link-preview-hover-fetch` preference mirrors the closest existing boolean field for field. The hook reads it once inside the debounced hover callback, after the cache read and only on a miss, so a cached preview still shows and the callback's identity is untouched; off, the hook resets to its initial state and no tooltip opens, because reusing the fetch-failure state would show a bare URL on every uncached link forever. Settings gets one toggle row after the external-image control. The threat model's B5 row moves to Mitigated with one residual clause for the default-on first hover, the attack-surface bullet says which paths stay ungated, and the open question is gone.

Review kept the one-shot read: the callback runs fresh on every hover, Settings is a view that replaces the page rather than a modal over it, and the image policy needs a subscription only because a mounted image must re-render on a settings write. One real finding was the help text, which promised Agaric would never contact a link's host with the setting off while a pasted or inserted URL is still fetched once by design; it now says so. Three narrating comments were cut and the assurance-case sentence gained the default.

Verified: the gate test red with the gate deleted and again with the gate moved above the cache read, the persistence tests red with the hook swapped for local state, the default test red with the default flipped, all against copies restored `cmp`-identical.
