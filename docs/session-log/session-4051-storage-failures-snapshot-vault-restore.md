# Session 4051 — Storage failures say their cause, a daily snapshot, and a whole-vault restore (#6554)

The last three boxes of #6554 in one PR, one commit each; the boot-failure box landed in #6681 while this was being gated, so `docs/TROUBLESHOOTING.md` § 8 now names both kinds of backup.

**Storage failures.** `AppError` gains `StorageFull`, `StorageReadOnly` and `StorageCorrupt`, built only by `AppError::storage_failure` from the error `sanitize_internal_error` would have collapsed: SQLite's primary result code (`extended & 0xFF`, so `SQLITE_READONLY_DBMOVED` counts) or the I/O error kind. The frontend hook is `unwrap` in `app-error.ts`, which every `commands.*` result but `readAttachment` passes through: it dispatches `STORAGE_FAILURE_EVENT` on `window`, and `StorageFailureBanner` under the shell header keeps one row per kind until dismissed. A window event and component state, not a store or a toast: the banner has to be a real component for its test to mean anything (sonner is mocked in vitest), and `app-error.ts` importing `notify` would be an import cycle. Each action still shows its own failure toast; suppressing those would have meant touching every call site. An MCP client still gets the generic internal error. Known limit: a write through the `query_only` read pool is also `SQLITE_READONLY` and would read as a read-only folder; a folder remounted read-only under a running app reports `SQLITE_IOERR` and stays `internal`.

**Daily snapshot.** `db/daily_snapshot.rs`, run as a maintenance job (hourly tick, at most one attempt per local day per launch): `notes.db.daily-<date>` beside the database through the existing `snapshot_vault` (`VACUUM INTO` on a read-only connection), written to `.partial`, flushed, renamed, newest seven kept. Only names ending in a date are ever pruned, so pre-migration backups are out of reach. The independent review found two things the first version got wrong: `File::open(..).sync_all()` fails on Windows (a flush needs a write handle), and an hourly retry would refill a nearly full disk every hour, since `VACUUM INTO` writes most of a copy before it fails. The retry is now once a day or at the next launch. A free-space check before copying would be better and needs a new dependency (std has none, `unsafe` is denied); left for the maintainer on #6554. Opening the folder is a Rust command through `tauri_plugin_opener::open_path`, so no capability changes; it has no test because it starts the file manager.

**Whole-vault restore.** Built by a subagent in its own worktree, then reviewed and amended here. *Export all spaces* now always writes each folder's `.agaric/space.json`, with the space's `name` (folder names are sanitised and disambiguated, so they cannot be matched back). `vaultRestoreSpaces` detects the pick and re-roots each folder's files, so the existing single-space pipeline runs unchanged per space; `useImportRunner.run` takes `groups` for one aggregate result. Added after review: a top-level `.DS_Store` no longer turns a vault pick back into the old everything-into-one-space import; two exported spaces of one name restore into two spaces; the page-merge question names its space. Accepted: declining a merge question cancels the whole restore but leaves the spaces already created, empty.

Traps: #6666 added two fields to `MaintenanceJob` while this branch was green on the older base, so the rebased branch did not compile, and the `just gen-sqlx` that hit the compile error deleted a hundred cache entries on its way out (`git checkout -- src-tauri/.sqlx`, as `codegen-and-sql.md` says). `cargo test` (not nextest) can fail the first test that builds the migrated template in a fresh temp dir, two threads racing on one staged file; nextest's process per test does not. A test for "a failed copy leaves no partial file" passed without the cleanup until the vault was made larger than SQLite's page cache: a small `VACUUM INTO` that fails leaves no file at all. `confirmDialog` in `e2e-tauri/helpers.ts` waited for no `alertdialog` at all, which never happens when the next question opens as the first closes; it now waits for the confirmed dialog's text to go. The `ipc-error-path-coverage` hook wants `<Component>.test.tsx`, so the restore tests live in `ImportSection.test.tsx`.

The real-backend lane runs in a cloud container after `apt-get install webkit2gtk-driver openbox xdotool` and `cargo binstall tauri-driver`; `e2e-tauri/vault-restore.e2e.ts` and `e2e-tauri/daily-snapshot.e2e.ts` each ran green there and red against a build with the code broken.
