# Session 3633 — a labelled link in a table cell is a backlink

Inside a GFM table cell the editor stores a labelled link as `[[ULID\|label]]` (`escapeCellPipes` writes it, `buildTableRows` reads it), and #6418 made the import read that form. Every reader of stored tokens still wanted a bare `|`, so a link in a table cell, typed or imported, got no `block_links` row: the target's linked references listed the block under Unlinked References instead, export wrote the raw ULID and search indexed the id.

- One optional character, `\|` → `\\?\|`, in `ULID_LINK_RE` / `PAGE_LINK_RE` (`agaric_store::cache`) covers the link reindex and backfill, `pages_cache` link targets, cross-space validation, the FTS ref maps and the export's reference collection. The `regex` crate does not backtrack and nothing new allocates; `count_backlinks_batch` itself is SQL.
- The FTS strip masks shown spans before it reads tokens, so `mask_shown_spans` now writes a cell's escaped pipe as `|`; the regex alone left search reading the id. The mock's `maskShownSpans` follows.
- `humanise_tag_and_page_refs` (export, Edit as Markdown, paste's shown text) writes `[[Title\|label]]` when the stored separator was escaped. Outside a table that stored form is one the editor cannot write (an MCP write or a paste can): export writes it escaped and a re-import stores it bare, and Edit as Markdown shows its ULID, since the name would not read back.
- Edit as Markdown's Preview (`withNameIds`) rewrote the buffer's new `[[Title\|label]]` to a bare-pipe `[[ID|label]]`, which split the cell in three; it keeps the pipes escaped in a table row, as `escape_pipes_as` does.
- Data-loss trap: `empty_blocks::referenced_candidate_ids` kept an empty block alive only when something linked it as `[[id]]` or `[[id|`, so the boot sweep would have soft-deleted an empty block linked only from a table cell. It now also checks `[[id\|`; `just gen-sqlx` swapped one query file in the root, engine and sync caches.
- Existing data: `backfill_block_links` is marker-gated and every vault had run `.v1`, so a cell link saved before this fix would have had no row until its block was next saved. The marker is now `.v2`, which runs the pass once more at the next boot.
- `readLinkLabels` unescapes a label's `\|` only when the separator was escaped: a cell escapes every pipe, a label elsewhere is written as typed.
- Also: the reconciliation oracle's literal; `audit_cross_space_refs` drops its local regex copies for the shared ones (and diagnostics its `regex` dependency); the mock's link scan; the frontend readers (`useBacklinkResolution`, `use-block-link-resolve`, `useDuePanelData`, `UnlinkedReferences`, `ulid-tokens`), which have no shared home for this token, so each regex changed in place; and the token grammar in `docs/architecture/editor-and-content.md`.
- Conformance: a new backend-authored `table_cell_link.json` (page link, backlinks, backlink count, search); `paste_blocks.json` gains one `page_links` row for the table-cell step #6418 added, the fix's own effect, approved by the coordinator.
- Left open: no WebdriverIO spec, which needs a native build and could not be shown red here; `table_cell_link.json` pins the backend side. `fts_blocks` rows of cell links indexed before this fix keep their old text until the block is next indexed, as no pass re-strips the index. `WIKILINK_NAME_RE` (`vault-import.ts`) reads an Obsidian file's `[[Note\|alias]]` as the note `Note\`, so a folder import does not ship that note with the link; it reads a source file, not a stored token.
- Ran: each new test shown red against the code it covers (the cache regexes, the FTS mask, the humaniser, the SQL guard, the marker, every frontend reader, the mock's scan and mask, the e2e spec); `SQLX_OFFLINE=true cargo check --workspace --all-targets` and `just gen-sqlx` (no diff); nextest over the workspace in two partitions; clippy; fmt; the whole vitest suite; typecheck; lint; prek in both stages; Playwright over the new spec and the `@pages`, `@search` and `@markdown` specs.
