# Session 3933 — sync reads no longer dirty engines, and a session that imported saves them (#6525)

The last three checkboxes of #6525; the first merged in #6591 (session 3881).

- **Reads stop marking.** `LoroEngineRegistry::with_engine(space, device, f)` runs `f` under the engine lock and marks the space dirty only if `f` moved the op log (`checkpoint_frontiers` before and after). Every engine access in `sync_protocol/loro_sync.rs` goes through it, the import included, so an import that adds nothing leaves the space clean. It is not a read-only accessor: `export_snapshot` can stamp the format version, an op the peer then holds, and an import writes; comparing frontiers marks both. The mark comes after the write, which the conditional clear tolerates (a pass that captured an older stamp keeps the space dirty). `for_space` still marks on every call. `guard_acquisitions` now reads a test-only counter bumped by every acquisition, since `mark_seq` no longer moves on an unmarked one. `registry::tests::with_engine_marks_only_what_moved_the_op_log_6525` pins the rule directly: a read, a second export and a no-op import leave the space clean; the first export's stamp, an import, and an import that then fails mark it.
- **Session-end save.** `SpacePlacementSink` runs `save_engines_and_advance_cursor` first in the task it spawns for a `Complete` that changed something, and in a task of its own for an `Error`. On mobile, `WindowEvent::Suspended` spawns `spawn_save_on_suspend` (cfg `mobile` or `test`; the mobile arm itself was not compiled here). The pass drains the background queue, so `the_signal_waits_for_the_placement_rebuilds_4785` now counts six processed tasks, not five.
- **Hydration re-run not done.** The issue's step 4 (re-run the #5670 hydration under a `v2` marker) is not built: re-hydrating from SQL seeds a block a peer authored, whose import a kill lost, as a local twin node, so after the next pull the block has two live engine nodes, the twins reach the peer, and deleting one leaves the space's export refused by the freshness gate. Options left for the maintainer: hydrate only blocks with a local (`is_replicated = 0`) `create_block` op, or leave it.
- **Divergence pinned.** `loro::tests::boot_replay_onto_a_snapshot_*_6525`: with the persisted blob taken before the peer's edit, the replayed edit gives laptop `abcXXY`, phone `abcXYY`, equal version vectors; with it taken after (the session-end save) both read `abcXY`. The app-level twin `a_replayed_edit_converges_with_the_peer_it_was_shipped_to_6525` is red without the save (`abcXYY` / `abcXYX`). Residual: a local edit made between an import's commit and the end of the session-end pass, shipped and then killed, still diverges.
- **Deleted.** `reload_registry_from_db` and its two tests (no production caller since #4699), and the `installed` exclusion in `advance_clean_space_watermarks` with `save_all_engines_does_not_advance_watermark_of_unrehydrated_space_3309`: every `loro_doc_state` row has an engine, since boot installs one per row or stops and a pass writes rows only for engines. `LoroEngineRegistry::clear` is now called only by tests; left for a follow-up because six tests use it to bump the generation.
- **Already on main.** The `loro/revert.rs` and "daemon is dormant" premises were corrected in #6572; the copy in `docs/architecture/rollback-safe-engine-apply.md` was fixed here.
- **Checks.** Red first for every new test by mutating the code it covers (with_engine always marking; the export read marking; each save call removed). Engine and sync packages and the app package ran green in nextest partitions; clippy and `SQLX_OFFLINE=true cargo check --workspace --all-targets` clean. `a_session_that_fails_after_an_import_still_saves_it_6525` timed out once on its first try right after an OOM-killed build and passed on retry; 13 isolated runs and 390 stress runs did not reproduce it.
