# Session 3334 — gutter controls centre on the first line at every font size

The maintainer saw page mode's grip, chevron and task checkbox sit a couple of pixels above the text line of a task whose text is a page link (with the cursor in it, so the `[[…]]` source shows), in the desktop app. No issue; claimed by paths.

**Cause.** Every control slot was a fixed `min-h-8` (2rem), standing for "one text line box": `py-1` plus a 24 px line. The line is `1.5 ×` the font-size setting (`--agaric-font-size`), so the slot matched only at Medium (16 px). Measured in Chromium (control centre minus the first line's centre; page mode and block mode alike): Large −1.5 px, Small +1.5 px, Medium 0; an h2 −2 px and an h1 −3.5 px at every size. The link row itself is no different from plain text: its source shows in the same line box.

**Fix.** `--block-first-line` (`index.css`) is the first line box: `1.5 × --agaric-font-size`, or a leading heading's line box from the heading's own Tailwind size tokens (with the `sm` step `HEADING_CLASSES` and `.ProseMirror hN` take). `min-h-block-line` (slot = that line plus the `py-1`) replaces `min-h-8` on block mode's control lane, the shared checkbox wrapper (`BlockInlineControls`), page mode's chevron gutter and its grip. The grip sits outside its block, so `PageGrip.place` copies the block's `--block-first-line` onto it. After: 0 px everywhere measured (h1 0.5 px), desktop and the phone page-mode layout.

**Left as found.** Block mode's row with the cursor in it centres its controls on the block's box, whose toolbar sits above the text (≈ −27 px); and block mode on a phone draws the checkbox in a 44 px `touch-target` box, +6 px below the line (page mode's phone layout uses `touch-hit-area` instead). Neither changed here.

**Tests.** `e2e/gutter-alignment.spec.ts` (Small/Medium/Large × both modes) is red on `origin/main` at every size (grip −1.5/+1.5/−2 px) and green with the fix; dropping the grip's copy of the block's line box reds the heading at Small and Medium. `e2e-tauri/gutter-alignment.e2e.ts` measures the same in WebKitGTK at Medium and Large; it was not run here (no tauri-driver in the cloud container), CI's `e2e-tauri-gate` runs it. Also ran the page-mode gutter, touch, look and main specs, gutter clicks and font-size scaling (76 green), vitest over `src/editor/page-mode` and `src/components/editor`, `npm run typecheck`, `typecheck:e2e-tauri`.
