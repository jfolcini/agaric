# Session 3337 — a plain child is a `+` item; tabs follow tab stops

#6277 D1 (decision 2). The Document writer (Rust `DocumentLayout::place`, TS `DocumentLayout.place`) wrote a plain child of a plain parent as an indented bare line. CommonMark tools read two or more plain levels as an indented code block, so Obsidian, GitHub and GitLab showed deep outlines from a block copy or an Edit as Markdown text as `<pre>`. A plain block with any parent is now a `+ ` item. Its column doesn't move, because a bare parent's child column equals the marker's width. The reader already read this form. The "parent was marked" flag had no other use and went.

`indent_columns` / `indentColumns` and both `dedent` twins now advance a tab to the next multiple of four, so Obsidian's tab-indented `1. a\n\t1. b` nests. A tab that straddles the content column is stripped whole, which is a deliberate departure from CommonMark's two leftover spaces. The writer writes only spaces, so the round trip is unaffected.

Reds: a markdown-it vitest of a three-level plain chain (`<pre>` before the fix); the reader row `1. a\n\t1. b` in `typed_rows` and the vectors (depth 0 before). `arb_document_forest` gains a plain-under-plain lead shape. Tests pinning the old form changed by decision 2, each citing it. One of them is the clipboard string in `e2e/page-mode-block-menu.spec.ts`. The conformance fixtures and `document-lines.vectors.json` were re-authored by the backend. `markdown-it` moved from a transitive dependency to devDependencies for the new vitest (knip).
