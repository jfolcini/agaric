# Session 1542 — Page History now shows a delete of a peer-added attachment

Second PR of the afternoon batch run alongside a second agent in another container (1541 carries the first). #4627 asked for a design call: whether `undo_page_op_inner` should start offering a replicated-added attachment's delete as an undo target, or only the read-side listing should change. The maintainer delegated the choice, and the answer comes from AGENTS.md rather than from the query family: `delete_attachment` is non-reversible by design, so undo can never offer it whoever added the attachment, and the listing is the only thing that was wrong. The three undo queries in `commands/history.rs` keep their gate untouched.

`list_page_history` resolves an attachment op's page with two probes, and probe 2 was gated on `src_add.is_replicated = 0`. On the device that received the add by sync, that gate was false, the live `attachments` row was already hard-deleted by the same transaction that appended the op, and the delete vanished from the page sheet. The builder found the gate in both branches of the query, the space-scoped one the History view calls and the per-page recursive one, and removed it from each; leaving one would have fixed the sheet while the view stayed blind. A replicated `add_attachment` carries `block_id` from its payload exactly as a local one does (`ingest_remote_op_in_tx` populates it for both ingest profiles), so nothing is misattributed. The query text changed inside `query_as!`, so `just gen-sqlx` moved all four `.sqlx` caches together: two entries retired, two added, byte-identical across the four directories.

The doc blocks around the query had grown a family history: the five-predicate byte-identity with the undo sites, a "second shape of the same caveat", and a paragraph saying #4627 was still open. They now state two reasons once: replicated adds carry `block_id`, and the undo family keeps the filter because the op is non-reversible. The reviewer cut a forward reference to a caveat this change removed, a filler clause, and a bare millisecond literal in the new test that had to sort between two other ops without saying so; it now parses the file's own ISO idiom.

Verified: one test with a replicated add, a local delete and no live row, asserting the exact seq vector from both branches; re-adding the gate to both branches reddens the first assertion, re-adding it to the space-scoped branch alone reddens the second, restored `cmp`-identical. Full `cargo nextest run --workspace`: 6279 passed, 10 skipped. `SQLX_OFFLINE=true cargo check --workspace --all-targets` clean. No frontend file changed.

Shipped: fix for #4627.
