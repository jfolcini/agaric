**Frontend batch.** `useDraftAutosave`'s timer skips `save_draft` when the live text equals the committed baseline (`storedMarkdown`, which `markCommitted` rebases). Two traps. The skip holds only when this hook has no row outstanding for the block (`draftRowIdsRef`, cleared on delete and flush): a row it wrote that holds text since typed back to the committed text, such as an uncommitted `key:: value` line deleted again, would be replayed at boot, because the commit predates the row and so does not supersede it (`draft_anchor_seq`); a row older than a later commit is superseded and dropped by recovery, so that case is not the hazard. And the tick clears the block's discard marker before the skip, not after: a committed edit that follows a blur is still a real edit, and with the marker left set an unmount without blur (`Ctrl+Shift+F`) dropped the tail typed after it. Three e2e tests waited for a debounced `save_draft` of plain text: `draft-autosave.spec.ts` now types a `key:: value` line (still drafted), its #2786 split test writes its pre-existing row through the `pagehide` flush, and `reload-keeps-editor.spec.ts` "a reload under a dirty editor" types a `key:: value` line for its positive control. `src/lib/tauri-mock.ts` is deleted; `@/lib/tauri-mock` resolves to the directory's `index.ts`, so the importers are unchanged, and the stale "Seed data (tauri-mock.ts)" spec headers point at `seed.ts`. The `PagesTreeSection` item was not built: the fetch decides whether the collapsed header exists at all (the section hides with no descendants), so not fetching while collapsed would never show a first child created on the open page (#5253, pinned in `PagesTreeSection.test.tsx`).
