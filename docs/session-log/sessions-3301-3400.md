## Session 3400 — Tables keep their column alignment (#6277 C2)

Set out to build #6277 C2: a GFM table whose delimiter row is `|:--|--:|:-:|` lost its alignment on its first edit, because the parser dropped the colons and `serializeTable` wrote `---` for every column; the mirrored file would lose it the same way.

**What shipped.** `buildTableRows` reads each column's alignment from the delimiter row onto that column's cells as `attrs.align` (TipTap 3.32's table cells already carry that attribute and draw it as `text-align`, so the schema did not change); an unaligned cell gets no attrs, so existing tables parse as before. `tableDelimiterCell` writes `:---`, `---:`, `:---:` or `---`, and `serializeTable` takes each column's alignment from the first cell in it that has one, since "add row above" inserts unaligned cells over the header. The static view aligns cells, and HTML paste carries a cell's `text-align` or `align` into the delimiter row.

**Review fix.** Agaric writes two tables back to back in one block; a width change split them only when the second delimiter was a bare `---`, so an aligned second table merged into the first on the next parse. `ABSORBED_TABLE_SEPARATOR_CELL` now takes `:?-{3,}:?`.

**Changed existing tests.** Nine `markdown-parse.test.ts` cases parsed aligned delimiter rows and expected cells without alignment, the behaviour this changes: the row-boundary ones compare through `unaligned()`, and the aligned short-dash one expects its alignment.

**For #6304.** The new `block-content.vectors.json` row carries no `rustReads` field; whichever of this PR and #6304 lands second regenerates the file under `CONFORMANCE_UPDATE=1`.

**Tests.** Parse, serialize (including a row added above the header), round-trip seeds and an aligned `arbTable`, the renderer, HTML paste, a page-mode save, a fidelity test for adjacent tables, and `e2e/table-alignment-6277.spec.ts` (an aligned table seeded through IPC, one typo fixed, re-queried after navigating away and back). ## Session 3396 — Markdown mirror, outbound

#5363 slice 1 (#6277 H1): with a folder chosen in Settings → Data, Agaric writes each live page to `<folder>/<space>/<title>.md` and keeps the files current. Desktop only, off by default. Built on the 2026-11-04 plan answers: a marker file names the mirroring device, a 2-second tick plus full passes, per-page state files plus one `mirror.folder` setting, and polling. The amendments of the same day apply too: the state holds `{ text, line_ids }` shadows, and anchors go only on addressed blocks.

Decisions worth knowing later:

- **Dirty set.** It comes from this device's own `op_log` rows by `seq`, from the pages named by `SyncEvent::Complete`, and from the pages linking to a renamed page. There is no hook in `commit_and_dispatch`. A peer's ops are never read from `op_log`, because their timestamps can be older than any watermark. A sync that changed nothing (`changed_blocks == Some(0)`) does not rescan.
- **Rename order.** A rename removes the old file, and only if it still equals the newest shadow, before writing the new one. Otherwise a case-only rename on a case-insensitive file system would delete the file it had just written.
- **Never overwrite.** A file that matches neither the newest shadow nor the render is never overwritten or removed. It is listed as diverged and retried every tick, so restoring it clears the listing.
- **Pausing.** A missing folder or marker, or a marker naming another device, pauses the mirror. The marker is checked again before each page write, so a drive unplugged mid-pass leaves nothing on the system disk.
- **Anchors.** `file_anchors` in `markdown.rs` writes `^ID` only on a block in A3's `addressed_blocks` (#6306), which the file read (`PageRead::File`) loads. Any other block is written the way a block copy writes it: it gets an anchor only when its text would otherwise read back as something else, such as an open fence or a trailing `^word`. Without its anchors, the file reads back as the buffer does, under the same line ids.
- **Paths** are ported from `export-graph.ts` into `mirror/paths.rs`. Collisions are folded with `normalize_tag_name`, and colliding names are disambiguated in id order. The ZIP keeps its TS copy; the maintainer was asked about this (Q-paths).

The widened Document proptest found that a page property holding `\r` makes Edit as Markdown refuse every save of that page. Filed as #6325; the generator leaves `\r` out of front-matter values until it is fixed.

## Session 3389 — Footnotes, numbered by first appearance (#6033 S11)

Set out to build #6033 S11 to the design the maintainer approved on the issue (2026-11-04), with their one change: references are renumbered 1, 2, 3 by the order their labels first appear on the page, while the stored text keeps the label.

**What shipped (TS only).** `[^label]` is an inline `footnoteRef` atom (parser `scanFootnoteRef`, serializer, `RichContentRenderer`, `revealed-markers`), in `contentExtensions` so block mode and page mode both have it. A block starting `[^label]: ` defines it. `src/editor/footnotes.ts` builds one label → number map per page from the page store's blocks in tree order, cached on the blocks array (a WeakMap), so the numbering is built once and recomputed only when the page's blocks change; `useRichContent` subscribes only for blocks whose text holds `[^`, which a Profiler test pins. A defined reference is a followable superscript (click, Enter or Space focuses its definition through `onNavigate`); an undefined one is muted with a tooltip. Typing `[^label]` converts on the closing `]` through a `handleTextInput` plugin so one Ctrl+Z brings the typed text back. The serializer writes `[^1]\(x)` when a `(` follows a reference so it cannot become a link, and a literal `\[^1\]` stays text.

**Decisions.** Only references count as appearances; a definition nothing refers to shows its label. Block mode's editor numbers from saved text, so a reference just typed shows its label until the block is left; page mode renumbers live. A label may not hold `[` or `\` (review: a later `]` could pair with it and turn the reference into a link at 20 000 property runs).

**Review fixes.** The static reference took no 44 px tap area and the browser's outline; it now has `touch-hit-area` and `focus-ring-visible`. Added pins for the selector guard, Space, spoken text (a reference reads as nothing), page mode's live numbering and click, and the phone tap area.

**Not done here.** The design's Rust checks (an import PCT holding references and an FTS test that `[^1]: text` is found by `text`) were left out of this TS-only slice; reading `strip_for_fts_with_maps`, the words pass through unchanged. Copying a reference and pasting it inside the editor degrades it to its label text, as page-link chips already do.

**Tests.** Parse, serialize and numbering units, node-view and typing tests in both modes, an axe-checked renderer test, round-trip seeds and a footnote property (20 000 runs after the label fix), and `e2e/footnotes-6033.spec.ts` (typed reference and definition, click focuses the definition, re-queried after navigating away and back; page mode; phone tap). Gates: full vitest (24527 passed), typecheck, lint, all and manual-stage hooks, and 1064 Playwright `@editor|@markdown|@journal` tests (`e2e-related` selects the whole lane because of `index.css`).
