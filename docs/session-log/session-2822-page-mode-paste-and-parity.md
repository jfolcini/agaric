# Session 2822 — page mode reads pasted Markdown into blocks, gains the emoji and query hint, and a parity test catches the next drift

The #5691 review of 2026-10-21 found page mode had drifted from block mode's extensions with nothing to notice it: `HtmlPaste`, `EmojiPicker` and `QueryHint` were in the roving editor only.

- **Markdown text paste.** Pasting `- a\n- b` gave blocks reading `\- a` and `\- b`. Block mode parses pasted text with the backend's import grammar through `PASTE_BLOCKS`, which writes through the block store, and no command runs that parse without writing. Page mode now parses it with the editor's own `markdown-serializer` `parse` in a `clipboardTextParser` (`page-paste.ts`): each list item becomes a block at its nesting depth under the block pasted into, headings, fences and paragraphs become blocks, marks and links stay marks, and a task item keeps `[ ] ` as text for page mode's commit-on-leave. A single line (but a bullet or task line, which block mode reads too), text with no Markdown in it, a Shift paste and a paste inside a code block, list or table keep ProseMirror's own paste. Two differences from block mode remain and are documented: a pasted heading does not adopt the blocks after it as children, and a numbered item comes in without an ordered list style.
- **Emoji picker and query hint.** Both now run in page mode. The emoji picker's key joined page mode's open-picker keys, or Enter split the block instead of picking; the query hint runs above `PageKeys`, or Tab indented the block instead of accepting the hint.
- **Parity test.** `page-mode-surface-parity.test.tsx` fails when an extension is in one editor's list and not the other's, when a `BLOCK_MENU_ACTION_IDS` row is not offered by page mode's block menu, or when a slash id, the `/turn`, `/priority` and other typed-query options included, is not in exactly one of page mode's at-once, after-the-save or not-offered sets, unless a waiver in the test gives the reason.

Suites run: `npx vitest run src/editor/page-mode`, typecheck, lint, the changed files' prek hooks, and `e2e/page-mode.spec.ts` with the new `e2e/page-mode-input.spec.ts`. Every new test was shown red by breaking the code it covers, the four e2e cases on one mutated build.
