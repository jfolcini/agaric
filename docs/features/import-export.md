# Import & Export

## Import (Settings → Data)

Settings → Data offers one row per source, each with its own button: Markdown, text or Org files, a folder, an **Obsidian vault**, **Evernote** (`.enex`), **Joplin** (`.jex`), and a bibliography file.

- **Markdown** files. Import is per file: each `.md`, `.markdown`, `.mdx` or `.txt` file is read as Markdown and becomes a page titled by its file name without the extension, and each `.org` file goes through the Org import below. Picking a folder imports every such file inside it independently — each file's relative path builds a namespaced page title, so the folder structure is reflected in page titles. A folder's files that its notes embed or link are their attachments; any other file that is not an image or a PDF is skipped and counted in one warning, and hidden files and folders (`.obsidian/`, `.DS_Store`) are skipped without one.
- **What import resolves:**
  - `[[Page Name]]` wiki-links — resolved within the active space to the page with that title (ignoring case, Unicode form and spaces at its ends), else the page with that alias; otherwise the page is created. Where several pages hold the name, the oldest (the lowest id) is linked. A title holding a `#` (`[[C# Notes]]`) is that page when it exists; otherwise the text before the `#` is the page and the rest a heading or block anchor. An anchor into another page is a reference to the block it names there, the page's first heading with that text in document order (as Obsidian resolves a repeated heading) or its block with that `^id` (an export writes a reference to another page's block as `[[Page#^id]]`); any other anchor links the page, with a warning. A folder import links an anchor into another note of the folder once every note is imported, whichever order they import in: `#^id` names the block whose text ended in that `^id`, and the marker leaves the block's text. On a folder import, a relative link to another note of the folder, a file of any note extension (`.md`, `.markdown`, `.mdx`, `.txt`, `.org`) whose destination is bare, `<…>` or titled (`[text](Other%20note.md)`, `[text](<Other note.txt>)`, `[text](Other.md "Title")`), is a `[[link]]` to the page that file imports as, labelled `text` when that differs from the title; a `#Heading` or `#^id` fragment (`[text](Other.md#Heading)`) is the link's anchor, read as that of `[[Other#Heading|text]]`, and a `%23` is a `#` of the file's name. A Markdown note links an `.org` file by its file name, not its `#+TITLE`. A file whose title names an empty page (the placeholder an earlier file's link created; the oldest where several share the title) fills that page instead of creating a twin; a page of that title with content is updated in place, as below. `[[Page|label]]` and Logseq's `[label]([[Page]])` keep the label (`[[ULID|label]]`); a label equal to the page's title is dropped, and one on a link that becomes a block reference is dropped with a warning, since a block reference carries no label. A title holding a `|` wins the same way a `#` does: the link text is tried whole, then up to each `|` from the last, and the first that names a page is the link, the rest its label (`[[A | B|see]]` is the page `A | B` labelled `see`); only when none names a page does the first `|` start the label.
  - **Obsidian embeds** (`![[…]]`, [Obsidian's embed syntax](https://obsidian.md/help/embeds)). A block that is one `![[Note]]` becomes an embed block of that page (`{{embed [[…]]}}`), `![[Note#Heading]]` one of the heading's block and `![[Note#^id]]` one of the block carrying that `^id`; an anchor that names no block embeds the page. An embed inside other text is a link, or a block reference where its anchor names a block, since an embed is a whole block. A target with a file extension (`![[img.png|100]]`, audio, a PDF) is a file: an attachment, as below. A paste, every MCP content write and *Edit as Markdown* (each block the save changes or creates) read a note embed the same way, with a name that has no page created as a `[[Name]]` creates it; a file embed stays text there, since none of them brings the file.
  - `#tag` and `#[[Multi Word Tag]]` hashtags — resolved to an existing tag of the same name, case-insensitively, or created, then rewritten to canonical tag references. A tag created from a name holding whitespace takes it as `-` (`#[[Multi Word Tag]]` becomes `Multi-Word-Tag`) and the import warns, since a new tag name holds no whitespace; a front-matter `tags:` item is read the same way. A `#name` is a tag only when the name holds a non-digit and the `#` starts the text or follows whitespace, as in Obsidian: `#42`, `(#tag)`, `"#tag`, `it&#39;s`, `[#A]`, `x.com/#install`, `\#tag` and a `#` inside a URL or link destination stay text. Typing `#` in the editor follows the same rule (see [tags-and-links.md](tags-and-links.md#tags)).
  - Properties — inline `key:: value` lines and YAML front-matter `key: value` scalars, the repeat rule (`repeat`, `repeat-until`, `repeat-count`) included. A `key:: value` value in double quotes reads as a JSON string, as the export writes one holding a line break. Logseq's page properties, the `key:: value` lines before the first block, are front matter too: `alias::` is the page's aliases and `tags::` its tags (created when missing), each a comma-separated list whose items may be written `[[Page]]` or `#tag`; any other key, `title::` included, is a page property and the page keeps its file-name title except in a Logseq graph folder (below). In YAML front matter `aliases:` and `tags:` are the page's aliases and tags, and so are Obsidian's older singular `alias:` and `tag:`, in either list form. So a page property literally named `alias` or `tag` comes back from an export as aliases or tags, and a page holding real aliases as well as such a property writes both keys into its Edit as Markdown buffer, which then refuses the save as a key written twice; a Logseq `alias::` line is already read the same way. A key names the built-in key or definition it matches ignoring case and `-`/`_` (`Priority::`, `due-date::`), with no aliases. A value its definition refuses (a select value outside the options, a date that is not `YYYY-MM-DD`, a bad repeat rule) stays in its block as the text it was written as, a refused ref value with its `[[` escaped so it links nothing, and one warning names it; the rest of the file imports. Front matter has no block to keep such a value in, so it is skipped with the warning. A ref-typed value, in front matter or on a `key::` line, is a block id of the space or a page named by `[[Title]]` or a plain title in the space (by title, ignoring case, then by alias; the oldest page where several match).
  - **Attachments**, but only on a *folder* import: the files a note embeds (`![[scan.pdf]]`, `![](pic.png)`) or links (`[paper](paper.pdf)`) are matched against the picked folder's other files and brought in, with the references rewritten: an embedded image to an image of the attachment, an Obsidian size (`![[pic.png|300]]`, `|300x200`) kept as its alt's (`![|300](…)`), a link or any other embedded file to a link to it. A reference is read from the note's own folder first (`../` climbs, never above the picked folder), then from the picked folder, then by filename alone; a filename several files share takes the first and warns. An image or link destination is read as CommonMark reads one: `<my image.png>` or `my%20image.png` for a name with a space, balanced parentheses (`a(1).png`) and an optional title; a bare `my image.png` is not an image. A link to a note (`.md`, `.markdown`, `.mdx`, `.txt`, `.org`), a URL, a mail address or a `#heading` is not an attachment, and a link naming no file of the folder stays as written, without a warning. A single-file `.md` pick has no siblings to match against, so its attachment references stay as-is.
- **How text becomes blocks.** A Markdown file reads the way a paste and the *Edit as Markdown* buffer read text, by lines ([editor.md](editor.md#edit-as-markdown)): a heading owns nothing, `- x` and `* x` are bulleted blocks, `1. x` and `1) x` numbered ones, `+ x` a plain one and `- [ ] x` a task, a bare `TODO` is text, and a trailing `^id` is the block's anchor. Only YAML front matter is read: TOML (`+++`) and JSON front matter stay a text block, and a setext heading is not one (a line over `===` is one paragraph; over `---`, a paragraph and a thematic break). A page of a Logseq graph or an `.org` file keeps its outline reading through the dialect, where a heading owns its section and a `TODO` keyword is a task. The format and both readings are specified in [editor-and-content.md](../architecture/editor-and-content.md#storage-format).
- **Tasks:** a checkbox after the list marker (`[ ]` TODO, `[/]` DOING, `[x]` / `[X]` DONE, `[-]` CANCELLED) is the block's task state, on import as when typed, pasted or saved from the buffer, and export writes the same checkbox (a state outside that alphabet, such as a custom `WAITING`, is a `todo_state::` line). A Logseq or Org import alone also reads Logseq and Org task syntax: a keyword at the start of the bullet (`TODO`, `LATER`, `WAIT`, `WAITING` → TODO; `DOING`, `NOW`, `IN-PROGRESS`, `STARTED` → DOING; `DONE`; `CANCEL`, `CANCELED`, `CANCELLED` → CANCELLED), a priority cookie after it (`[#A]`, `[#B]`, `[#C]` → the first, second and third priority level), and `SCHEDULED: <2026-10-01 Thu>` / `DEADLINE: <…>` lines under the bullet → the scheduled and due dates, with a repeater the repeat rule can express (`+1w`, `++1d`, `.+1m`) → `repeat`; the day name in any language (`Thu`, `jeu.`, `周四`) and a time are skipped, and a warning period or delay (`-3d`, `--3d`) is dropped with a warning while the date stays. A planning line that cannot be read in full stays text and is counted in the warnings, as does a second line whose repeater is not the block's; a keyword with no `<` timestamp after it (`DEADLINE: when we're ready`) is prose. Typed, pasted, in Edit as Markdown or in a Markdown file, `TODO`, `[#A]` and a planning line stay text, and an export writes them as the text they are. On a task line, one with a checkbox, the Obsidian Tasks fields at the end of its first line, before any `^anchor`, are read on every surface, imported, pasted, saved from Edit as Markdown or appended by an agent: `📅 2026-10-05` → the due date, `⏳ 2026-10-01` → the scheduled date, `🔺` or `⏫` → the first priority level, `🔼` the second, `🔽` or `⏬` the third, `🔁 every day`, `every 2 weeks` and the like (days, weeks, months, years) → `repeat` (`+1d`, `+2w`), with `when done` → the `.+` form, and on a done task `✅ 2026-10-03` → its completion date. Any other signifier (`🛫`, `➕`, a recurrence the rule cannot express, `✅` on a task not done) and one whose value does not parse stay text and are counted in the warnings; off a task line every signifier is text. Every surface also writes them (#6277 D3): a checkbox task's export, copy, Edit as Markdown buffer and agent read put its priority level (`⏫`, `🔼`, `🔽`), its rule (`🔁 every week`, `… when done`), its scheduled and due dates and, done, its completion date at the end of its first line, before its `^anchor`, in that order, as the Tasks plugin writes them; a rule Tasks cannot express (`++1d`, `daily`) or one with a `repeat-until` or `repeat-count` stays `repeat*::` lines, a value no signifier reads back as (a priority outside the levels) stays its `key::` line, and a block with no checkbox keeps its `key::` lines. A task whose own text holds a signifier that would read as something else is written with a `\` before each of its signifiers, which every reader removes, so it reads back as the text it is.
- **Logseq bookkeeping:** in a page of a Logseq graph or an `.org` file only, a block's `id:: <uuid>` line is its anchor, so a `((uuid))` reference to it anywhere in the same file, or on a folder import in any file of the folder, becomes a reference to the imported block, and `{{embed ((uuid))}}` an embed of it; a `((uuid))` to a block of no file imported with it is stripped and counted in the warnings. `collapsed:: true` folds the block on the device that imported it (collapse is a per-device layout), `heading:: true` makes the block a heading one level below its outline level, as Logseq shows it (`heading:: 2` an h2), and a `:LOGBOOK:` clock drawer is dropped, counted in one warning. None of these lines stays a property. On any file import, Logseq's image size map (`![a](pic.png){:width 300}`, `{:height 53, :width 42}`) becomes its alt's size (`![a|300](pic.png)`, `|42x53`), for an attached or a remote image alike.
- **Logseq and Org blocks:** in a page of a Logseq graph or an `.org` file, a `#+BEGIN_X` … `#+END_X` block inside a block's text, outside a code fence, is read when X is one of Logseq's admonitions (`NOTE`, `TIP`, `IMPORTANT`, `CAUTION`, `WARNING`, `PINNED`), as a `> [!X]` callout of its lines, or `QUOTE`, as a `>` quote of them; the keyword and the kind are read ignoring case, as Org reads them. Any other kind (`SRC`, `EXAMPLE`, a custom one) and a block with no `#+END_X` stay text as written.
- **Highlight and math from other tools** (#6033): Logseq's `^^x^^` highlight is stored as `==x==`, LaTeX's `\(x\)` as `$x$`, and GitHub's ```` ```math ```` fence as a `$$` block. A `\[x\]` is math only when its text holds a LaTeX command (`\frac`, `\alpha`): a `$$` block when it is the whole block, else `$x$`; Logseq's `\[x^2\]` and the bracketed text `[x]` stay text. Code, the name or label of a `[[…]]` link and an escaped form (`\^^`, `\\(`) stay as written. A paste, every MCP content write and *Edit as Markdown* (each block the save changes or creates) read them the same way. Outside math, a link's address and an image's alt, the editor writes none of these forms: it stores a literal `^^` that could pair as `\^\^`. Text stored before that escape existed reads its `^^` pair as Logseq's highlight, and a code block of language `math` reads as math, once a paste or an *Edit as Markdown* save writes the block again. An earlier import stored `\(x\)` as written, which the editor shows and saves as `(x)`: a block edited since has lost the math (re-import the file to get it back), and one never edited converts with the rest.
- **Logseq graph folder:** a folder holding `logseq/config.edn`, or both `pages/` and `journals/`, is read as a Logseq graph. A page is titled by its file name alone, never its folder: `___` is a namespace `/` (`a___b.md` is `a/b`; in the legacy file-name format, a config without `:file/name-format :triple-lowbar`, a `.` is), and every `%XX` is decoded (`What%3F.md` is `What?`); a leading `title::` line names the page instead. A journal whose file name is a day in the config's `:journal/file-name-format` (default `yyyy_MM_dd`) is that day's journal page, `YYYY-MM-DD`, and a `[[link]]` outside a code fence that names it by its title in `:journal/page-title-format` (an older graph's `:date-formatter`; default `MMM do, yyyy`: `[[Oct 21st, 2026]]`) links that page; a title format date-fns cannot write leaves those links as written, with a warning in the app log. The graph's `logseq/` folder (config, `bak/` and `version-files/` copies) is not imported. No other tool-specific syntax is interpreted, apart from a Notion export's below.
- Imports land in the **active space**. To import into a specific space, switch first.
- **Re-import** (#6277 decision 7): a Markdown file picked on its own (not from a folder), or an Evernote or Joplin note without attachments, whose title names a page of the space with content updates that page in place, as an *Edit as Markdown* save of the file does: a line whose `^id` anchor names one of the page's blocks, or that pairs with one by its text, updates that block, a new line adds a block, and a block the file no longer holds goes to the Trash. Before it runs, the import lists the pages it will update and asks to go on. Importing the same file again changes nothing (but for an Obsidian `^name` marker or a Logseq `{:width 300}` image size, which an import takes out of a block's text and a save leaves in it), and Undo on the page reverts its update in one step. An update past the undo cap, or one a save refuses (a property value its definition refuses), fails that file. A file whose title names a page an earlier file of the same import created or updated becomes a new page `Title (2)`, with a warning, so two notes called "Meeting" stay two pages; so does a folder's note, a note with attachments and a Logseq or Org file, which the import reads in ways a save does not.

### Evernote (`.enex`)

Each note becomes a page titled by its file name and title, as a Joplin note is by its notebook path, since an ENEX export carries no notebook: `Work.enex`'s note `Meeting` is the page `Work/Meeting`, so two files' `Meeting`s stay two pages. A `/` or `\` in the file name or title is kept as a look-alike (`∕`, `⧵`) so each stays one level rather than a namespace (`TCP/IP` is the page `Work/TCP∕IP`). The note goes through the same import as a Markdown file, so a `#word` in its text becomes a tag and a checkbox item a task. Its tags become the page's tags, whole (`C++`, `2024`; a name holding a space, `Multi Word`, as `Multi-Word`, with a warning); its created and updated dates and a web clip's source URL become the page properties `created`, `updated` and `source-url`, beside `source: evernote`. The body keeps headings, lists, links, emphasis, strikethrough, horizontal rules, code, code blocks with their indentation, checkboxes as task states and tables (a table with no header row takes its first row as the header; a merged cell stays one cell, so the cells after it shift left; a list or a nested table is flattened into its cell), and an encrypted block becomes a warning callout. Evernote tasks become task blocks where their task group stood, in Evernote's order (a task whose group the body lacks goes after the body): TODO or DONE as Evernote had it, its due date as the task's due date and its reminder as its scheduled date, each the day in the task's own time zone (else local time). A note with an older note reminder opens with a task block named after the note: DONE once the reminder is done, its reminder time (the day in local time) as the due date. An embedded image, PDF, text file, audio file (MP3, M4A, AAC, WAV, Ogg, Opus, WebM, FLAC) or archive (ZIP, tar) becomes an attachment, a space or parenthesis in its file name replaced by `_`; an image shows inline and any other file as a link to it. An export carries no note IDs, so a link to another note (`evernote:///view/…`) becomes a link to that note's page (`[[Work/Meeting|Meeting]]`) when its text is the title of a note in the same file, matched as page names are (ignoring case); any other stays an Evernote link, and one import warning counts them all. Not imported: Office, video and other attachment types (each rejected with a warning), a task's flag and recurrence, the other note attributes (author, location), and styling such as highlight, colour and underline.

The Import button shows a per-block progress count while a file imports, then a count-only summary (page title, blocks created, properties set, and a `N warning(s)` count). It does not show per-file detail or which file produced a given warning.

### Joplin (`.jex`)

Each note becomes a page titled by its notebook path and title (`Projects/Roadmap/Note`), and a `/` or `\` inside one notebook or note title is kept as a look-alike (`∕`, `⧵`) rather than a namespace level (a notebook `A/B` is the one level `A∕B`); a link to the note names the same title. It goes through the same import as a Markdown file. An HTML note (a web clip) is converted to Markdown first, as an Evernote body is. Its tags become the page's tags, whole (`C++`, `2024`; a name holding a space, `Multi Word`, as `Multi-Word`, with a warning); its created and updated dates become the page properties `created` and `updated`, beside `source: joplin`. A to-do opens with a task block named after the note: TODO or DONE as Joplin had it, and its due date (the day in local time) as the task's due date. An embedded or linked image, PDF, text file, audio file (MP3, M4A, AAC, WAV, Ogg, Opus, WebM, FLAC) or archive (ZIP, tar) becomes an attachment, a space or parenthesis in its name replaced by `_`; an embedded image shows inline and a linked or any other file as a link to it, and Office, video and other types are each rejected with a warning. A link to another note becomes a `[[Notebook/Title|label]]` link, from `:/id` and `joplin://id`; an `#anchor` on it is dropped. Not imported: a reference-style link (`[label]: :/id`) or an HTML `<a href=":/id">` in a Markdown note, which stays a Joplin link; encrypted items, skipped and counted; a note's location, author and source URL, and an image's size.

### Notion export

Unzip Notion's *Markdown & CSV* export and pick the folder. A folder whose `.md` files mostly end in Notion's 32-hex page id (`Plan 0123…cdef.md`) is read as a Notion export; any other folder is untouched.

- **Kept:** each page, titled without the id, folders too (`Export/Plan/Sub`); links between pages (`[Sub](Plan%20<id>/Sub%20<id>.md)`), which name the pages they import as; a database row's `Key: value` lines under the title as page properties, the key lowercased with `-` for spaces and accents dropped (`Due date` is `due-date`, and `Tags` the page's tags), unless a key is reserved by the app (`Space`, `Template`, `Created at`) or has no Latin letter or digit left (`状態`), when the lines stay text; an `<aside>` as a `> [!note]` callout; a `<details>` toggle as a callout titled by its `<summary>`, open, since Agaric has no toggle. Code blocks stay as written.
- **Dropped:** the database tables (`.csv`), skipped and counted in one warning; each row is also a page of the export and imports with its properties. A property value its definition refuses (a `Status: In progress` against the built-in `status` select) is skipped with a warning, as front matter is.

### Org (`.org`)

- **Kept:** each headline as a block nested by its stars, with the task syntax a Logseq or Org import reads (`TODO`, `DONE` and the other keywords, `[#A]`, `SCHEDULED:` / `DEADLINE:`); the keywords a `#+TODO`, `#+SEQ_TODO` or `#+TYP_TODO` line declares, as a task in Agaric's fixed states: a keyword the import already reads keeps its state (`NOW` is DOING, `CANCELED` CANCELLED), and any other (`NEXT`, `HOLD`) is TODO before the `|` and DONE after it, the last keyword being the done one when there is no `|`; `#+FILETAGS` as the page's tags and a headline's `:tags:` as its block's; a `:PROPERTIES:` drawer as the headline's properties, and one before the first headline as the page's (a drawer with no `:END:` stays text, as does a page property the app reserves, such as `:Space:`); `#+TITLE` as the page title, else the file name (a `/` or `\` in a `#+TITLE` kept as a look-alike, `∕` or `⧵`, not a namespace); `[[url][desc]]` as a link, `[[Page][desc]]` as a labelled page link, `[[file:other.org][desc]]` as a link to the page `other.org` imports as (on a folder import, by its `#+TITLE` when it is a file of the folder, else by its file name), and `[[file:pic.png]]` as an embedded image; an `[[id:…]]` link, with or without a description, as a reference to the headline of the pick whose drawer holds that `:ID:` (a uuid, as Org writes it; the description is dropped) or as a link to the page whose file-level drawer holds it; source and example blocks as code blocks; quote blocks and Logseq's admonitions (`#+begin_note`, `#+begin_tip`, …) as quotes and callouts, as a Logseq or Org import reads them; tables, other `#+BEGIN_` blocks and other `#+KEYWORD:` lines as text.
- **Dropped:** `# comment` lines and `CLOSED:` stamps. Not read, so left as text: Org emphasis (`*bold*`, `/italic/`, `=code=`), and a link to a heading (`[[*Budget]]`), a custom id (`[[#custom-id]]`) or an id no file of the pick holds, which links no page. There is no `.org` export.

### Bibliography import (BibTeX / CSL-JSON)

*Import bibliography* in Settings → Data accepts `.bib` (BibTeX) and `.json` (CSL-JSON) files. Each entry becomes a **reference page** in the active space:

- **Page title** is the citation display name — `{first-author family name} {year}` (e.g. "Smith 2024"; a braced BibTeX name like `{World Health Organization}` or a CSL `literal` name counts whole), falling back to the citation key; title collisions get the citation key appended.
- **Typed properties** per entry: `citation-key`, `title` (the paper title), `authors` ("; "-joined), `year` (number), `doi`, `url`, `journal`, `abstract`, `reference-type`. Those types are a *preference*, not a guarantee — **the vault's existing shape for a key always wins, declared or not**, and the import coerces its own values to that shape instead:
  - A key you have already **declared** (Settings → Properties) keeps your declaration; the imported values coerce to it.
  - A key you have **values under but never declared** stays undeclared — declaring it would constrain that key on every block in the vault, not just the imported pages, and there is no clean way back once values exist. The imported values are stored as text, like any undeclared key's.
  - Only a key that is both undeclared and unused anywhere in the vault gets the type above.
  - Every skipped declaration is reported in the import summary's `warnings` (counted as `N warning(s)`), naming the key and why.
- **Re-import is idempotent:** entries whose `citation-key` (or, as a fallback, non-empty `doi`) already exists in the space are skipped and counted.
- **BibTeX is a documented subset** (`src-tauri/agaric-engine/src/bibliography.rs`): brace-bodied entries with `{…}` / `"…"` / bare-integer values; `@comment` / `@preamble` / `@string` are skipped with a warning (no macro expansion, no `#` concatenation); `journal` falls back to biblatex `journaltitle`, then `booktitle`, and `year` to the leading four-digit year of `date`; LaTeX decoding covers only the common escapes, dashes, `~` (a space), case-protection braces (dropped), and the accent commands (`\'e`, `\v{c}`, `\'{\i}`, …) — anything else stays literal with a per-entry warning. Unbalanced braces or an unterminated quote fail the import with the entry's line number.
- Authors and journals land as text, not linkable `ref` pages; a live citation picker is a possible follow-up.

## Export

### Per-page export

In the **PageHeaderMenu** kebab → *Export as Markdown* (or `Ctrl+Shift+E`).

- Emits the page's content as Markdown, laid out as the *Edit as Markdown* buffer is (a plain block a paragraph, a list block its marker, a task `- [ ]`, a plain child a `+` item), but for a first block opening with a `#` heading, also a `+` item, which an import would otherwise take for the title, so a Markdown import reads it back as the page's blocks; a block ends in its `^id` only when something addresses it (below) or it leaves a code fence open, whose end that line marks.
- A YAML front-matter block opens the file, where Obsidian and GitHub read it, and carries the page's properties (todo state, dates, tags, custom properties); the `# Title` line follows it. Each block's properties follow the block as `key:: value` lines, a repeating task's rule (`repeat`, `repeat-until`, `repeat-count`) included, so a re-import keeps it repeating, and a value with a line break or surrounding spaces is written quoted, so it reads back whole. A ref-typed value is written as a link to its page, `owner: "[[Title]]"` in the front matter and `owner:: [[Title]]` on a block's line, and as its target's id when that is not a live page.
- Inline `[[links]]` and `#tags` are written as their textual equivalents (`[[Title|label]]` for a labelled link), and both round-trip: re-importing the file resolves them back into page references and tags. A tag whose bare form would not read back as the same tag (`C++`, `v1.2`, `Q&A`, `42`, a name with spaces, or one written after anything but whitespace, as in `[#work]` or `(#work)`) is written as `#[[name]]`; a name with spaces re-imports as that tag where the space has it, else dashed, with a warning.
- A block reference is written as an Obsidian block link (`[[Page#^id]]`, `[[#^id]]` on its own page), and an embed block as an Obsidian embed (`![[Page]]`, `![[Page#^id]]`, `![[#^id]]`); *Edit as Markdown*, block copy and the Markdown mirror write them so too wherever the link reads back as the same page or block, a block copy naming the page of a reference to its own page (`[[Page#^id]]`), and keep the id (`((id))`) where it would not, as for a block of another space or a deleted one. An embed among other text, or of a page whose title would read as a file name (`paper.pdf`), stays `{{embed [[Page]]}}`. A block that a reference or embed from any page, a ref-typed property value or an attachment addresses ends in its `^id`, so a folder import of the export restores block references and embeds rather than page links.

*Edit as Markdown*, next in the same kebab, edits the page as its source buffer, line by line: a plain block as its own paragraph, a `-` or `1.` marker only on a bulleted or numbered block, `- [ ]` / `- [x]` tasks, each block's id carried out of sight by the line it starts on, children indented under their parent's text, `key:: value` property lines, the page's own properties, aliases and tags as the export's front matter, and no title or attachment lines (see [editor.md](editor.md#edit-as-markdown)). Block copy writes the blocks in the buffer's format and a paste reads text the same way, so a copy pastes back as the blocks it was: as a Markdown file import does, a paste reads `- x` and `* x` as bulleted blocks, `1. x` as a numbered one, `+ x` as a plain one and `- [ ] x` as a task. A paste is no page, so text that opens with front matter, as an *Export as Markdown* copy does, pastes without it, with a warning, and the copy's `# Title` line is a heading block; a `---` anywhere else, or one no `---` line closes, is text. *Duplicate*, a new day's copy of the journal template, and the MCP tools' page reads and writes use the same format. Either way a copy keeps its list style, task state, properties (a value with a line break included, written quoted as the buffer writes it), repeat rule and nesting, and a multi-line block stays one block; a task that also holds a hidden list style is copied as a task without it. A pasted property line reads as an import reads one: a value its definition refuses stays text in the pasted block, and a warning toast names it.

### Export-as-ZIP (Settings → Data)

Two rows: **Export this space** and **Export all spaces** (the whole vault, one top-level folder per space, with same-named spaces disambiguated).

- One Markdown file per page, with the namespace hierarchy mirrored as folders. The path names the page, so the file has no `# Title` line.
- Each file carries the same YAML front-matter as per-page export.
- Attachments — inline images and block-scoped files alike — are written into an `assets/` folder and the Markdown links are rewritten to relative paths, so they resolve in other tools, and a folder import of the unzipped export attaches them again.
- What a file cannot carry goes in the space's `.agaric/space.json` (each space folder has its own in *Export all spaces*): the space's property definitions (key, type, options), and the title of each page whose file name could not spell it (`a:b` is filed as `a_b.md`; a duplicate title gets a suffix). A folder import of the unzipped space folder reads it first (a pick of the whole *Export all spaces* ZIP holds none at its root, so it restores no definitions or titles): it creates each definition the space lacks before any page imports, so number, date, select and ref values come back typed, and titles those files as recorded. A definition it cannot create is a warning in the import summary.
- A folder import makes no page of a file under `.agaric/`.
- If any page or attachment couldn't be exported, the ZIP gains an `.agaric/export-report.txt` listing exactly what was skipped, and the toast says so rather than reporting a clean success.

### Markdown mirror (Settings → Data)

Off by default, desktop only, and set per device: *Choose folder…* turns it on and *Turn off* stops it.

- Every page in every space is written as a `.md` file under the chosen folder, one folder per space with the namespace hierarchy as subfolders, and kept up to date as pages change.
- Each file holds the page's front matter, then its blocks, as *Edit as Markdown* writes them, with a block id only on a block that a reference, an embed, a ref-typed property or an attachment addresses.
- The folder must be empty or one this device's mirror created. A folder another device mirrors to, a non-empty folder Agaric did not create, and the app's own data folder are refused, with the reason shown.
- A file edited outside Agaric is read back into its page once it stops changing (two reads two seconds apart agree), as an *Edit as Markdown* save over a page that changed meanwhile: what Agaric changed since the file was last written is kept, and a block both sides changed is kept twice, with a warning. One Undo on the page reverts it. Until it is read, Settings lists it under *Changed outside Agaric; not read in yet*.
- A line the file edit leaves without its block id is matched to its block by its text, so a line edited in place or moved keeps its block; a line matching none is a new block, and a block whose line is gone goes to the Trash.
- The file keeps its own form: Agaric writes back only to add or drop the id of a block something refers to, and a later edit in Agaric rewrites only the lines of the blocks it changed, so `*` bullets, `1)` numbers and indents written elsewhere stay.
- A file that is empty or not UTF-8, or whose edit is more than one undo can revert, is not read: the page is unchanged, and Settings lists the file under *Could not be written or read* until it changes. A file saved with CRLF line ends or a byte-order mark is read, and written back with LF and none.

## Pitfalls to know

- **Imports don't merge by ULID.** Two devices that each import the same Markdown set end up with two parallel pages. Sync converges them via CRDT, but the page titles will collide. Plan imports on one device, then sync.
- **Malformed YAML front-matter lines are skipped, not fatal.** A front-matter line that isn't a valid `key: value` scalar is ignored; the page and the rest of its front-matter still import. The skipped lines are surfaced (not silently swallowed) in the summary's warning count as `N frontmatter line(s) [...] ignored`, so there's no need to re-run the import. Array/collection front-matter syntax is likewise parsed-and-ignored with a warning.
- **Import is per-space; export doesn't have to be.** Imports always land in the active space, but *Export all spaces* covers the whole vault in one ZIP — no need to switch spaces and export repeatedly.
- **Export does not include device-local state** (drafts, recent-pages, sidebar width, keyboard customisations).
