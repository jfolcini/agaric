# Editor

The editor is a block-based outliner built on TipTap (ProseMirror). Only the focused block is editable at any moment — every other block renders as a read-only static block. This *roving editor* keeps memory bounded and undo history isolated per edit session.

## Surfaces around the focused block

Above the focused block sits the **FormattingToolbar** — always visible. It carries icon buttons grouped by purpose: refs+blocks, structure, metadata, history. Low-priority buttons collapse into a `MoreHorizontal` overflow popover when the container is narrow.

When you select text inside a block, the **SelectionBubbleMenu** appears next to the selection. It hosts the six mark toggles (Bold / Italic / Code / Strike / Highlight / Underline) plus an External Link button. It only appears on non-empty selections so it doesn't get in the way of typing. From the keyboard, with *Tab indents blocks* off in Settings → Editor, Tab moves into it, `←` / `→` move between its buttons, and `Enter` or `Space` presses one.

## Markdown surface

Type, paste, or use the toolbar:

| Mark / structure | Trigger |
| --- | --- |
| Bold | `Ctrl+B` |
| Italic | `Ctrl+I` |
| Inline code | `Ctrl+Shift+K` |
| Strikethrough | `Ctrl+Shift+S` |
| Highlight | `Ctrl+Shift+H` |
| Underline | `Ctrl+U` (stored as `<u>…</u>`) |
| Heading levels | `Ctrl+Alt+1` … `Ctrl+Alt+6`, toolbar → Heading popover, or slash menu (`/h1` … `/h6`) |
| Blockquote | Toolbar, or slash menu (`/quote`) |
| Code block | Toolbar (with language picker), or slash menu (`/code`) |
| Divider | Slash menu (`/divider`) |
| Callout | Slash menu (`/callout`); types: tip / note / info / warning / error |
| Ordered / unordered list | Toolbar, or markdown shortcut (`1.`, `-`). A task is the third kind of list: it shows its checkbox, never a bullet or a number. Making a block a task (the task button, `Ctrl+Enter`, `/todo` and its siblings, the block menu, the batch toolbar, a typed checkbox) takes its bullet or number off, and making a task bulleted or numbered (the toolbar, `/bullet-list`, `/numbered-list`, *Turn into*, the block menu, a typed `-` or `1.`) takes its task state off; cycling a task back to no state brings no list style back. A task between two numbered blocks ends their run. One page-level `Ctrl+Z` takes back a change of kind (a list block made a heading, a callout, a quote, code or a task; a task made bulleted or numbered) together with the kind it took off |
| Table | Slash menu (`/table` opens a size grid at the caret, starting at 3×3: arrows resize it, Enter inserts) |
| Task | A checkbox and a space typed at the start of the block, with or without a `-` and a space before it: `[ ]` TODO, `[/]` DOING, `[x]` or `[X]` DONE, `[-]` CANCELLED. The marker disappears and the block takes the state; `Ctrl+Enter`, the checkbox and the toolbar cycle it from there. `TODO` stays a word |

Markdown shortcuts trigger as you type (`#`, `##`, ``` ` ```, `**bold**`, `_italic_`, `~~strike~~`, `==highlight==`, `[text](url)`, `1.`, `-`, `>`, `[ ]`, `[/]`, `[x]`, `[-]`). A mark delimiter follows CommonMark's flanking rule, typed, pasted or stored alike: one with a space on its inner side stays text, so `5 * 3 = 15 and 2 * 4 = 8` is not italic, while a mid-word `un*break*able` is. A delimiter run never closes the mark it opened, so `a====b` stays text.

## Markdown syntax around the cursor

Settings › Editor › *Show Markdown syntax around the cursor* (on by default, as Obsidian's Live Preview; turned off per device) draws the syntax of the formatting the cursor is in or touches, in blocks and in page mode alike: the markers of bold, italic, code, strikethrough and highlight, a heading's `#` run, and an external link's `[` and `](url)`; underline, stored as `<u>` HTML, shows none. The syntax is drawn for you to read and is never in the text, the clipboard or the saved block; a bare URL (which is stored as it reads) shows none, a selection across blocks shows none, and nothing is drawn while the editor does not have focus (focus in its link popover still counts). While the mouse button is down nothing new is drawn, so a drag selects the text it started on; the syntax appears when the button is released.

- **A page, tag or block-ref chip shows its syntax beside it** while the caret is right before or after it, or it is selected: `[[` and `]]` around a page link, `#` before a tag, `((` and `))` around a block reference. It is read-only and not a marker: the chip stays one atom with its id, Backspace and Delete take it whole as they do with the setting off, and the arrows step over it. The syntax is no part of the selection, the text, the clipboard or the history, and a range selection shows none.
- **A quote, a callout, a code block and math show their syntax the same way, to read only**, in blocks and in page mode: the line the cursor is on in a quote starts with its `>` (`> >` in a quote in a quote, and `> [!NOTE]` on a callout's first line), a code block shows its fences and language on lines of their own above and below the code, and math shows its `$` beside the cursor, or its `$$` above and below a selected display equation, whose LaTeX its own source field edits. The editor's own keys act on them as with the setting off (Backspace at the start of a quote line takes it out of the quote), the caret stays where it was as the syntax appears and goes, and what you type inside is saved as the block's Markdown.

- **A marker is one unit.** Backspace right after it, or Delete right before it, removes the formatting from the whole range, lowers the heading one level (a level 1 becomes a paragraph) or unlinks the text, as one undo step; at the start of a block this is not a join with the block above, and in a list block it comes before the list's own Backspace. `#` typed left of a heading's run raises the level.
- **The arrows and a click cross a marker without moving in the text**, so there is one caret stop at each edge of a formatted range: left of a closing marker typing stays formatted, right of it typing is plain. At the end of a block, ArrowRight steps past the closing marker first and the next one leaves the block (in page mode, into the next block, left of the markers at its start; ArrowLeft into the block above lands right of the markers at its end). End on a block's last line lands past every closing marker there, so typing after it is plain; Home stays right of a heading's `#` run, at the start of its text.
- A link's URL is edited in the link popover (`Ctrl+K`), not in its `](url)`.
- While an IME composes, the markers stay where they are until it ends.

## External links

- **Add a link to selected text**: `Ctrl+K` opens the **LinkEditPopover**. Enter the URL; the selection becomes a clickable link.
- **Add a link by pasting**: paste a URL while text is selected — the selection becomes the link's label.
- **Edit an existing link**: click the link → LinkEditPopover opens for edit.
- **Remove a link**: open the popover → *Remove*.
- **Hover preview** (desktop): hovering a link shows a tooltip with the page's title and favicon (cached locally; first hover triggers a fetch).
- **Long-press copy** (mobile): long-press a link to bring up *Copy URL*.

## Block operations

[keyboard.md](keyboard.md) is the source of truth for bindings; this table is the editor's action inventory.

| Action | Trigger |
| --- | --- |

| Leave the block | `Escape` keeps what you typed and selects the block, so the block-selection keys act on it; a second `Escape` clears the selection, and `Ctrl+Z` undoes the edit like any other. | Merge into previous | `Backspace` at start of block. On a bullet / numbered block the first `Backspace` clears the list style; the second merges (or, on an empty block, deletes it) |
| Indent / dedent | `Tab` / `Shift+Tab`, or `Ctrl+Shift+→` / `Ctrl+Shift+←` |
| Move block up / down | `Ctrl+Shift+↑` / `Ctrl+Shift+↓` |

| Open Property Drawer | `Ctrl+Shift+P` |
| Set priority directly | `Ctrl+Shift+1` / `Ctrl+Shift+2` / `Ctrl+Shift+3` (P1 / P2 / P3) |
| Insert a date at the cursor | `Ctrl+Shift+D` |
| Set a due / scheduled date | Toolbar (no default keyboard binding) |
| Cycle task state | `Ctrl+Enter` or `Ctrl+L` |
| Multi-select adjacent blocks | `Shift+Click`, `Ctrl+Click`, `Ctrl+A` (within page) |
| Delete block | Toolbar → *Delete*, or `Ctrl+Backspace` on an empty block |

`Tab` / `Shift+Tab` indent and dedent by default. If you'd rather keep them as plain focus navigation, turn off *Tab indents blocks* in Settings → Editor; either way they're suppressed while a picker popup is open.

## Drag and drop

Drag-handle on the left gutter. On touch there is no handle: hold anywhere on a block for 400 ms (it lifts), then drag it; let go without moving and its menu opens instead. A parent's collapse chevron sits at the right end of its row there. The drop indicator shows the projected nesting depth — horizontal offset during drag determines whether you're moving the block as a sibling, a child, or to an outer level. Offscreen blocks become zero-height placeholders to preserve scroll position. Auto-scroll engages when dragging near the top or bottom of the viewport.

You cannot drop a block into its own subtree.

## Edit as Markdown

Page kebab → *Edit as Markdown*, or the *Edit as Markdown* link in page mode's footer, swaps the page's blocks for a plain-text editor holding the page as markdown, line by line: the page's own properties, aliases and tags as YAML front matter when it has any, then each block as the page shows it. A plain block is its own paragraph, a bulleted one `- text`, a numbered one `1. text` by its place in the list, a task `- [ ] text` (`[/]`, `[x]` and `[-]` for its other states), a heading `## text`; a blank line goes between blocks, but not between neighbouring list lines. A block's children are indented under its text, and its `key:: value` property lines (a repeating task's `repeat`, `repeat-until` and `repeat-count` among them) sit under it at its text's column. Every line shows its markdown exactly as typed, with no formatting and no shortcut turning it into something else. The title and attachments keep their own UIs and are not in it.

- **Each line keeps its block.** The line a block starts on carries the block's id out of sight, and keeps it while you edit the text. Cut a block's lines (a paragraph with the blank line after it) and paste them where a line starts, or drag them there, to move or re-nest the block; cutting only the start of a line leaves the line its block. Deleting a block's lines deletes it, and a new paragraph or list line creates one. Enter keeps the id on the line where the text it splits starts, so what follows is a new block. Joining two blocks' lines (Backspace at the start of one, or Delete at the end of the one before) keeps the first block and deletes the second. A copy pasted (or dragged with `Ctrl`) is a new block, and so are lines pasted or dropped from another page's buffer and text from anywhere else: a `^ID` in it is text. Copying out of the buffer gives the lines as plain text, without ids.
- **Enter starts a new block**, as in page mode: a sibling of the block the cursor is in, at the same level. After a paragraph, a heading or any other line with text, including a block's further line, it leaves a blank line and starts the next line at that block's indentation (a `+` item under a list block), so what you type next is a block of its own beside it, and text split off a heading stays a heading of its level; after a bulleted or numbered block's further line, though, it starts the next line with that block's marker, numbered one up, and after a task's further line it leaves a plain block. With the cursor before a line's text, the text keeps its indentation and the cursor moves down with it, after its indentation and list marker, as page mode's Enter at a block's start leaves it. `Shift+Enter` breaks the line inside the block instead. On a `-`, `*`, `+`, `1.` or `1)` line Enter starts the next line with the same indentation and marker, numbered one up, and a task line goes on as `- [ ]`; on a line holding only its marker it removes the marker, ending the list, and leaves a blank line, another under the cursor where a list line follows. In a fenced code block and in the front matter it breaks the line. `Ctrl+Z` and `Ctrl+Shift+Z` undo and redo in the buffer a run of typing at a time.
- **The block editor's keys work on blocks** ([keyboard.md](keyboard.md#edit-as-markdown)), through the same bindings and your rebinds. `Tab` and `Shift+Tab` (or `Ctrl+Shift+→` / `Ctrl+Shift+←`) indent the blocks at the cursor, each with its further lines and children, under the block before them, and take them a level out, leaving a block with no sibling before it, or a top-level one, where it is; with *Tab indents blocks* off in Settings → Editor, Tab moves focus instead. `Ctrl+Shift+↑` / `Ctrl+Shift+↓` move the blocks at the cursor with their children past their sibling, a selection's siblings together, so the save moves those blocks; they stop at the top and bottom of the parent and at the front matter. `Ctrl+Enter` steps the task of the block at the cursor as the block editor does: none, `[ ]`, `[/]`, `[x]`, `[-]`, none, a task taking its block's bullet or number off. `Ctrl+Alt+1` … `Ctrl+Alt+6` turn the block at the cursor into that heading, as *Turn into* does. A block one of these changes is written again as the page writes it: at the column its parent's text starts, a plain block under a list block as a `+` item, and with the blank lines it needs. Every block keeps its id through all of these, and one `Ctrl+Z` undoes each. `Escape` leaves the buffer.
- **Pickers write markdown.** `[[` opens the page picker and the page picked is written `[[Title]]`; `#`, where a tag can start (at the start of a line or after a space, not in a fenced code block), opens the tag picker and writes `#name`, or `#[[name]]` when the bare form would read as another tag; `((` searches blocks and writes `((ID))`. *Create* writes the name as typed, and the save creates the page or tag. An open picker takes `Enter`, `Tab` and `Escape`.
- **The block editor's toolbar is above the buffer**, the same buttons in the same order, each writing its markdown on the line at the cursor or on the block the cursor is in (the block a line starts, or the one whose line starts the lines the cursor is in). *Format* wraps the selection in a mark's markdown (`**`, `*`, `` ` ``, `~~`, `==`, `<u>`), and again unwraps it. *Turn into* rewrites the block as the block editor's Turn into does: `# text` for a heading, `>` before each of its lines for a quote, a fence around them for code, `1.` and `-` for a numbered and a bulleted list (taking a task's checkbox off), and *Divider* makes its text `---`. *Internal link* closes `[[ ]]` around the selection, or types `[[`; *Block reference* types `((` and *Insert tag* `#`, each opening its picker on what follows. *Cycle priority*, *Set due date* and *Set scheduled date* write the block's `priority::`, `due_date::` and `scheduled_date::` line under its text, as the export writes them; *Insert date* writes `[[YYYY-MM-DD]]`; *Insert query* makes the block's text the `{{query …}}` built; *Emoji* writes the emoji at the cursor; *Toggle TODO* steps its checkbox; *New line* is `Shift+Enter`; *Undo* and *Redo* are the buffer's; *Discard changes* is Cancel.
- **The block menu** opens from the toolbar's *Block actions* button, since a long press in a text field belongs to the phone, and acts on the block the cursor is in: its TODO and priority, Turn into, Move & arrange (Indent and Dedent take the lines indented under the block along, Move up and down are the move keys, Duplicate copies it with them as new blocks), Delete (with the lines under it), and Copy block reference (for a block already saved) and Copy page reference. Every line keeps its block through all of these, and `Ctrl+Z` undoes each.
- **Left out of the buffer**, each because it has no meaning there: Insert table and the table operations (a table is its `|` rows, typed as text), Properties and the menu's History (they act on the saved block, behind the buffer; a property is its `key:: value` line), Zoom in and Collapse (the buffer is the whole page, every line shown), Merge (Backspace at a line's start joins it to the one above), Open link and Copy URL (the menu does not open on a link), and the menu's content copies (select the lines and copy them). Attachments stay out of the buffer, so there is no attach action in it either.
- **On a phone** the toolbar is pinned above the keyboard and carries *Cancel* and *Save* in place of the buttons under the buffer, with *New line* for the line break a virtual keyboard has no key for.
- **The buffer reads by lines.** A blank line separates blocks, and lines with none between them stay one block (a line break, a table, a quote). A heading, a fence or a `---` typed under a paragraph starts a block of its own, and a heading owns nothing: what is indented under a block after a blank line is its child. `-` and `*` make a bulleted block, `1.` and `1)` a numbered one, `- [ ]` a task, and `+` a plain block, the form a plain block under a list block takes; text typed right under a closing fence stays in the code block. A line that would read as something else is written with a leading `\`, which the save removes again (a paragraph opening `- x`, a `## x` line inside a paragraph), and a line holding only `\` is an empty block, or an empty line inside one. A fence left open in a block ends at the next line that carries a block, and the save warns which fence it closed. A paste reads text this way too, and a file import keeps its own grammar ([import-export.md](import-export.md#import-settings--data)).
- **Property lines** read as import reads them, with one difference: `key::` with no value, with or without a trailing space, deletes the property the block holds; for a key it does not hold, the line stays in the block as text. A key names the built-in key or definition it matches ignoring case and `-`/`_`, and a ref-typed value is a block id, a `[[Title]]` or a plain title in the space. A value its definition refuses refuses the save. A value its line cannot hold as it is (one with a line break, which an agent can set, a space at either end, or one that is itself a quoted string) is written as a JSON string: `note:: "two\nlines"`, with `\"` for a quote and `\\` for a backslash inside. A value typed in double quotes is read the same way; any other value, backslashes included, is taken as it is.
- **A refused save names the line.** The message starts with `line N:`, the buffer line of the block the save stopped at, counted from the top of the buffer, and that line is selected so the cursor is on it. A depth or size limit names the line of the block where it was reached the same way.
- **Page properties** are the front matter at the top of the buffer, the export's and Obsidian's form: `---`, then `aliases: [a, b]`, `tags: [a, b]` and one `key: value` line per property, then `---`; a value with a line break is written `key: |`, its lines indented two spaces under it. Typing one on a page that has none creates it, and Logseq's `key:: value` lines above the first bullet (`alias::` and `tags::` among them) are read too, a quoted value as a block's is. Save writes what changed as the page's property table, alias list and tag list write it: a key left out is deleted, a tag no tag of the space names is created. The keys the property table does not show (`created_at`, `template` and the like) are not written, so leaving them out deletes nothing. A line that is not a `key: value` pair, a key the app keeps, a key written twice, a `---` nothing closes and a value its definition refuses each refuse the save, and the message names the line, the `---` being line 1.
- `[[Page]]` and `#tag` resolve in the page's space as import resolves them ([import-export.md](import-export.md#import-settings--data)): exact title, then a unique case-insensitive title, then a unique alias, else created; the `[[` picker's `[[text]]` rule follows the same order over the full title, namespace included.
- **Ids that stay ids** (a `((ID))` block ref, a ref property's `key:: ID`, and a `[[ID]]`, `[[ID|label]]` or `#[ID]` whose title would not read back as it: a duplicate title, another space's page, a deleted one) show their target's title under them while hovered or while the cursor touches them, which a screen reader hears; a missing target shows the chip's broken-link label, struck through. Each one is edited whole: the arrow keys step over it, Backspace or Delete beside it removes it in one undo step, typing inside it does nothing, and a paste over a selection that splits one lands beside it, so it never removes text the selection did not hold whole. Selecting a whole id and typing replaces it. Save warns, without stopping, of any that point to nothing.
- `[[Page|label]]` links `Page` and shows `label` in its place, stored as `[[ULID|label]]` so the link still follows a rename; a label equal to the title is not stored. `[[Page#Heading]]` links the page titled `Page#Heading` when one exists, else `Page` (it never creates `Page#Heading`). Ctrl+K on a selected link chip opens the link popover on its label.
- **Save** (`Ctrl+S`) writes the whole buffer as one change, so one page-level `Ctrl+Z` undoes it. Saving an empty buffer asks first, since it deletes every block. **Cancel** (or `Escape`) closes the buffer; when it is not the page as loaded, in its text or in which line carries which block (a restored draft included), it asks first, and *Keep editing* goes back to the text.
- **Page**, left of Cancel and Save, goes to page mode instead of closing, as GitLab's *Switch to rich text editing*; `Ctrl+E` / `Ctrl+Shift+M` in the buffer does the same, and page mode opens with the cursor at the page's start. A buffer that is the page as loaded switches at once, writing nothing. A changed one is saved first, as Save saves it, and page mode opens once the save lands: an emptied buffer asks first, a page changed elsewhere opens the conflict dialog, whose *Merge* and *Overwrite* end in page mode, and a refused save, *Keep editing*, *Reload* or a cancelled emptying leave the buffer open, where the next Save closes it as usual. The save is one page-level undo step, as Save's: page mode opens with no undo history of its own, so `Ctrl+Z` in the document does not take it back, and `Ctrl+Z` outside the document does, in one step. On a page over page mode's block cap, *Page* is disabled and its tooltip says why.
- **Edit, Preview and Changes** above the buffer switch what shows in its place. *Preview* shows the buffer as the page shows its blocks: each block at its depth with its task checkbox, its text rendered, its property lines and the front matter as chips, and a `[[Name]]` or `#name` as the chip of the page or tag the save links (or creates). It reads the buffer with the save's grammar. *Changes* is the buffer's line diff against the page as loaded: each change's removed lines (`−`) then its added ones (`+`), the words that changed marked, three unchanged lines either side and longer runs folded. *Save* counts those changes (*Save (3 changes)*) and is off while the buffer is the page as loaded; on a phone, Preview and Changes put Save and Cancel under the view, since the toolbar goes with the buffer.
- **A save leaves a report** with *Undo*, which reverts the whole save while it is still the page's latest change; after that it says so and reverts nothing. A save that deleted blocks (the report then counts what it deleted, created, edited and moved), created pages or tags for names nothing matched (listed as links, so a typo in a `[[Name]]` shows), or saved something differently than written (one line each) keeps its report until you dismiss it; any other save shows *Markdown saved* for a few seconds.
- **If the page changed elsewhere** (another device, an agent, another tab) since you opened the buffer, Save lists what changed there instead of saving: each block added, removed or changed, as its lines read in the buffer. *Merge* saves your text with those changes folded in, as one change, and closes the buffer like Save. Where both sides changed the same lines of a block differently, your version is saved as a new block just before the page's; a block you removed that was changed or moved to another parent there stays; a block you changed or moved to another parent that was removed there comes back as a new block; a block moved differently on each side keeps the page's parent, and children reordered differently on each side keep your order. Each of these shows a warning. *Reload* swaps your text for the page as it is now, *Keep editing* leaves your text so you can copy it out, and *Overwrite* saves your text over those changes: edits made there are reverted, blocks added there are deleted, a line whose block was deleted there comes back as a new block with a warning naming the line, and a page renamed there is linked by its old name, which creates a new page.
- **Unsaved text is kept** on this device as a draft, with the block each line carries, and restored the next time you open *Edit as Markdown* on that page, until you save or discard it. A restored draft still catches what changed on the page since. A draft kept by an earlier version (its blocks `^ID` anchors in its text, or written before the buffer read by lines) is not loaded into the buffer, which could save it as other blocks: it shows read-only above it with *Copy earlier edits*, until editing, saving or discarding the buffer replaces it.
- The front matter's lines carry no id.

## Page mode

Settings › Editor › *Edit pages as* sets how pages open on this device: **Blocks**, the default, one block at a time, or **Page**, the page as one document whose paragraphs are its blocks at their depths, the cursor moving across them freely. The page header's *Blocks | Page* switch, or `Ctrl+E` / `Ctrl+Shift+M`, changes it for the page on screen; on a touch phone the switch is a row of the header's *Page actions* menu, *Edit as page* or *Edit as blocks*, so the header keeps to one row. The journal's Daily view opens its day's page the same way, its switch at the end of the row above the day; the Weekly and Stream views, a day's blocks under each date, stay in blocks whatever the setting says, and Monthly is a calendar with no editor.

The page reads as a document in a frame, as GitLab's rich text editor shows one: no box around each block and no mark on the one the cursor is in, paragraphs spaced apart and list items closer, headings with space above them and a rule under the first two levels, and a footer under the text with a hint, *Supports Markdown. Type / for commands*, and the *Edit as Markdown* link, as GitLab's *Switch to plain text editing*: it saves the text and opens the page's Markdown buffer, whose *Page* link comes back (see [Edit as Markdown](#edit-as-markdown)). The journal's day has no Markdown mode, so no link.

- **Every block keeps its id.** Enter splits a block and Backspace or Delete joins two, as in block mode, and `Tab` and `Shift+Tab` (or `Ctrl+Shift+→` / `Ctrl+Shift+←`) indent and outdent the blocks at the cursor with their children, as block mode does; with *Tab indents blocks* off in Settings → Editor, Tab moves focus instead. `Ctrl+Alt+1` … `Ctrl+Alt+6` make every block the selection touches that heading, taking off its list style, as in block mode; a block that opens with code, a quote or a table is left as it is. Cut and paste within the page moves blocks, so their `((refs))` and history go with them; a copy pasted is new blocks. Paragraphs pasted from elsewhere become blocks of their own, except inside a list or a table in a block, where they stay. Markdown text pasted from elsewhere (a list, a heading, a code fence, a task line, marks or links) comes in as the blocks it reads as: each list item a block, a nested item one deeper, a task's checkbox becoming its state once the cursor leaves the block, marks and links as marks; the first block joins the text before the cursor and the last the text after it. It reads as block mode's paste does, so both make the same blocks: a `-` or `*` item is a bulleted block and a `1.` item a numbered one, its style written once the block is saved, and a `+` item a plain one. `Ctrl+Shift+V` pastes the lines as they are.
- **It saves as you type**, after a short pause and every few seconds of typing that does not pause, as block mode keeps its draft, and when you leave the editor or the page, before an export, and when the app is hidden or closed. When a save fails, a notice says so, and the switch to blocks and *Edit as Markdown* keep the page in page mode until a save succeeds.
- **The switch keeps your place**, either way: the cursor where it was in its block, if you were typing, and the block at the top of the page where it was, the first switch included.
- **`Escape` leaves the text**, saving it, and leaves the focus on the document's frame, ringed, as block mode leaves the block selected; `Tab` from there goes back to the cursor. A key pressed while a chip or a block's chevron has the focus is that control's: `Tab` moves the focus on and never indents. `Escape` on a chip leaves the text all the same.
- **Block mode's formatting toolbar sits above the document**, staying at the top as the page scrolls, without *Discard* (page mode saves as you type). Its buttons act as in block mode, on the cursor's block, with two differences: *Turn into* (text, a heading, a list, a quote, code, a callout) acts on every block the selection touches, and the task button sets TODO on every block the selection touches, or clears it once all of them are tasks. A heading or code takes off a block's list style, and a list style a heading, as in block mode. *Turn into* shows the cursor's block's list style.
- **`Ctrl+Z` outside the document** takes back the page's saves as block mode's takes back its edits: the saves of one block's text are one step, and a save that writes several blocks, or adds, moves or deletes one, is a step of its own. A block brought back by an undo in the document is a step of its own too, so the next `Ctrl+Z` outside takes it back, not the delete before it.
- **A new or empty page takes typing at once**, as block mode focuses the first block it makes on one; a page with text opens without taking the focus.
- **Changes from elsewhere** (another device, an agent) come in while the page is open, block by block: a new block appears in its place, a moved one moves, a deleted one goes. Text you were typing into a block deleted elsewhere is kept as a new block, and a notice says so. A write the backend refuses makes the save read the page again and try once more, never in a loop. A block it refuses (a pasted link to a page in another space, say) waits, with the blocks under it, until it changes; the rest of the page still saves.
- **The Markdown syntax around the cursor** (*Show Markdown syntax around the cursor*, above) works here as in block mode, around the cursor's block only.
- **It shows** text with its marks, headings, code blocks with their highlighting, math, Mermaid, images written in the text, and links, tags and block references as chips that open what they point to, with the `[[`, `#` and `((` pickers. As in block mode, `Ctrl+click` or a middle click on a link or block reference opens it in a tab behind, and `Alt+Enter` follows the one at the cursor. A block reference peeks on hover and a page link previews its page on Ctrl (Cmd) + hover, as in block mode.
- **Bubble menus act on what the cursor rests in**, with block mode's words and icons. In a link: its URL, *External link* (block mode's link popover, as `Ctrl+K` opens it), *Open link* and *Remove*. In a table: *Table*, block mode's row and column operations. In a code block: its language (block mode's picker) and *Copy code*. A selected image has the image bubble below. None shows over a text selection, which has the marks bubble.
- **The block you point at shows block mode's grip, and its chevron if blocks are under it,** left of its text, on its first line; the chevron also shows while the cursor is in its block. Drag the grip to move the block with the blocks under it: the bar shows where it lands, before or after the block under the pointer, and dragging sideways moves it a level in or out within what the blocks around allow; the save writes the move (`Ctrl+Z` undoes it), and Escape cancels the drag. A click on the grip opens the block menu; the grip is no tab stop, so from the keyboard the menu key or `Shift+F10` opens the cursor's block's, or a focused chevron's block's. The chevron, `Ctrl+.` in the block or the menu's *Collapse* collapses a block with blocks under it, hiding them, and expands it again; which blocks are collapsed is block mode's own (per page, on this device), so a block collapsed in either mode is collapsed in the other. A collapsed block above the cursor shows what it hides until the cursor leaves, as block mode shows a block it focuses. Enter in a collapsed block, or a paste of several blocks into it, keeps what it hides under it: the text after the cursor goes to a new block after them (at the block's start, an empty block goes before it). Backspace at the start of the block after them joins its text to the collapsed block, as block mode's merge does, and Delete at the end of a collapsed block joins the block after them, so a block you cannot see is never joined into.
- **A right click on a block opens block mode's block menu on it**, and so do a click on its grip, and the menu key and `Shift+F10` on the cursor's block. Its rows act on the block under the pointer, not the cursor's: indent, dedent, move up and down, duplicate, merge, delete and Turn into edit the document (Turn into is the slash menu's, and a list target also writes the block's list style), and the save writes them (`Ctrl+Z` undoes them); task state, priority, properties and history run block mode's commands after the save; the copy rows and a link's open and copy URL work as in block mode. Right-clicking text selected inside one block keeps the webview's own menu, so Copy and Paste stay reachable; right-clicking inside a selection across blocks opens the menu for all of them (Copy selection is its copy; `Ctrl+C` and `Ctrl+V` still work), with block mode's batch toolbar's rows that set one task state on all of them (TODO, DOING, DONE) or clear it, leaving the blocks under them that are not selected as they were. Duplicate copies the text and its blocks, as a copy pasted does, not their task state or properties. The rows' shortcuts act at the cursor, as in block mode: `Ctrl+Shift+↑` / `Ctrl+Shift+↓` move the blocks the selection spans, `Ctrl+Shift+J` duplicates the cursor's block and `Ctrl+Shift+Y` opens its history. Left out: Zoom in.
- **On touch** the toolbar is pinned above the keyboard, as block mode's is, and the cursor scrolls into view above it. It ends with *Block actions*, which opens the block menu on the cursor's block, or on the selection when it spans blocks, once you have tapped into the page (until then the cursor's block may be out of sight, and the button is greyed out): its rows move, indent, collapse, duplicate and delete blocks in place of the grip, the right click and the menu key, none of which a touch screen has. A hold in the text selects text, as in any text field. The marks are in the toolbar's *Format*, as in block mode on touch, with no bubble over a selection, and a cursor in a link shows the link's bubble alone; a chip opens what it points to, with no preview on hover; a block's chevron shows while the cursor is in its block.
- **The slash menu and the `::` and `{{` pickers are block mode's**, and act on the block the cursor is in. A command that sets the block's task state, priority, a date, a property or its list style, or opens the date picker, the property drawer, the query builder or the voice recorder, waits for the save that creates the block, so it works in a new, empty block too; its checkbox, badge, chips or marker then show. `/attach` opens the file dialog at once, and the file chosen is attached as a pasted one is, once the block is saved. A heading, a callout, a divider or *Turn into* rewrites the block's text in the document (a heading, code, a quote or a callout also takes off the block's list style, at once, written once the block exists), and a mark, a link, a tag, a block reference, an embed, an emoji or a table goes in at the cursor, all saved like typing. `::` starts a `key::` line, which becomes the property once the cursor leaves the block, and `{{` offers the query builder, whose query becomes the block's, and embeds. `/duplicate` and `/template` are not offered: they add blocks outside the document. Escape closes a menu and changes nothing. `:` and a name opens the emoji picker, unless it is turned off in Settings › Editor, and `{{query` shows its hint, which `Tab` takes, both as in block mode.
- **Tasks show block mode's checkbox** beside their text, and a done or cancelled task is struck through and muted except while the cursor is in it. Clicking the checkbox or `Ctrl+Enter` / `Ctrl+L` (in any block, a new empty one too) steps the state as in block mode: none, TODO, DOING, DONE, CANCELLED, none. A state changed elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Priorities and dates show block mode's badge and chips** under the block's text, muted and smaller, as text rather than pills; the priority and an overdue or today's due date keep their colour. Clicking the badge steps the priority as in block mode, and `Ctrl+Shift+1`, `2` or `3` sets it on the block the cursor is in. Clicking a due or scheduled chip opens block mode's date picker; the date chosen is the block's, and the cursor stays where it was. `Ctrl+Shift+D` opens the picker to link a date's page at the cursor. `/due` and `/schedule` give a block a date it does not have yet, and the property drawer clears one. A change made elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Properties show block mode's chips** under the block's text, with a repeating task's rule as its own chip, shown with the dates. The property chips show on the block the pointer, the cursor or the focus is in, and are hidden elsewhere, keeping their place so nothing moves as they show; `Tab` still reaches them; the app's own keys (a task's `created_at` and `completed_at`, an image's size) show nowhere, as in block mode. Clicking a chip's value opens block mode's property editor, and its key renames it; clearing the value deletes the property. The `+N` pill, or `Ctrl+Shift+P` in any block, opens the property drawer. When the editor or the drawer closes, the block's chips are read again, and the cursor is where it was. Completing a repeating task brings its next occurrence into the page, with its rule and dates. A change made elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Bullet and numbered blocks show block mode's marker** before their text, numbered as block mode numbers them: a block's place in the run of numbered siblings it is in, starting again after a sibling that is not numbered (blocks nested between two numbered siblings do not restart it). A task is a list kind of its own, as in block mode: it shows its checkbox and no marker, and the toolbar, slash menu, block menu and typed markers that make a block a task or a list take the other kind off. Typing `-`, `*` or `+` and a space at the start of a block, then a character, makes it a bullet, and `1.` (any number) and a space, then a character, makes it numbered; the prefix leaves the text. A `[` after the `-` and space waits, so a typed `- [ ]` and space is still a task marker. Enter in a list block gives the block it makes the same style; Enter on an empty one leaves the list instead. Backspace at the start of a list block takes its style off, and a second Backspace joins it to the block before. A style shows at once and is written once the block exists. `Ctrl+Z` takes back the typing, not the style: right after the prefix it gives back what was typed as text (`- a`), the next `Ctrl+Z` takes that typing back, and the style stays, as block mode's `Ctrl+Z` gives back its one-item list with the style kept. Backspace right after the prefix deletes the character typed, where block mode's gives back its one-item list. A style changed elsewhere shows when the page reloads.
- **Attachments show as in block mode** under the block's text: an image, a PDF or a text file's preview, and the attachment badge with their count, which shows and hides as the property chips do. Clicking an image opens it full screen. The badge opens block mode's attachment list, where an attachment is renamed or deleted. A file pasted into a block, or dropped on one, is attached to it as in block mode, an image also going in at the cursor while the cursor is in that block; a file pasted into a new block is attached once the block is saved, and one that cannot be attached says so. An attachment added, renamed or deleted elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Queries and embeds show as in block mode**: a `{{query …}}` block shows its results, and an `{{embed …}}` block the embedded block, in place of its text. With the cursor in the block, its text shows instead, to edit as any other text; the arrow keys step into it. An edit of the text shows in the results once the cursor leaves the block. A click on a result row puts the cursor in the text, an embed's *Open source* goes where block mode's goes, and the results follow a save of this page, as block mode's do. The query's edit button opens block mode's query builder, whose Save writes the query. An embed of a block of this page shows that block's text as saved. An embed cannot be unlocked for editing in place, as it can in block mode: edit the block on its own page.
- **A task marker, a `key:: value` line or a `#name` left as text** becomes the block's task state, property or tag once the cursor leaves its block, or you leave page mode, as block mode makes them when you leave a block. The marker is a checkbox and a space at the start of the block, typed or pasted, with or without a `-` and a space before it (`[ ]`, `[/]`, `[x]`, `[-]`), and leaves the text; a marker the block held before you edited it stays text (a block Enter made held nothing, here as in block mode), and `TODO` stays a word. A `key:: value` line (on its own line, `Shift+Enter`) leaves the text once its property is written; one the backend refuses stays text, with a notice, and a line whose key the block held as text before you edited it stays text. A tag is the existing tag of that name in any case, else a new one. Undo takes back the typing it came from; a chip that undo leaves behind (typing paused between undo groups) is deleted like any other.
- **A page of more blocks than `PAGE_MODE_BLOCK_CAP` opens in blocks**, and *Page* in the switch says why in its tooltip, as a phone's *Edit as page* row does under its label (#5743). A page that grows past it while open in page mode goes back to blocks, with a notice. Page mode draws every block, so a key costs more the longer the page; `scripts/measure-page-mode-webkit.mjs` measures it against block mode on WebKitGTK, Linux's webview.

## File attachments

- **Drag-and-drop** files into the editor.
- **Paste** images directly into a block.
- **Click** an image in the editor to open the **ImageLightbox** (full-screen viewer with keyboard navigation).
- **Drag the corner handle** of an image to resize.
- **Select** an image in the text (click it, or arrow onto it), in blocks and in page mode, for its bubble: *Edit alt text* writes the alt into the image's Markdown, keeping its `|width` (`![alt|300](src)`, as typed in *Edit as Markdown*), *Open image … in full screen* opens it in the ImageLightbox (not offered for a web image the external-image setting withholds), and *Remove image* deletes it.
- **PDF attachments** open in the **PdfViewerDialog**.
- **A link to an attachment** in a block's text, `[label](attachment:<id>)` as an import writes a linked file or an embedded one that is not an image, shows with a paperclip; clicking it (Ctrl/Cmd+Click while editing) downloads the file.
- **Audio attachments** play inline. `/voice` records a voice note from the microphone and attaches it to the block; recording stops on its own just before the 50 MB attachment limit.
- Files render with type-specific icons (PDF, Word, Excel, image, generic).

## Drafts (autosave)

Edits to the focused block save locally on every interaction — both on blur and on a debounced timer while typing. If the app crashes or you close it mid-edit, the draft restores on next open. Drafts that never resolved against a real block are swept periodically.

## Code blocks

Code blocks support a curated set of grammars rather than the full highlight.js bundle — the exact list lives in `src/lib/lowlight-curated.ts`. Pick the language from the toolbar's code-block popover; the block shows its language name in the corner.

Syntax highlighting is local. Fenced markdown imports respect the language hint.

## Mermaid diagrams

Fence a code block as `mermaid` and the editor renders the diagram inline. Edit-on-click swaps back to the source; click outside to re-render.

See [pickers-and-slash.md](pickers-and-slash.md) for the trigger characters and [tags-and-links.md](tags-and-links.md) for the resolution model and inline query blocks.

## Pitfalls to know

- **The editor focuses one block at a time.** Clicking a different block flushes the current one's content before unmounting; if you bind a custom UI to "the focused block", be aware that the focused block changes on click.
- **Markdown shortcuts don't trigger after the cursor moves to a non-start position.** `#` at the start of an empty block becomes a heading; mid-paragraph it stays literal.
- **`Ctrl+Z` inside the editor undoes typing.** `Ctrl+Z` outside the editor (i.e. when you've clicked away) undoes the previous page-level operation (block create / delete / move / etc.). The two undo stacks are intentionally separate. A change of a block's kind is one page-level step with the list style or task state it took off. Inside the editor, the undo of a change that took a list block's bullet or number off (the block made a heading, code, a quote or a callout) gives it back with the text, except to a block that has become a task since (a task shows no bullet or number, so the undo leaves it a task), and a redo takes it off again; the undo of a heading typed with `#` first gives back the `#` as text. Nothing else in the editor gives it back: making the block text again, with *Turn into* or a Backspace on its `#`, leaves it plain. A change that empties the editor's history (in block mode, a command that rewrites the block's text, such as `/h2`) or leaves the text alone (a task made a list, or a list a task) is taken back by a page-level `Ctrl+Z` only.
- **Paste of a URL only creates a link when text is selected.** Otherwise it inserts the URL as plain text. Use the LinkEditPopover for a no-text link.
- **Pasting text of more than one line pastes blocks, spliced like a text editor.** It reads as the *Edit as Markdown* buffer does, the format block copy writes, so a copy pastes back as it was: a `-` or `*` item is a bulleted block, a `1.` item a numbered one and a `+` item a plain one (HTML from a web page is read by its elements instead): the first block joins the block at the cursor (at the start of a plain paragraph it brings its task state, list style and properties; after text, and in a heading or a quote, whose marker counts as text, it joins as the text you pasted, so the block keeps its type), the text after the cursor ends the last one (after a code block, on a block of its own), a selection is replaced, and the caret ends up just before that text. One undo takes back the paste and nothing typed before it, and the "Pasted N blocks" toast offers *Undo* and *Paste as text* (the lines as they are, as `Ctrl+Shift+V` pastes them). A single line pastes into the block at the caret with its markdown read (`**bold**`, `[text](url)`, `![alt](src)`, `$math$`, …), but a single list line (`- x`, `1. x`) pastes as its block where a block starts, and after text through the editor's own paste; a task line and a bare URL keep their own paste.
- **A block splits on blur only when the edit added blocks** beyond what it was loaded with. So a block loaded with N paragraphs stays one block when one paragraph is deleted and another added, and likewise when N paragraphs are pasted over it: the same trade, taken so that a typo fix never splits a block that was stored that way.
