# Editor

The editor is a block-based outliner built on TipTap (ProseMirror). Only the focused block is editable at any moment — every other block renders as a read-only static block. This *roving editor* keeps memory bounded and undo history isolated per edit session.

## Surfaces around the focused block

Above the focused block sits the **FormattingToolbar** — always visible. It carries icon buttons grouped by purpose: refs+blocks, structure, metadata, history. Low-priority buttons collapse into a `MoreHorizontal` overflow popover when the container is narrow.

When you select text inside a block, the **SelectionBubbleMenu** appears next to the selection. It hosts the six mark toggles (Bold / Italic / Code / Strike / Highlight / Underline) plus an External Link button. It only appears on non-empty selections so it doesn't get in the way of typing.

## Markdown surface

Type, paste, or use the toolbar:

| Mark / structure | Trigger |
| --- | --- |
| Bold | `Ctrl+B` |
| Italic | `Ctrl+I` |
| Inline code | `Ctrl+E` |
| Strikethrough | `Ctrl+Shift+S` |
| Highlight | `Ctrl+Shift+H` |
| Underline | `Ctrl+U` (stored as `<u>…</u>`) |
| Heading levels | `Ctrl+Alt+1` … `Ctrl+Alt+6`, toolbar → Heading popover, or slash menu (`/h1` … `/h6`) |
| Blockquote | Toolbar, or slash menu (`/quote`) |
| Code block | Toolbar (with language picker), or slash menu (`/code`) |
| Divider | Slash menu (`/divider`) |
| Callout | Slash menu (`/callout`); types: tip / note / info / warning / error |
| Ordered / unordered list | Toolbar, or markdown shortcut (`1.`, `-`) |
| Table | Slash menu (`/table` opens a size grid at the caret, starting at 3×3: arrows resize it, Enter inserts) |
| Task | A checkbox and a space typed at the start of the block, with or without a `-` and a space before it: `[ ]` TODO, `[/]` DOING, `[x]` or `[X]` DONE, `[-]` CANCELLED. The marker disappears and the block takes the state; `Ctrl+Enter`, the checkbox and the toolbar cycle it from there. `TODO` stays a word |

Markdown shortcuts trigger as you type (`#`, `##`, ``` ` ```, `**bold**`, `_italic_`, `~~strike~~`, `==highlight==`, `[text](url)`, `1.`, `-`, `>`, `[ ]`, `[/]`, `[x]`, `[-]`). A mark delimiter follows CommonMark's flanking rule, typed, pasted or stored alike: one with a space on its inner side stays text, so `5 * 3 = 15 and 2 * 4 = 8` is not italic, while a mid-word `un*break*able` is. A delimiter run never closes the mark it opened, so `a====b` stays text.

## Markdown syntax around the cursor

Settings › Editor › *Show Markdown syntax around the cursor* (off by default, per device) draws the syntax of the formatting the cursor is in or touches, in blocks and in page mode alike: the markers of bold, italic, code and strikethrough, a heading's `#` run, and an external link's `[` and `](url)`. The syntax is drawn for you to read and is never in the text, the clipboard or the saved block; a bare URL (which is stored as it reads) and a page, tag or block-ref chip show none, and a selection across blocks shows none.

- **A marker is one unit.** Backspace right after it, or Delete right before it, removes the formatting from the whole range, lowers the heading one level (a level 1 becomes a paragraph) or unlinks the text, as one undo step; at the start of a block this is not a join with the block above, and in a list block it comes before the list's own Backspace. `#` typed left of a heading's run raises the level.
- **The arrows and a click cross a marker without moving in the text**, so there is one caret stop at each edge of a formatted range: left of a closing marker typing stays formatted, right of it typing is plain. At the end of a block, ArrowRight steps past the closing marker first and the next one leaves the block (in page mode, into the next block).
- A link's URL is edited in the link popover (`Ctrl+K`), not in its `](url)`.
- While an IME composes, the markers stay where they are until it ends.

## External links

- **Add a link to selected text**: `Ctrl+K` opens the **LinkEditPopover**. Enter the URL; the selection becomes a clickable link.
- **Add a link by pasting**: paste a URL while text is selected — the selection becomes the link's label.
- **Edit an existing link**: click the link → LinkEditPopover opens for edit.
- **Remove a link**: open the popover → *Remove*.
- **Hover preview** (desktop): hovering a link shows a tooltip with the page's title and favicon (cached locally; first hover triggers a fetch).
- **Long-press copy** (mobile): long-press a link to bring up *Copy URL*.

## Block operations

[keyboard.md](keyboard.md) is the source of truth for bindings; this table is the editor's action inventory.

| Action | Trigger |
| --- | --- |
| Split block | `Enter`. The text after the caret becomes a new block, read as typed, as page mode reads a new block: a task marker, `key:: value` line or `#name` it holds becomes its task state, property or tag when you leave it. Enter at the start of a block moves its text down unchanged |
| Leave the block | `Escape` keeps what you typed and selects the block, so the block-selection keys act on it; a second `Escape` clears the selection, and `Ctrl+Z` undoes the edit like any other. An empty block is not selected: leaving tidies it away, as a click elsewhere does. The toolbar's *Discard changes* throws the edit away instead |
| Continue a list | `Enter` on a bullet / numbered block creates the next block with the same list style; `Enter` on an *empty* styled block leaves the list instead |
| Line break inside a block | `Shift+Enter`, or the toolbar's *New line* button (virtual keyboards have no Shift+Enter). A single line break is a line of the same block, stored as one newline and shown as a break; a blank line separates blocks |
| Merge into previous | `Backspace` at start of block. On a bullet / numbered block the first `Backspace` clears the list style; the second merges (or, on an empty block, deletes it) |
| Indent / dedent | `Tab` / `Shift+Tab`, or `Ctrl+Shift+→` / `Ctrl+Shift+←` |
| Move block up / down | `Ctrl+Shift+↑` / `Ctrl+Shift+↓` |
| Collapse / expand children | `Ctrl+.` (or click the chevron) |
| Open Property Drawer | `Ctrl+Shift+P` |
| Set priority directly | `Ctrl+Shift+1` / `Ctrl+Shift+2` / `Ctrl+Shift+3` (P1 / P2 / P3) |
| Insert a date at the cursor | `Ctrl+Shift+D` |
| Set a due / scheduled date | Toolbar (no default keyboard binding) |
| Cycle task state | `Ctrl+Enter` |
| Multi-select adjacent blocks | `Shift+Click`, `Ctrl+Click`, `Ctrl+A` (within page) |
| Delete block | Toolbar → *Delete*, or `Ctrl+Backspace` on an empty block |
| Drag to reorder | Drag the gutter handle; on touch, hold a block, then drag it |
| Block menu (touch) | Hold a block and let go |
| Swipe-to-delete (touch) | Swipe left on a block |
| Zoom into a block | `Alt+.`, toolbar → Zoom, or click the block-zoom breadcrumb (`Escape` zooms out) |

`Tab` / `Shift+Tab` indent and dedent by default. If you'd rather keep them as plain focus navigation, turn off *Tab indents blocks* in Settings → Editor; either way they're suppressed while a picker popup is open.

## Drag and drop

Drag-handle on the left gutter. On touch there is no handle: hold anywhere on a block for 400 ms (it lifts), then drag it; let go without moving and its menu opens instead. A parent's collapse chevron sits at the right end of its row there. The drop indicator shows the projected nesting depth — horizontal offset during drag determines whether you're moving the block as a sibling, a child, or to an outer level. Offscreen blocks become zero-height placeholders to preserve scroll position. Auto-scroll engages when dragging near the top or bottom of the viewport.

You cannot drop a block into its own subtree.

## Edit as Markdown

Page kebab → *Edit as Markdown* swaps the page's blocks for a plain-text editor holding the page as markdown: the page's own properties, aliases and tags as YAML front matter when it has any, then a `-` bullet per block, children indented two spaces, `key:: value` property lines (a repeating task's `repeat`, `repeat-until` and `repeat-count` among them) and `[ ]` / `[x]` tasks. Every line shows its markdown exactly as typed, with no formatting and no shortcut turning it into something else. The title and attachments keep their own UIs and are not in it.

- **Each line keeps its block.** The line a block starts on carries the block's id out of sight, and keeps it while you edit the text. Cut a line with its line break and paste it where a line starts, or drag it there, to move or re-nest its block; cutting only the start of a line leaves the line its block. Removing a bullet deletes its block and a new bullet creates one. Enter keeps the id on the line where the text it splits starts, so the line it opens is a new block. Joining two lines (Backspace at the start of one, or Delete at the end of the one before) keeps the first line's block and deletes the second's. A copy pasted (or dragged with `Ctrl`) is a new block, and so are lines pasted or dropped from another page's buffer and text from anywhere else: a `^ID` in it is text. Copying out of the buffer gives the lines as plain text, without ids.
- **Enter continues a list.** On a `-`, `*`, `+`, `1.` or `1)` line it starts the next line with the same indentation and marker, numbered one up, and a task line goes on as `- [ ]`. Enter on a line holding only its marker removes the marker, ending the list, and `Shift+Enter` breaks a line without one. `Ctrl+Z` and `Ctrl+Shift+Z` undo and redo in the buffer a run of typing at a time.
- **The block editor's keys work on lines** ([keyboard.md](keyboard.md#edit-as-markdown)), through the same bindings and your rebinds. `Tab` and `Shift+Tab` (or `Ctrl+Shift+→` / `Ctrl+Shift+←`) indent the blocks at the cursor, each with its further lines and children, two spaces and take up to two spaces or a tab off them, leaving a top-level block where it is; with *Tab indents blocks* off in Settings → Editor, Tab moves focus instead. `Ctrl+Shift+↑` / `Ctrl+Shift+↓` move the line with the lines indented under it past its sibling, a selection's siblings together, so the save moves those blocks; they stop at the top and bottom of the parent and at the front matter. `Ctrl+Enter` steps the task of the block at the cursor as the block editor does: none, `[ ]`, `[/]`, `[x]`, `[-]`, none. Every line keeps its block through all of these, and one `Ctrl+Z` undoes each. `Escape` leaves the buffer.
- **Pickers write markdown.** `[[` opens the page picker and the page picked is written `[[Title]]`; `#`, where a tag can start (at the start of a line or after a space, not in a fenced code block), opens the tag picker and writes `#name`, or `#[[name]]` when the bare form would read as another tag; `((` searches blocks and writes `((ID))`. *Create* writes the name as typed, and the save creates the page or tag. An open picker takes `Enter`, `Tab` and `Escape`.
- **The block editor's toolbar is above the buffer**, the same buttons in the same order, each writing its markdown on the line at the cursor or on the block the cursor is in (the block a line starts, or the one whose line starts the lines the cursor is in). *Format* wraps the selection in a mark's markdown (`**`, `*`, `` ` ``, `~~`, `==`, `<u>`), and again unwraps it. *Turn into* rewrites the block as the block editor's Turn into does: `- # text` for a heading, `>` before each of its lines for a quote, a fence around them for code, `- 1.` and `- -` for a numbered and a bulleted list, and *Divider* makes its text `---`. *Internal link* closes `[[ ]]` around the selection, or types `[[`; *Block reference* types `((` and *Insert tag* `#`, each opening its picker on what follows. *Cycle priority*, *Set due date* and *Set scheduled date* write the block's `priority::`, `due_date::` and `scheduled_date::` line under its text, as the export writes them; *Insert date* writes `[[YYYY-MM-DD]]`; *Insert query* makes the block's text the `{{query …}}` built; *Emoji* writes the emoji at the cursor; *Toggle TODO* steps its checkbox; *New line* is `Shift+Enter`; *Undo* and *Redo* are the buffer's; *Discard changes* is Cancel.
- **The block menu** opens from the toolbar's *Block actions* button, since a long press in a text field belongs to the phone, and acts on the block the cursor is in: its TODO and priority, Turn into, Move & arrange (Indent and Dedent take the lines indented under the block along, Move up and down are the move keys, Duplicate copies it with them as new blocks), Delete (with the lines under it), and Copy block reference (for a block already saved) and Copy page reference. Every line keeps its block through all of these, and `Ctrl+Z` undoes each.
- **Left out of the buffer**, each because it has no meaning there: Insert table and the table operations (a table is its `|` rows, typed as text), Properties and the menu's History (they act on the saved block, behind the buffer; a property is its `key:: value` line), Zoom in and Collapse (the buffer is the whole page, every line shown), Merge (Backspace at a line's start joins it to the one above), Open link and Copy URL (the menu does not open on a link), and the menu's content copies (select the lines and copy them). Attachments stay out of the buffer, so there is no attach action in it either.
- **On a phone** the toolbar is pinned above the keyboard and carries *Cancel* and *Save* in place of the buttons under the buffer, with *New line* for the line break a virtual keyboard has no key for.
- **The buffer reads as markdown** (the grammar in [import-export.md](import-export.md#import-settings--data)): `-`, `*`, `+`, `1.` and `1)` all start a block, nested by the marker's content column; a bare paragraph is a block, and a heading typed without a bullet owns what follows it. A line under a bullet that would read as a marker, a heading or a `key:: value` property is written with a leading `\`, which the save removes again. A fence left open in a block ends at the next line that starts a block, and the save warns which fence it closed.
- **Property lines** read as import reads them, with one difference: `key::` with no value, with or without a trailing space, deletes the property the block holds; for a key it does not hold, the line stays in the block as text. A key names the built-in key or definition it matches ignoring case and `-`/`_`, and a ref-typed value is a block id, a `[[Title]]` or a plain title in the space. A value its definition refuses refuses the save. A value its line cannot hold as it is (one with a line break, which an agent can set, a space at either end, or one that is itself a quoted string) is written as a JSON string: `note:: "two\nlines"`, with `\"` for a quote and `\\` for a backslash inside. A value typed in double quotes is read the same way; any other value, backslashes included, is taken as it is.
- **A refused save names the line.** The message starts with `line N:`, the buffer line of the block the save stopped at, counted from the top of the buffer, and that line is selected so the cursor is on it. A depth or size limit names the line of the block where it was reached the same way.
- **Page properties** are the front matter at the top of the buffer, the export's and Obsidian's form: `---`, then `aliases: [a, b]`, `tags: [a, b]` and one `key: value` line per property, then `---`; a value with a line break is written `key: |`, its lines indented two spaces under it. Typing one on a page that has none creates it, and Logseq's `key:: value` lines above the first bullet (`alias::` and `tags::` among them) are read too, a quoted value as a block's is. Save writes what changed as the page's property table, alias list and tag list write it: a key left out is deleted, a tag no tag of the space names is created. The keys the property table does not show (`created_at`, `template` and the like) are not written, so leaving them out deletes nothing. A line that is not a `key: value` pair, a key the app keeps, a key written twice, a `---` nothing closes and a value its definition refuses each refuse the save, and the message names the line, the `---` being line 1.
- `[[Page]]` and `#tag` resolve in the page's space as import resolves them ([import-export.md](import-export.md#import-settings--data)): exact title, then a unique case-insensitive title, then a unique alias, else created; the `[[` picker's `[[text]]` rule follows the same order over the full title, namespace included.
- **Ids that stay ids** (a `((ID))` block ref, a ref property's `key:: ID`, and a `[[ID]]` or `#[ID]` whose title would not read back as it: a duplicate title, another space's page, a deleted one) show their target's title under them while hovered or while the cursor touches them, which a screen reader hears; a missing target shows the chip's broken-link label, struck through. Each one is edited whole: the arrow keys step over it, Backspace or Delete beside it removes it in one undo step, typing inside it does nothing, and a paste over a selection that splits one lands beside it, so it never removes text the selection did not hold whole. Selecting a whole id and typing replaces it. Save warns, without stopping, of any that point to nothing.
- `[[Page|label]]` links `Page` and shows `label` in its place, stored as `[[ULID|label]]` so the link still follows a rename; a label equal to the title is not stored. `[[Page#Heading]]` links the page titled `Page#Heading` when one exists, else `Page` (it never creates `Page#Heading`). Ctrl+K on a selected link chip opens the link popover on its label.
- **Save** (`Ctrl+S`) writes the whole buffer as one change, so one page-level `Ctrl+Z` undoes it. Saving an empty buffer asks first, since it deletes every block. **Cancel** (or `Escape`) closes the buffer; when it is not the page as loaded, in its text or in which line carries which block (a restored draft included), it asks first, and *Keep editing* goes back to the text.
- **Edit, Preview and Changes** above the buffer switch what shows in its place. *Preview* shows the buffer as the page shows its blocks: each block at its depth with its task checkbox, its text rendered, its property lines and the front matter as chips, and a `[[Name]]` or `#name` as the chip of the page or tag the save links (or creates). It reads the buffer as the toolbar does, not with the save's grammar, so a heading typed without a bullet does not nest what follows it there. *Changes* is the buffer's line diff against the page as loaded: each change's removed lines (`−`) then its added ones (`+`), the words that changed marked, three unchanged lines either side and longer runs folded. *Save* counts those changes (*Save (3 changes)*) and is off while the buffer is the page as loaded; on a phone, Preview and Changes put Save and Cancel under the view, since the toolbar goes with the buffer.
- **A save leaves a report** with *Undo*, which reverts the whole save while it is still the page's latest change; after that it says so and reverts nothing. A save that deleted blocks (the report then counts what it deleted, created, edited and moved), created pages or tags for names nothing matched (listed as links, so a typo in a `[[Name]]` shows), or saved something differently than written (one line each) keeps its report until you dismiss it; any other save shows *Markdown saved* for a few seconds.
- **If the page changed elsewhere** (another device, an agent, another tab) since you opened the buffer, Save lists what changed there instead of saving: each block added, removed or changed, as its lines read in the buffer. *Merge* saves your text with those changes folded in, as one change, and closes the buffer like Save. Where both sides changed the same lines of a block differently, your version is saved as a new block just before the page's; a block you removed that was changed or moved to another parent there stays; a block you changed or moved to another parent that was removed there comes back as a new block; a block moved differently on each side keeps the page's parent, and children reordered differently on each side keep your order. Each of these shows a warning. *Reload* swaps your text for the page as it is now, *Keep editing* leaves your text so you can copy it out, and *Overwrite* saves your text over those changes: edits made there are reverted, blocks added there are deleted, a line whose block was deleted there comes back as a new block with a warning naming the line, and a page renamed there is linked by its old name, which creates a new page.
- **Unsaved text is kept** on this device as a draft, with the block each line carries, and restored the next time you open *Edit as Markdown* on that page, until you save or discard it. A restored draft still catches what changed on the page since. A draft kept by an earlier version, whose blocks were `^ID` anchors in its text, is not loaded into the buffer: it shows read-only above it with *Copy earlier edits*, until editing, saving or discarding the buffer replaces it.
- The front matter's lines carry no id.

## Page mode

Settings › Editor › *Edit pages as* sets how pages open on this device: **Blocks**, the default, one block at a time, or **Page**, the page as one document whose paragraphs are its blocks at their depths, the cursor moving across them freely. The page header's *Blocks | Page* switch, or `Ctrl+Shift+M`, changes it for the page on screen. On touch devices neither is shown and pages open in blocks.

- **Every block keeps its id.** Enter splits a block and Backspace or Delete joins two, as in block mode, and `Tab` and `Shift+Tab` (or `Ctrl+Shift+→` / `Ctrl+Shift+←`) indent and outdent the blocks at the cursor with their children, as block mode does; with *Tab indents blocks* off in Settings → Editor, Tab moves focus instead. Cut and paste within the page moves blocks, so their `((refs))` and history go with them; a copy pasted is new blocks. Paragraphs pasted from elsewhere become blocks of their own, except inside a list or a table in a block, where they stay.
- **It saves as you type**, after a short pause, and when you leave the editor or the page, before an export, and when the app is hidden or closed.
- **Changes from elsewhere** (another device, an agent) come in while the page is open, block by block: a new block appears in its place, a moved one moves, a deleted one goes. Text you were typing into a block deleted elsewhere is kept as a new block, and a notice says so. A write the backend refuses makes the save read the page again and try once more, never in a loop.
- **The Markdown syntax around the cursor** (*Show Markdown syntax around the cursor*, above) works here as in block mode, around the cursor's block only.
- **It shows** text with its marks, headings, code blocks with their highlighting, math, Mermaid, images written in the text, and links, tags and block references as chips that open what they point to, with the `[[`, `#` and `((` pickers. Collapsed blocks show their children, and stay collapsed in block mode. Drag handles are block mode's.
- **A right click on a block opens block mode's block menu on it**, and so do the menu key and `Shift+F10` on the cursor's block. Its rows act on the block under the pointer, not the cursor's: indent, dedent, move up and down, duplicate, merge and delete edit the document, and the save writes them (`Ctrl+Z` undoes them); task state, priority, properties and history run block mode's commands after the save; the copy rows and a link's open and copy URL work as in block mode. Right-clicking text selected inside one block keeps the webview's own menu, so Copy and Paste stay reachable; right-clicking inside a selection across blocks opens the menu for all of them (Copy selection is its copy; `Ctrl+C` and `Ctrl+V` still work). Duplicate copies the text and its blocks, as a copy pasted does, not their task state or properties. Left out: Turn into (a document edit page mode does not have yet), Collapse and Zoom in, and drag moves. Touch keeps its toolbar.
- **The slash menu and the `::` and `{{` pickers are block mode's**, and act on the block the cursor is in. A command that sets the block's task state, priority, a date, a property or its list style, or opens the date picker, the property drawer, the query builder or the voice recorder, waits for the save that creates the block, so it works in a new, empty block too; its checkbox, badge, chips or marker then show. `/attach` opens the file dialog at once, and the file chosen is attached as a pasted one is, once the block is saved. A heading, a callout, a divider or *Turn into* rewrites the block's text in the document, and a mark, a link, a tag, a block reference, an embed, an emoji or a table goes in at the cursor, all saved like typing. `::` starts a `key::` line, which becomes the property once the cursor leaves the block, and `{{` offers the query builder, whose query becomes the block's, and embeds. `/duplicate` and `/template` are not offered: they add blocks outside the document. Escape closes a menu and changes nothing.
- **Tasks show block mode's checkbox** beside their text, and a done or cancelled task is struck through and muted except while the cursor is in it. Clicking the checkbox or `Ctrl+Enter` (in any block, a new empty one too) steps the state as in block mode: none, TODO, DOING, DONE, CANCELLED, none. A state changed elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Priorities and dates show block mode's badge and chips** under the block's text. Clicking the badge steps the priority as in block mode, and `Ctrl+Shift+1`, `2` or `3` sets it on the block the cursor is in. Clicking a due or scheduled chip opens block mode's date picker; the date chosen is the block's, and the cursor stays where it was. `Ctrl+Shift+D` opens the picker to link a date's page at the cursor. `/due` and `/schedule` give a block a date it does not have yet, and the property drawer clears one. A change made elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Properties show block mode's chips** under the block's text, with a repeating task's rule as its own chip; the app's own keys (a task's `created_at` and `completed_at`, an image's size) show nowhere, as in block mode. Clicking a chip's value opens block mode's property editor, and its key renames it; clearing the value deletes the property. The `+N` pill, or `Ctrl+Shift+P` in any block, opens the property drawer. When the editor or the drawer closes, the block's chips are read again, and the cursor is where it was. Completing a repeating task brings its next occurrence into the page, with its rule and dates. A change made elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Bullet and numbered blocks show block mode's marker** before their text, numbered as block mode numbers them: a block's place in the run of numbered siblings it is in, starting again after a sibling that is not numbered (blocks nested between two numbered siblings do not restart it). Typing `-`, `*` or `+` and a space at the start of a block, then a character, makes it a bullet, and `1.` (any number) and a space, then a character, makes it numbered; the prefix leaves the text. A `[` after the `-` and space waits, so a typed `- [ ]` and space is still a task marker. Enter in a list block gives the block it makes the same style; Enter on an empty one leaves the list instead. Backspace at the start of a list block takes its style off, and a second Backspace joins it to the block before. A style shows at once and is written once the block exists. `Ctrl+Z` takes back the typing, not the style: right after the prefix it gives back what was typed as text (`- a`), the next `Ctrl+Z` takes that typing back, and the style stays, as block mode's `Ctrl+Z` gives back its one-item list with the style kept. Backspace right after the prefix deletes the character typed, where block mode's gives back its one-item list. A style changed elsewhere shows when the page reloads.
- **Attachments show as in block mode** under the block's text: an image, a PDF or a text file's preview, and the attachment badge with their count. Clicking an image opens it full screen. The badge opens block mode's attachment list, where an attachment is renamed or deleted. A file pasted into a block, or dropped on one, is attached to it as in block mode, an image also going in at the cursor while the cursor is in that block; a file pasted into a new block is attached once the block is saved, and one that cannot be attached says so. An attachment added, renamed or deleted elsewhere shows when the page reloads, and `Ctrl+Z` in the document never takes it back.
- **Queries and embeds show as in block mode**: a `{{query …}}` block shows its results, and an `{{embed …}}` block the embedded block, in place of its text. With the cursor in the block, its text shows instead, to edit as any other text; the arrow keys step into it. An edit of the text shows in the results once the cursor leaves the block. A click on a result row puts the cursor in the text, an embed's *Open source* goes where block mode's goes, and the results follow a save of this page, as block mode's do. The query's edit button opens block mode's query builder, whose Save writes the query. An embed of a block of this page shows that block's text as saved. An embed cannot be unlocked for editing in place, as it can in block mode: edit the block on its own page.
- **A task marker, a `key:: value` line or a `#name` left as text** becomes the block's task state, property or tag once the cursor leaves its block, or you leave page mode, as block mode makes them when you leave a block. The marker is a checkbox and a space at the start of the block, typed or pasted, with or without a `-` and a space before it (`[ ]`, `[/]`, `[x]`, `[-]`), and leaves the text; a marker the block held before you edited it stays text (a block Enter made held nothing, here as in block mode), and `TODO` stays a word. A `key:: value` line (on its own line, `Shift+Enter`) leaves the text once its property is written; one the backend refuses stays text, with a notice, and a line whose key the block held as text before you edited it stays text. A tag is the existing tag of that name in any case, else a new one. Undo takes back the typing it came from; a chip that undo leaves behind (typing paused between undo groups) is deleted like any other.
- **A page of more blocks than `PAGE_MODE_BLOCK_CAP` opens in blocks**, and *Page* in the switch says why in its tooltip (#5743). A page that grows past it while open in page mode goes back to blocks, with a notice.

## File attachments

- **Drag-and-drop** files into the editor.
- **Paste** images directly into a block.
- **Click** an image in the editor to open the **ImageLightbox** (full-screen viewer with keyboard navigation).
- **Drag the corner handle** of an image to resize.
- **PDF attachments** open in the **PdfViewerDialog**.
- **Audio attachments** play inline. `/voice` records a voice note from the microphone and attaches it to the block; recording stops on its own just before the 50 MB attachment limit.
- Files render with type-specific icons (PDF, Word, Excel, image, generic).

## Drafts (autosave)

Edits to the focused block save locally on every interaction — both on blur and on a debounced timer while typing. If the app crashes or you close it mid-edit, the draft restores on next open. Drafts that never resolved against a real block are swept periodically.

## Code blocks

Code blocks support a curated set of grammars rather than the full highlight.js bundle — the exact list lives in `src/lib/lowlight-curated.ts`. Pick the language from the toolbar's code-block popover; the block shows its language name in the corner.

Syntax highlighting is local. Fenced markdown imports respect the language hint.

## Mermaid diagrams

Fence a code block as `mermaid` and the editor renders the diagram inline. Edit-on-click swaps back to the source; click outside to re-render.

## Pitfalls to know

- **The editor focuses one block at a time.** Clicking a different block flushes the current one's content before unmounting; if you bind a custom UI to "the focused block", be aware that the focused block changes on click.
- **Markdown shortcuts don't trigger after the cursor moves to a non-start position.** `#` at the start of an empty block becomes a heading; mid-paragraph it stays literal.
- **`Ctrl+Z` inside the editor undoes typing.** `Ctrl+Z` outside the editor (i.e. when you've clicked away) undoes the previous page-level operation (block create / delete / move / etc.). The two undo stacks are intentionally separate.
- **Paste of a URL only creates a link when text is selected.** Otherwise it inserts the URL as plain text. Use the LinkEditPopover for a no-text link.
- **Pasting text of more than one line pastes blocks, spliced like a text editor.** It reads as a markdown import does (HTML from a web page gives the same tree): the first block joins the block at the cursor (at the start of a plain paragraph it brings its task state, list style and properties; after text, and in a heading or a quote, whose marker counts as text, it joins as the text you pasted, so the block keeps its type), the text after the cursor ends the last one (after a code block, on a block of its own), a selection is replaced, and the caret ends up just before that text. One undo takes back the paste and nothing typed before it, and the "Pasted N blocks" toast offers *Undo* and *Paste as text* (the lines as they are, as `Ctrl+Shift+V` pastes them). A single line pastes into the block at the caret with its markdown read (`**bold**`, `[text](url)`, `![alt](src)`, `$math$`, …); a task line and a bare URL keep their own paste.
- **A block splits on blur only when the edit added blocks** beyond what it was loaded with. So a block loaded with N paragraphs stays one block when one paragraph is deleted and another added, and likewise when N paragraphs are pasted over it: the same trade, taken so that a typo fix never splits a block that was stored that way.
